Com Vite

A Ana passou a semana com dois terminais abertos: um gerando o CSS do Tailwind, outro servindo o site. Funcionava — até o dia em que ela esqueceu o primeiro e passou quarenta minutos procurando um erro de classe que não existia. Nesta aula ela conhece o Vite, o programa que faz o papel dos dois terminais de uma vez só: ela salva o arquivo, o CSS é recompilado, a página se atualiza sozinha. No fim, um comando gera a pasta que ela publica. É a primeira vez que o projeto da padaria fica com uma estrutura de verdade, com src, package.json e dist.

Você vai aprender
  • O que o Vite faz, em uma frase, e o que ele não faz.
  • Como criar o projeto da padaria com npm create vite.
  • Os dois pacotes do Tailwind e por que são dois.
  • Onde o @theme mora num projeto com Vite: no CSS de entrada.
  • Como ler o vite.config.js sem medo.
  • O que muda entre npm run dev e npm run build.
  • Por que a página abre sem estilo e como descobrir o motivo.
  • O que existe dentro da pasta dist que você publica.

1. A cena: dois terminais e um CSS velho

O jeito que a Ana usava era o mais direto possível. No primeiro terminal, um comando que olhava os arquivos HTML e escrevia o CSS compilado num arquivo separado. No segundo, um programa que servia a pasta como site, para ela abrir no navegador. Dois processos, dois lugares para olhar, duas coisas para esquecer.

Quando dava certo, era mágico: ela escrevia p-4, salvava, e o espaço aparecia. Quando dava errado, era cruel: ela escrevia p-4, salvava, e nada acontecia. Nenhuma mensagem, nenhum aviso. Só o silêncio do navegador mostrando o cartão encostado na borda. E o pior é que o arquivo estava certo — o CSS é que era de dez minutos atrás, de antes da última edição.

Esse é o problema real que ferramentas de desenvolvimento vieram resolver, e não é sobre beleza de código: é sobre o resultado na tela corresponder ao que você acabou de escrever. Um projeto que compila sozinho a cada salvamento tira uma categoria inteira de erro do caminho. Você para de desconfiar do seu HTML e passa a desconfiar, com razão, do processo que gera o CSS.

O Vite é o programa que junta as duas tarefas em um processo só, e faz a terceira — a da publicação — quando você pede. Ele não substitui o Tailwind: continua sendo o Tailwind que lê as suas classes e escreve o CSS. O Vite é o encanamento em volta: ele serve os arquivos, percebe o que mudou, manda o navegador atualizar e, no fim, monta a pasta que vai para o ar.

2. O que é o Vite (e o que ele não é)

O nome vem do francês vite, "rápido", e a promessa é essa: enquanto você edita, nada de esperar meio minuto a cada salvamento. A ideia por trás é simples de entender mesmo sem saber programar. Em vez de juntar todos os arquivos num pacote antes de abrir a página, o Vite entrega cada arquivo separado para o navegador e só transforma o que for pedido. Como o navegador moderno sabe ler os arquivos do projeto, quase nada precisa ser preparado antes.

Na prática, você roda um comando e ganha um endereço. Abre esse endereço no navegador e vê o site da padaria funcionando, com o CSS já compilado. Salva um arquivo e, em menos de um segundo, o navegador mostra a mudança — muitas vezes sem recarregar a página inteira. Isso tem nome: hot reload, ou recarregamento quente. É o que faz a diferença no dia a dia, mais do que qualquer recurso avançado.

Quando o site está pronto, o mesmo programa faz o contrário: pega tudo, compila, reduz, renomeia os arquivos com um código no nome e escreve o resultado numa pasta chamada dist. Essa pasta é o site. Você a envia para o servidor e acabou. Nada de Node no servidor, nada de Tailwind rodando no computador do cliente: só HTML, CSS e os arquivos que você já conhece.

Vite
O programa que serve o projeto durante o desenvolvimento e monta a pasta final quando você manda. Não é o Tailwind, e não é o site.
servidor de desenvolvimento
Um programa que responde a um endereço no seu próprio computador, como http://localhost:5173, entregando os arquivos do projeto.
build
O passo de compilar e empacotar. Em inglês, "construir"; no dia a dia, "gerar o build".
dependência
Um pacote que o seu projeto usa e que fica listado no package.json. Instalar é baixar; o projeto não carrega esses arquivos no site final.
plugin
Um adaptador que ensina o Vite a fazer algo a mais. É por um plugin que o Tailwind entra no processo.

Uma coisa que o Vite não faz: ele não decide classes por você, não troca p-4 por p-6 e não corrige HTML. Ele é encanamento. Se o cartão está sem respiro, o problema continua sendo seu — e a solução continua sendo a mesma das aulas anteriores.

3. Node, npm e o primeiro comando

Tudo isso depende de um programa chamado Node, que é o que permite rodar JavaScript fora do navegador. Ele vem com o npm, o gerenciador de pacotes: é o npm que baixa o Vite, o Tailwind e o resto. Você instala uma vez, no computador, e esquece — mas vale conferir a versão antes de começar, porque projeto com ferramenta velha dá erro esquisito.

ana@notebook:~$ node -v
v22.14.0
ana@notebook:~$ npm -v
10.9.2

O $ no começo da linha é o convite do terminal: ele está esperando um comando. Você não digita o $. O ana@notebook é só o nome da máquina, para você se localizar quando tiver duas janelas abertas. As respostas, v22.14.0 e 10.9.2, são versões: números maiores significam mais novo.

Se o terminal responder que não conhece o comando, o Node não está instalado — e aí o caminho é baixar do site oficial e instalar como qualquer programa. Se as versões aparecerem, siga em frente. Para o Vite de hoje, o Node precisa ser razoavelmente novo: a partir da versão 20, com folga. Node 18 ainda funciona em projetos antigos, mas o Vite mais recente pede 20 ou mais; se ele reclamar disso no meio da instalação, é atualização do Node, não erro seu.

Duas palavras de vocabulário que aparecem em todo tutorial e confundem: npm install é "baixe o que está listado no package.json", enquanto npm install alguma-coisa é "baixe este pacote novo e acrescente na lista". O primeiro comando você roda toda vez que baixa um projeto; o segundo, só quando quer acrescentar algo. O Vite vem do segundo tipo, mas quem faz o trabalho é um comando de criação.

4. Criar o projeto da padaria

Existe um comando que monta a estrutura inteira, com as pastas e os arquivos no lugar, para você não começar do nada. Ele se chama create e faz parte do pacote do Vite. Rode na pasta onde você guarda os seus projetos — no caso da Ana, a pasta pessoal dela:

ana@notebook:~$ npm create vite@latest padaria -- --template vanilla

Scaffolding project in /home/ana/padaria...

Done. Now run:

  cd padaria
  npm install
  npm run dev

Vamos por partes, porque cada pedaço tem um motivo. npm create vite@latest quer dizer "baixe a versão mais recente do criador de projetos do Vite e rode". padaria é o nome da pasta que vai ser criada. -- --template vanilla é a receita: "sem framework, só HTML, CSS e JavaScript". Os dois traços antes de --template existem porque o npm repassa o resto da linha para o criador; é chato de decorar, e é por isso que todo tutorial copia e cola igual.

Se você rodar sem os dois traços, o criador abre um menu interativo e pergunta o nome do projeto e o modelo. Funciona também, e talvez seja mais fácil na primeira vez: use as setas para escolher Vanilla e JavaScript quando ele perguntar. O resultado é o mesmo.

Depois do cd padaria e do npm install, a pasta fica assim. Vale olhar com carinho, porque é a estrutura que você vai usar em todo projeto daqui para a frente:

padaria/
├── index.html
├── package.json
├── vite.config.js
├── public/
└── src/
    ├── main.js
    └── style.css

Três detalhes que surpreendem quem vem de tutorial antigo. Primeiro: o index.html mora na raiz do projeto, e não dentro de uma pasta de publicação — o Vite trata esse arquivo como o ponto de partida do site. Segundo: não existe pasta de CSS pronta, você cria. Terceiro: existe um vite.config.js, que é o arquivo de configuração do Vite — e é nele que o Tailwind vai entrar no próximo passo.

5. Instalar o Tailwind no projeto

Com o projeto criado, falta o Tailwind. São dois pacotes, e vale entender por que são dois antes de digitar o comando: um é o compilador, o cérebro que lê as classes e escreve o CSS; o outro é o adaptador, a peça que ensina o Vite a chamar esse compilador na hora certa.

PacoteO que éSe faltar
tailwindcssO compilador: lê as classes, resolve o tema, gera o CSS.Nenhuma classe funciona; o CSS sai vazio.
@tailwindcss/viteO plugin que liga o compilador ao Vite.O arquivo CSS é copiado como está, com o @import sem resposta.
viteO servidor de desenvolvimento e o empacotador.Nem dev nem build existem.

O comando instala os dois de uma vez, dentro da pasta do projeto:

ana@notebook:~/padaria$ npm install tailwindcss @tailwindcss/vite

added 38 packages, and audited 40 packages in 5s

found 0 vulnerabilities

O que mudou no disco foi o package.json, que ganhou duas linhas na lista de dependências, e a pasta node_modules, que é onde os pacotes baixados ficam. Essa pasta costuma ter milhares de arquivos e nunca é enviada para lugar nenhum: o .gitignore que vem no projeto já a exclui, e quem baixar o projeto roda npm install para recriá-la.

Repare que a versão não aparece no comando. Isso é de propósito: o npm pega a mais recente. Se um dia um tutorial mandar npm install tailwindcss@3, desconfie — o três no fim é a versão 3, e o guia inteiro é sobre a 4. A diferença não é cosmética: na 3, a configuração vivia num arquivo JavaScript separado; na 4, ela vive no CSS, dentro do @theme, que é o assunto de O @theme.

6. Ligar o plugin: o vite.config.js

Instalar não é o mesmo que ligar. O Vite ainda não sabe que o Tailwind existe; é o arquivo de configuração que avisa. Ele já vem com um conteúdo mínimo, e você acrescenta duas coisas: a linha do import e o plugin na lista.

import { defineConfig } from "vite";
import tailwindcss from "@tailwindcss/vite";

export default defineConfig({
  plugins: [tailwindcss()],
});

Leia de cima para baixo, como uma receita. A primeira linha traz a função defineConfig, que serve só para o editor ajudar você a escrever; ela não faz nada no navegador. A segunda traz o plugin do Tailwind. Depois, o export default entrega a configuração: um objeto com uma chave plugins, que é uma lista, e dentro dela o plugin já chamado, com os parênteses.

Os parênteses não são enfeite. tailwindcss sem parênteses é a fábrica; tailwindcss() é a peça pronta que o Vite espera. Escrever sem eles dá um erro no terminal que não explica nada — e é o erro mais comum deste arquivo, junto com o nome do pacote digitado errado.

Uma coisa importante: esse arquivo é lido uma vez, quando o servidor começa. Se você mexer nele com o npm run dev rodando, nada acontece. Pare o servidor com Ctrl + C e comece de novo. Já no resto do projeto, com o arquivo de configuração quieto, o recarregamento é automático — e é aí que a mágica aparece.

Se o seu projeto usa TypeScript, o arquivo se chama vite.config.ts e o conteúdo é idêntico, sem os tipos. O nome do arquivo muda, a ideia não. E se você viu por aí um tailwind.config.js, é da versão 3: no Tailwind 4 ele não é necessário, e criar um não vai fazer mal, mas também não vai fazer nada.

7. O CSS de entrada: @import e @theme

Falta a peça que liga o Tailwind ao CSS da página. No Vite, todo projeto tem um arquivo CSS de entrada, importado pelo JavaScript. No projeto da padaria, é o src/style.css, e ele precisa começar com uma linha só:

@import "tailwindcss";

@theme {
  --color-marca: #b4532a;
}

.botao {
  @apply rounded-lg bg-amber-600 px-4 py-2 text-white;
}

São três partes, e cada uma tem um papel. O @import "tailwindcss" é o que traz todo o Tailwind — sem ele, nada de classes. O @theme é onde os valores da padaria moram: declare --color-marca e a classe bg-marca passa a existir, exatamente como nas aulas de variáveis de tema. E o .botao mostra que esse arquivo é CSS de verdade processado pelo Tailwind: @apply pega classes e as escreve dentro de uma regra com nome.

O @import precisa vir antes de tudo, na primeira linha do arquivo. CSS tem essa regra chata: importações vêm no topo. Se você escrever o @theme primeiro e o @import depois, o navegador ignora a importação e o Tailwind reclama. É um erro de uma linha de diferença e de mensagem confusa, então memorize a ordem.

Agora a parte que costuma pegar: esse arquivo precisa estar importado em algum lugar do JavaScript. No modelo do Vite, o src/main.js já tem uma linha assim:

import "./style.css";

document.querySelector("#app").innerHTML = `
  <div class="p-4 bg-amber-100">Pão quentinho</div>
`;

A linha import "./style.css" parece não fazer nada, mas é ela que diz ao Vite "este CSS faz parte do site". Sem ela, o arquivo existe no disco, o Tailwind até compila, e a página abre sem estilo nenhum. É o mesmo tipo de erro do capítulo 1: nada quebra, nada avisa, e você fica olhando um HTML que parece certo.

O cartão chegou sem respiro e com fundo branco. Deixe 16 px por dentro (p-4) e o fundo âmbar claro (bg-amber-100).

<div id="alvo" class="rounded-lg bg-white p-2 text-stone-700">Pão quentinho</div>
padding: 8px
background-color: rgb(255, 255, 255)
color: oklch(0.374 0.01 67.558)
border-radius: 8px

<div id="alvo" class="rounded-lg bg-amber-100 p-4 text-amber-900">Pão quentinho</div>

Essa caixa é a prova número um do projeto com Vite: as classes do HTML viram CSS. Se depois de npm run dev o seu cartão continuar sem cor, o problema não está na classe — está no caminho entre o CSS de entrada e a página. Volte ao import "./style.css" e ao plugin no vite.config.js, nessa ordem.

O bloco @theme existe, mas a cor da padaria não. Declare --color-marca: #b4532a dentro dele e pinte o selo com bg-marca.

<style type="text/tailwindcss">
@theme {
  --color-marca-clara: #f6e7e0;
}
</style>

<span id="alvo" class="rounded-full bg-stone-200 px-3 py-1 text-stone-700">Feito hoje</span>
background-color: oklch(0.923 0.003 48.717)
color: oklch(0.374 0.01 67.558)
border-radius: 3.35544e+07px
padding-inline: 12px
padding-block: 4px

<style type="text/tailwindcss">
@theme {
  --color-marca: #b4532a;
}
</style>

<span id="alvo" class="rounded-full bg-marca px-3 py-1 text-white">Feito hoje</span>

Nas caixas deste guia, quem faz o papel do src/style.css é a tag <style type="text/tailwindcss">: é a maneira de escrever CSS de verdade dentro da prévia. Quando o assunto for o seu projeto, troque mentalmente uma coisa pela outra — o conteúdo é idêntico, e é por isso que a caixa serve de ensaio.

Uma observação que vale desde já: o @theme do Tailwind 4 é o mesmo em qualquer ferramenta. Se você migrar do Vite para outra coisa amanhã, o bloco vai junto, sem tradução. O que muda é só o nome do arquivo e o comando que liga o compilador. Essa portabilidade é uma das melhores razões para aprender o tema de verdade, e não decorar receitas de instalação — as receitas mudam, o bloco fica.

8. npm run dev e npm run build

Com tudo ligado, o comando é curto:

ana@notebook:~/padaria$ npm run dev

  VITE v7.1.0  ready in 412 ms

  ➜  Local:   http://localhost:5173/
  ➜  press h + enter to show help

Essas quatro linhas contam quase tudo. ready in 412 ms é o tempo que o servidor levou para ficar pronto — meio segundo. localhost quer dizer "este computador": o endereço só existe na sua máquina, e ninguém de fora acessa. 5173 é a porta, o número que identifica qual programa atende naquele endereço; se você já tiver outro projeto rodando, o Vite escolhe a próxima livre e mostra o número certo na tela.

Enquanto esse comando roda, o terminal fica ocupado — é assim que deve ser. Edite o HTML, salve, e o navegador atualiza. Edite o src/style.css, salve, e a mudança de cor aparece sem recarregar a página. Edite o vite.config.js e nada acontece, como já vimos: pare com Ctrl + C e comece de novo.

Quando o site estiver do jeito que a Ana quer, é hora do segundo comando. Ele não abre endereço nenhum: ele escreve a pasta final.

ana@notebook:~/padaria$ npm run build

vite v7.1.0 building for production...
✓ 12 modules transformed.
dist/index.html                  0.62 kB
dist/assets/index-Dk2f9a.css    14.71 kB
✓ built in 1.08 s

Repare em dois detalhes. O CSS virou um arquivo de 14 kB, muito menor do que a soma dos arquivos do Tailwind: o compilador escreveu só as classes que a página usa. E o nome tem um código no meio (index-Dk2f9a.css), que muda a cada build — é de propósito, para o navegador do cliente nunca mostrar um CSS velho guardado na memória.

ComandoO que fazQuando usar
npm run devServidor com recarregamento automático.Enquanto você escreve a página.
npm run buildCompila e escreve a pasta dist.Antes de publicar, e para conferir o tamanho.
npm run previewServe a pasta dist como ela vai ao ar.Para testar o resultado final antes de publicar.

Existe um detalhe que faz o build parecer quebrado na primeira vez: abrir o dist/index.html com duplo clique. Os arquivos lá dentro usam caminhos absolutos, e o navegador, aberto direto do disco, procura o CSS na raiz do sistema de arquivos. A página aparece sem estilo e você jura que o build falhou. Não falhou: use npm run preview, que serve a pasta por um endereço de verdade.

Outra coisa: se você publicar o site numa subpasta, como loja.test/padaria, avise o Vite no vite.config.js com base: "/padaria/". Sem isso, o HTML vai procurar /assets/index-Dk2f9a.css na raiz do domínio, e o visual se perde do mesmo jeito. É o mesmo tipo de erro de caminho, agora com uma solução de uma linha.

O .botao do CSS de entrada só tem o arredondamento. Complete com @apply rounded-lg bg-amber-600 px-4 py-2 text-white e veja o botão inteiro.

<style type="text/tailwindcss">
.botao {
  border-radius: 8px;
}
</style>

<button id="alvo" class="botao">Encomendar</button>
border-radius: 8px

<style type="text/tailwindcss">
.botao {
  @apply rounded-lg bg-amber-600 px-4 py-2 text-white;
}
</style>

<button id="alvo" class="botao">Encomendar</button>

O @apply funciona no Vite porque esse CSS passa pelo compilador do Tailwind — é o mesmo caminho do @theme. E aqui está uma diferença importante: no modo sem build, que é o assunto da próxima aula, o CSS também é processado; o que muda é quando e onde. Com Vite, tudo é compilado no seu computador, uma vez, e o site publicado leva o CSS pronto.

9. Cenários do dia a dia

Cenário 1: a página abre sem estilo e o terminal está limpo

Este é o campeão de audiência. O terminal não mostra erro, o servidor está de pé, e a página é um texto preto no branco. Na maioria das vezes, o import "./style.css" foi apagado do src/main.js em algum momento, ou o CSS de entrada nunca começou com @import "tailwindcss". A conferência é rápida: abra o painel do navegador na aba Network, recarregue e veja se algum arquivo .css foi baixado. Se não foi, o problema é o import. Se foi e está vazio, o problema é o @import.

Cenário 2: mudou o vite.config.js e nada mudou

A Ana acrescentou o plugin e continuou achando que o Tailwind não funcionava. O servidor estava rodando desde antes da mudança, e a configuração é lida uma vez só, no começo. A solução é parar (Ctrl + C) e rodar npm run dev de novo. Vale a regra geral: mudou arquivo de configuração, reinicie. Mudou HTML, CSS ou JavaScript, não precisa.

Cenário 3: funciona no dev e quebra no servidor

No computador dela, tudo certo. Publicado, o site aparece sem imagem e sem CSS. Quase sempre é caminho: o HTML do dist pede /assets/…, a partir da raiz do domínio, e o site está numa subpasta. A correção é uma linha no vite.config.js (base: "/padaria/") e um build novo. O outro suspeito é ter enviado a pasta errada para o servidor: o que vai ao ar é o conteúdo de dist, não a pasta do projeto com node_modules e tudo.

Exercício: ligar o plugin

No vite.config.js da padaria, complete a lista de plugins com a chamada do plugin do Tailwind, do jeito que o Vite espera — com os parênteses.

export default defineConfig({ plugins: [] });

Dica: o nome sem parênteses é a fábrica; o Vite quer a peça pronta. Se você escrever só o nome, o terminal reclama de um plugin inválido.

11. Resumo

O Vite junta duas tarefas que antes viviam separadas: servir o site enquanto você edita e montar a pasta de publicação quando você manda. O projeto nasce com npm create vite@latest, ganha o Tailwind com npm install tailwindcss @tailwindcss/vite e é ligado com duas linhas no vite.config.js — o import e o plugin na lista, com parênteses.

O CSS de entrada, src/style.css, é o arquivo mais importante do conjunto: começa com @import "tailwindcss", guarda o @theme da padaria e pode ter classes com @apply. Ele precisa ser importado no JavaScript, senão a página abre sem estilo e nenhum erro aparece. Durante o desenvolvimento, npm run dev dá um endereço em localhost e recarrega sozinho; antes de publicar, npm run build escreve a pasta dist e npm run preview deixa você ver o resultado como ele vai ao ar.

Para lembrar

  • Vite é encanamento: serve em desenvolvimento, empacota na publicação.
  • node -v e npm -v antes de começar; Node 20 ou mais novo.
  • npm create vite@latest padaria -- --template vanilla cria a estrutura.
  • Dois pacotes: tailwindcss (compilador) e @tailwindcss/vite (plugin).
  • vite.config.js precisa do import e de plugins: [tailwindcss()].
  • Mudou a configuração? Pare o servidor e rode npm run dev de novo.
  • O CSS de entrada começa com @import "tailwindcss", na primeira linha.
  • O @theme e o @apply vivem nesse arquivo, não no config do Vite.
  • O JavaScript precisa de import "./style.css"; sem isso, nada de estilo.
  • build gera dist; abra com preview, nunca com duplo clique.
  • Publicando em subpasta, ajuste base no vite.config.js.
