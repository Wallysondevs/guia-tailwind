Escuro Automático

A Ana instalou um botão de tema no site: uma lua pequena no canto do cabeçalho. Ninguém achou. Em três meses, duas pessoas clicaram — uma delas foi ela mesma, testando. Enquanto isso, a cliente que abre o site de madrugada continua levando o clarão, porque o celular dela já está no escuro e o site não acompanha. Nesta aula a Ana descobre o contrário do que imaginava: o jeito mais comum de ter tema escuro não é botão nenhum. O site pergunta ao sistema operacional em que tema ele está e se veste sozinho — e o Tailwind já sabe fazer isso sem uma linha de JavaScript.

Você vai aprender
  • O que prefers-color-scheme é e quem responde a pergunta.
  • Qual é a configuração padrão do dark: no Tailwind v4 — e por que ela não tem classe nenhuma.
  • Quando vale trocar o gatilho do sistema pela classe dark.
  • O color-scheme, que escurece barra de rolagem, caixinhas e campos nativos.
  • O scheme-light-dark do Tailwind e o <meta name="color-scheme">.
  • O script de quatro linhas que evita o piscar branco ao carregar (é JavaScript, e é pouco).
  • Como testar o escuro automático sem mudar o tema do computador.
  • Os tropeços de quem liga o escuro e esquece das bordas.

1. A cena: o botão que ninguém aperta

O botão de tema parecia uma boa ideia. Fica no cabeçalho, tem um ícone de lua, funciona: clicou, trocou. O problema é que ele exige que a pessoa (a) repare nele, (b) descubra o que ele faz e (c) queira apertar. Nenhuma das três coisas acontece com naturalidade.

A alternativa é não perguntar nada. O sistema operacional já sabe a resposta: quem usa o computador à noite costuma deixar o modo escuro ligado, e o mesmo vale para o celular. O navegador repassa essa informação para a página, numa pergunta chamada prefers-color-scheme — algo como “prefere esquema de cor escuro?”. A página que responde “sim” está fazendo tema automático, e não precisa de botão, de memória, de nada.

O Tailwind já faz essa pergunta por você. É por isso que uma classe como dark:bg-stone-900, escrita sem nenhuma configuração extra, funciona em quem está no escuro — e continua clara para quem está no claro. O que quase ninguém conta é que existem três formas de ligar o escuro, e cada uma serve a um tipo de site. Esta aula passa pelas três.

2. As três formas de ligar o escuro

sistema
O tema vem da preferência do aparelho, lida pelo navegador. Nenhum botão, nenhuma memória: o site segue o que o sistema diz.
classe
O tema é ligado por uma classe dark colocada em algum elemento acima. É o que permite um botão de tema que troca na hora.
atributo
Mesma ideia, mas com um atributo — data-theme="dark" — em vez de classe. Serve para quem quer mais de dois temas (claro, escuro, alto contraste).
preferência
A escolha do visitante, guardada no navegador (localStorage). É o que faz o botão “lembrar” da última escolha.
piscar
O clarão branco que aparece por uma fração de segundo quando a página carrega antes de o tema ser aplicado. Tem nome técnico e tem conserto.

O padrão do Tailwind v4 é o primeiro: sistema. Você não escreve nada, não configura nada, e o dark: responde à preferência do aparelho. É também o mais acessível dos três, porque respeita uma configuração que a pessoa já fez — e não uma que ela teria de descobrir no seu site.

3. O padrão: a media query que você não escreveu

Por trás do dark: existe uma regra de CSS comum. No Tailwind v4, sem configuração, o que ele gera para uma classe escura é isto:

@media (prefers-color-scheme: dark) {
  .dark\:bg-stone-900 {
    background-color: var(--color-stone-900);
  }
}

É a mesma estrutura que você já viu no CSS do md:, só que a condição não é largura, é preferência. A media query prefers-color-scheme aceita três valores: light, dark e no-preference (este último praticamente não é usado hoje). O navegador resolve a condição sozinho, consultando o sistema — e o resultado muda até sem recarregar, se a pessoa trocar o tema do aparelho enquanto o site está aberto.

Repare numa diferença importante em relação ao md:: lá a largura é uma coisa que você pode conferir arrastando a janela; aqui não há como mexer no sistema operacional a cada teste. Por isso todo navegador tem um jeito de fingir a preferência, e a seção 8 mostra onde fica. Sem isso, você vai editar o tema escuro às cegas.

E por que a versão do guia funciona com classe, então? Porque cada caixa desta página injeta uma linha de configuração que troca o gatilho do sistema pela classe dark — é o que permite ver o escuro aqui dentro sem mexer no seu computador, e é o assunto da seção 4. No seu projeto, essa linha só entra se você quiser um botão de tema.

4. O gatilho por classe

Trocar o gatilho é uma decisão de projeto, e o Tailwind v4 deixa isso numa linha de CSS. Primeiro, a experiência: com o gatilho por classe, quem liga o escuro é a presença da classe dark em algum elemento acima. Basta colocar a classe no bloco de fora para todo o conteúdo de dentro mudar.

O cartão já tem os pares do escuro, mas nada acontece — falta o gatilho. Acrescente a classe dark ao <div> de fora, o que envolve o cartão, e clique em Rodar. O painel confere o fundo e a cor do texto do cartão.

    <p class="font-semibold">Horário da padaria</p>
    <p class="mt-1">Aberto das 6h às 19h.</p>
  </div>
</div>

Antes da missão, o painel mostra fundo branco e texto escuro: nenhuma regra dark: vale, porque não existe a classe em lugar nenhum. Depois de rodar a solução, os dois valores viram os tons escuros. A prévia desta caixa está no tema claro de propósito — repare que a única coisa que mudou foi uma palavra no class do bloco de fora. É assim que um botão de tema funciona por dentro: ele não troca cor nenhuma, só liga e desliga uma classe.

Agora, o que essa experiência ensina e vale para os dois gatilhos: o dark: de um filho responde ao pai. Se você puser a classe no <html>, a página inteira responde. Se puser num cartão, só o cartão. Esse controle fino é útil: dá para mostrar um “veja como fica no escuro” dentro de uma página clara, com a classe num único bloco.

Para trocar o gatilho no seu projeto, a linha é esta, escrita no arquivo de CSS de entrada:

@import "tailwindcss";
@custom-variant dark (&:where(.dark, .dark *));

Ela diz: “dark: quer dizer quando existe um ancestral com a classe dark”. Para usar atributo em vez de classe, a linha muda só no pedaço de dentro: @custom-variant dark (&:where([data-theme="dark"], [data-theme="dark"] *));. Nada mais no HTML precisa mudar — as classes dark:bg-… continuam iguais.

5. color-scheme: os controles que o Tailwind não veste

Tema escuro com CSS funciona para tudo o que você desenhou. Mas alguns pedaços da página não são seus: a barra de rolagem, a caixinha de marcar, o seletor de data, a setinha do <select>, o fundo claro do preenchimento automático. Esses são desenhados pelo navegador, e ele não sabe que a página está escura — a menos que você avise.

O aviso é uma propriedade chamada color-scheme. Ela diz ao navegador quais temas o elemento aceita, e o navegador pinta os controles nativos de acordo: escuros no escuro, claros no claro. O Tailwind tem utilitárias para isso, e o CSS gerado é de uma linha:

.scheme-light-dark {
  color-scheme: light dark;
}

Este cartão tem um campo de busca e uma caixinha de marcar. Para os controles nativos acompanharem o tema do sistema, o bloco precisa declarar que aceita os dois: acrescente scheme-light-dark ao <div id="alvo">.

A prévia não muda de aparência porque o sistema desta janela está no tema claro — o color-scheme não pinta nada por conta própria, só dá permissão. No computador de quem usa o escuro, a diferença aparece: a caixinha de marcar fica escura, a barra de rolagem também, e o preenchimento automático do campo deixa de ser um retângulo claro no meio da página escura. Sem essa linha, você tem uma página escura com uma barra de rolagem branca — um detalhe que parece pequeno até o dedo do visitante encostar nele.

As variações mais usadas são quatro: scheme-light-dark (aceita os dois e segue o sistema), scheme-dark (força o escuro), scheme-light (força o claro) e scheme-normal (volta ao padrão do navegador). Existem ainda scheme-only-dark e scheme-only-light, que travam o tema e proíbem o navegador de oferecer o outro. No caso automático, a que interessa é a primeira.

6. O pacote completo no seu projeto

Juntando as peças, o escuro automático de um site tem três camadas, e é fácil esquecer a terceira:

  • As cores — os pares bg-white dark:bg-stone-900, do jeito que a aula anterior mostrou.
  • O gatilho — nenhum, se você ficar no sistema; a classe dark, se quiser botão.
  • O color-scheme — no elemento raiz, para os controles nativos acompanharem.

Esta prévia está no escuro. O bloco de fora é a “página” e continua clara. Acrescente a ele scheme-light-dark e o par do fundo escuro, dark:bg-stone-950.

    <p class="mt-1 text-sm">Aberto das 6h às 19h.</p>
  </div>
</div>

No seu projeto, o scheme-light-dark não vai num bloco qualquer: vai no <html> (ou no <body>), porque a barra de rolagem pertence à página inteira. Existem dois jeitos de declarar isso, e os dois funcionam:

<html lang="pt-BR" class="scheme-light-dark">
<!-- ou, no <head>: -->
<meta name="color-scheme" content="light dark">

O <meta> tem uma vantagem discreta: o navegador o lê antes de carregar o CSS, então a barra de rolagem já nasce certa e não pisca branca na abertura. Se você usa o tema por classe, o <meta> é o companheiro natural do script da seção seguinte. Se usa só o sistema, qualquer um dos dois serve.

Uma última peça de CSS que vale conhecer, mesmo sem usar agora: a função light-dark(). Ela recebe duas cores e escolhe sozinha, com base no color-scheme — sem dark:, sem classe. É o jeito “raiz” de fazer o automático, e você vai encontrar isso em folhas de estilo de terceiros. No Tailwind, o dark: faz o mesmo com mais controle, mas saber que a função existe evita estranheza ao ler o CSS de outra pessoa.

7. O piscar branco e o script que resolve

Quando o tema é ligado por classe, aparece um problema de tempo. O navegador começa a desenhar a página antes de o seu JavaScript rodar. Se o tema escuro só é aplicado depois, a pessoa vê um flash branco — meio segundo de clarão, justamente em quem está no escuro. Chama-se FOUC, e a solução é colocar o script no <head>, antes de qualquer conteúdo, para ele rodar cedo.

O pedaço abaixo é JavaScript, e é o único da aula. São poucas linhas, e cada uma faz uma coisa:

<script>
  (function () {
    try {
      var escolha = localStorage.getItem("tema");
      var escuro = escolha
        ? escolha === "escuro"
        : matchMedia("(prefers-color-scheme: dark)").matches;
      if (escuro) document.documentElement.classList.add("dark");
    } catch (e) {}
  })();
</script>

Lendo em português: “veja se a pessoa já escolheu um tema antes; se escolheu, respeite a escolha; se nunca escolheu, pergunte ao sistema; e, se a resposta for escuro, ligue a classe dark no <html>”. O botão de tema, quando existir, faz o caminho de volta: grava "claro" ou "escuro" com localStorage.setItem("tema", …) e liga ou desliga a mesma classe.

O try em volta existe porque alguns navegadores com privacidade rigorosa bloqueiam o localStorage e o script quebraria; com o catch vazio, ele simplesmente segue sem lembrar a escolha. E o matchMedia é a versão JavaScript da media query da seção 3: a mesma pergunta, feita no mesmo navegador, só que respondida para o código em vez de para o CSS.

Note que ele usa as duas informações: a escolha guardada e o sistema. É o comportamento que a maioria das pessoas espera — o site segue o aparelho até o momento em que elas dizem o contrário, e a partir daí lembra. Também note que ele não decide cor nenhuma: só liga a classe. Quem decide o que é escuro continua sendo o CSS, com os pares do dark:.

Se o seu site não tem botão de tema, nada disso é necessário: o gatilho do sistema resolve, sem JavaScript e sem piscar. Esse é o argumento mais forte a favor do automático puro — menos código, menos coisas para dar errado, e a preferência de quem visita respeitada de graça.

8. Como testar o escuro automático

Você não precisa desligar a luz da sala. O navegador sabe fingir que o sistema está no escuro:

NavegadorOndeO que escolher
Chrome e EdgeDevTools → menu ⋮ → More tools → RenderingEmulate CSS media feature prefers-color-scheme → dark
FirefoxInspector → ícone de tema na aba de regrasSimulate color scheme → dark

Com a emulação ligada, a página responde na hora — e você pode testar as duas versões sem fechar o inspetor. Um aviso útil: a emulação vale para a aba em que você ligou, e volta ao normal quando você fecha o DevTools. Se o site parecer “preso” no escuro depois de um teste, recarregue antes de procurar defeito no CSS.

EstratégiaComo ligaQuando escolher
Sistema@media (prefers-color-scheme: dark), o padrão do v4site simples, sem botão; respeita a escolha do aparelho
Classe@custom-variant dark (&:where(.dark, .dark *)) + classe no <html>quando há botão de tema e a escolha precisa ser lembrada
Atributo@custom-variant dark (&:where([data-theme="dark"], [data-theme="dark"] *))mais de dois temas (claro, escuro, alto contraste)

As três convivem com o mesmo HTML de classes: os pares dark:bg-stone-900 não mudam. O que muda é só a condição — e essa é a vantagem de aprender o assunto nesta ordem. Quem começa pelo botão costuma achar que o dark: e o botão são a mesma coisa; são camadas diferentes.

9. Cenários do dia a dia

Cenário 1: o site fica escuro, mas a barra de rolagem continua branca

O caso mais comum de “quase pronto”. As cores estão todas certas e, no canto direito da janela, a barra de rolagem aparece branca — um risco de luz na página escura. Falta o color-scheme: sem ele, o navegador desenha a barra no tema padrão dele, que é o claro. Acrescente scheme-light-dark no <html> (ou o <meta name="color-scheme">) e a barra acompanha. O mesmo resolve a caixinha de marcar e o seletor de data.

Cenário 2: no celular escuro, o site continua claro

“Liguei o modo escuro no celular e o site não mudou.” Aqui há duas causas prováveis. A primeira: o gatilho do site é por classe, e ninguém ligou a classe — o que só acontece com botão ou com o script do <head>. A segunda: o navegador do celular está desatualizado ou o site tem uma configuração que força o tema claro (um scheme-light esquecido, por exemplo). Antes de mexer no CSS, abra o site no computador com a emulação de prefers-color-scheme ligada: se lá funcionar, o CSS está certo e o problema é do gatilho naquele aparelho.

Cenário 3: o flash branco na abertura

Ao abrir o site no escuro, aparece um piscar branco antes de a página escurecer. É o tempo entre o navegador desenhar e o script rodar. Três consertos, em ordem de eficácia: colocar o script no <head>, antes do conteúdo (o mais importante); acrescentar o <meta name="color-scheme"> para a barra de rolagem já nascer certa; e deixar o fundo do <html> com a cor escura declarada direto no CSS de entrada, para o primeiro quadro já sair escuro. Nenhum deles custa mais que três linhas.

11. Resumo

O tema escuro automático é o que não pede botão: o site consulta o sistema com prefers-color-scheme e se veste sozinho. No Tailwind v4 esse é o comportamento padrão do dark: — a classe vira @media (prefers-color-scheme: dark) e nenhuma configuração é necessária.

Quem precisa de botão de tema troca o gatilho com uma linha de @custom-variant, que transforma o dark: em “quando existe um ancestral com a classe dark”; aí entra o script de quatro linhas no <head> para lembrar a escolha e evitar o piscar branco. As classes do HTML não mudam em nenhum dos casos: os pares são os mesmos.

Falta a camada que quase todo mundo esquece: o color-scheme. Ele não pinta nada, só dá permissão para o navegador desenhar barra de rolagem, caixinhas e campos nativos de acordo com o tema. Com scheme-light-dark no <html> — ou o <meta name="color-scheme"> no <head> — o escuro fica inteiro, sem um risco branco na lateral.

Para lembrar

  • Padrão do v4: dark: segue o sistema, sem classe e sem JS.
  • Com botão de tema: @custom-variant dark (&:where(.dark, .dark *)) e a classe no <html>.
  • A classe no pai liga o dark: de todos os filhos.
  • scheme-light-dark = color-scheme: light dark: barra de rolagem e controles nativos acompanham.
  • O <meta name="color-scheme"> vale antes do CSS carregar.
  • Script no <head>, antes do conteúdo, para não piscar branco.
  • Teste com a emulação de prefers-color-scheme no DevTools, não com o sistema.
  • Sem botão é mais simples, mais acessível e quase sempre o suficiente.
