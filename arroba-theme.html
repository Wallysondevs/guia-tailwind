O @theme

A Ana copiou um bloco @theme de um tutorial e funcionou: o site ganhou a cor da marca. Animada, escreveu --cor-do-botao: #b4532a, criou a classe bg-cor-do-botao e nada aconteceu. Nesta aula ela abre o bloco e olha dentro: quais nomes o Tailwind reconhece, o que ele faz com cada um, por que um prefixo errado não gera classe nenhuma e como as variáveis que ele publica podem servir também para o CSS que ela escreve à mão. É a aula que transforma o @theme de receita copiada em ferramenta que ela sabe usar.

Você vai aprender
  • O que o @theme é — e o que ele não é.
  • O caminho que o Tailwind percorre do bloco até a classe na tela.
  • Os namespaces (--color-*, --font-*, --spacing…) e o que cada um gera.
  • A diferença entre acrescentar um token e sobrescrever um padrão.
  • Por que --cor-marca não vira classe e --color-marca vira.
  • Como usar as variáveis publicadas dentro de um CSS comum.
  • Por que nem toda variável declarada aparece no arquivo final.
  • Como apagar uma família inteira de valores quando a paleta é fechada.

1. A cena: o bloco que funcionou por acidente

O bloco que a Ana copiou tinha sete linhas e três cores. Ela trocou os valores pelos da padaria, salvou, e o site ficou terracota. Só isso já justificava a aula — mas ela quis mais: criou --cor-do-botao com o terracota escuro, escreveu bg-cor-do-botao no botão e salvou. O botão continuou branco.

Nada de erro, nada de aviso. Ela conferiu a ortografia três vezes, comparou com as linhas que funcionavam, e a diferença era invisível: --cor-do-botao em vez de --color-do-botao. Uma letra. Em português, "cor"; em inglês, "color". O Tailwind lê o começo do nome e decide o que fazer; se o começo não é de um nome que ele conhece, ele guarda a variável e não cria classe nenhuma.

Essa é a chave da aula inteira: o @theme não é uma lista de cores, é uma tabela de nomes. O prefixo é o que diz ao Tailwind em que prateleira o valor está, e a prateleira determina quais classes ele vai gerar. Quem entende a tabela inventa token sem medo; quem não entende fica tentando adivinhar por que uma linha funciona e a vizinha não.

2. O que o @theme é (e o que ele não é)

O @theme é um bloco de CSS. Ele fica no mesmo arquivo onde está o @import "tailwindcss" — o CSS de entrada do projeto — e contém apenas declarações de variáveis, no formato --nome: valor;. Nada de seletores, nada de body, nada de regra solta: se você precisa de uma regra, ela vai fora do bloco, como qualquer CSS.

@import "tailwindcss";

@theme {
  --color-marca: #b4532a;
  --font-titulo: Georgia, serif;
  --radius-cartao: 0.75rem;
}

.card {
  background-color: var(--color-marca);
}

O que ele não é: um arquivo de configuração em JavaScript. Quem vem do Tailwind 3 procura um tailwind.config.js com uma lista de cores e não encontra. No Tailwind 4, essa lista virou este bloco, dentro do CSS. Ganhou-se uma coisa boa: o tema passa a ser CSS, então as mesmas variáveis servem para as classes do Tailwind e para o seu CSS escrito à mão.

Também não é um lugar mágico onde qualquer nome vira classe. O Tailwind lê o bloco antes de gerar o CSS, monta uma tabela de nomes e usa essa tabela para decidir se bg-marca existe. Se o nome não estiver na tabela, a classe não existe — e classe que não existe não avisa, como você já sabe.

Por fim, ele não substitui a paleta: ele convive com ela. Declarar --color-marca não apaga bg-amber-100; os dois funcionam. Apagar uma família inteira é possível, mas é um ato deliberado, com uma sintaxe própria, que aparece mais adiante nesta aula.

3. O caminho do bloco até a tela

Vale acompanhar o que acontece entre o seu texto e o pixel, porque isso explica todos os erros desta aula. São três passos.

Primeiro: o Tailwind lê o bloco e anota os nomes, junto com os valores padrão que ele já traz. É uma tabela interna, com as prateleiras separadas por prefixo. Segundo: ele varre o HTML, encontra classes como bg-marca e p-4, e para cada uma procura na tabela o valor correspondente. Terceiro: escreve o CSS final, com as variáveis publicadas em :root e as regras das classes apontando para elas.

@layer theme {
  :root, :host {
    --color-marca: #b4532a;
    --spacing: 0.25rem;
    --font-sans: system-ui, sans-serif;
  }
}

.bg-marca {
  background-color: var(--color-marca);
}

.p-4 {
  padding: calc(var(--spacing) * 4);
}

Repare em dois detalhes que mudam o jeito de pensar. As variáveis vão para :root, que é a raiz do documento: qualquer elemento da página pode usar var(--color-marca), inclusive os que não têm classe nenhuma. E as classes não repetem o valor: elas apontam para a variável. É por isso que trocar o valor no bloco muda todos os lugares de uma vez, e é por isso que o CSS final fica pequeno mesmo com muitas cores.

namespace
O prefixo que classifica o valor: --color-, --font-, --radius-. É ele que determina quais classes o token gera.
token
Um nome com valor, como --color-marca. A palavra vem de "símbolo": algo curto que representa uma decisão.
valor padrão
O que o Tailwind já traz, como --color-amber-100 ou --spacing: 0.25rem. Você pode sobrescrever qualquer um.
:root
A raiz do documento. É onde o Tailwind publica as variáveis, deixando-as disponíveis para toda a página.
acrescentar
Declarar um nome que não existe. A classe correspondente passa a existir, e nada mais muda.
sobrescrever
Declarar um nome que já existe com outro valor. A classe continua com o mesmo nome e passa a usar o valor novo.

4. As prateleiras: os namespaces que geram classes

Não são muitos, e os que importam no dia a dia cabem numa tabela. A regra é sempre a mesma: o que vem depois do prefixo é o nome da classe.

Prefixo no @themeClasse que nasceExemplo do guia
--color-*bg-*, text-*, border-*--color-marca vira bg-marca
--font-*font-*--font-titulo vira font-titulo
--text-*text-* (tamanho)--text-chamada vira text-chamada
--spacing e --spacing-*p-*, m-*, gap-*, w-*--spacing-cartao vira p-cartao
--radius-*rounded-*--radius-lacre vira rounded-lacre
--shadow-*shadow-*--shadow-cartao vira shadow-cartao
--breakpoint-*prefixo de variante--breakpoint-portatil cria portatil:
--ease-*, --animate-*ease-*, animate-*--animate-flutuar vira animate-flutuar

Duas linhas dessa tabela merecem atenção especial. A de --spacing não tem asterisco: ela é uma variável só, que multiplica a escala inteira, e tem aula própria adiante. A de --breakpoint-* é a única que não gera classe, e sim um prefixo de variante — o portatil: funciona como md:, com o tamanho que você escolher.

Há mais prateleiras do que caberia aqui: --tracking-* para o espaçamento entre letras, --leading-* para a altura da linha, --container-* para larguras máximas, --blur-*, --aspect-*. Você não precisa decorar a lista: quando sentir falta de um valor com nome, procure na documentação qual prefixo corresponde, ou repare no CSS que o Tailwind gerou — ele mostra o nome da variável de onde o valor veio.

E o mais importante da tabela é o que ela não tem: não existe --cor-*, não existe --fonte-*, não existe --espaco-*. O namespace é sempre em inglês, porque é o Tailwind que o lê — o nome do token, depois do prefixo, é livre: você pode escrever --color-trigo, --color-marca ou --color-padaria e todos funcionam.

5. Acrescentar ou sobrescrever

Existem duas operações no mesmo bloco, e a diferença entre elas é o nome que você escolhe. Nome novo, como --color-marca: acrescenta. A classe bg-marca passa a existir e a paleta continua intacta. Nome que já existe, como --color-amber-100: sobrescreve. O Tailwind não cria uma segunda variável; ele troca o valor daquela, e todas as classes que usam amber-100 passam a mostrar a sua cor.

Sobrescrever é uma ferramenta poderosa e um pouco perigosa. Poderosa porque você ajusta a paleta inteira sem sair dos nomes que todo mundo conhece: se o âmbar do Tailwind é amarelo demais para o pão, você declara o seu --color-amber-100 e a página toda acompanha, incluindo as aulas e os componentes escritos antes. Perigosa porque o nome deixa de dizer a verdade: quem lê bg-amber-100 espera âmbar claro, e pode encontrar bege.

O âmbar da paleta está forte demais para o cartão. Dentro do @theme, declare --color-amber-100: #ffe4c4 — sobrescrevendo o padrão — e veja o cartão mudar sem trocar nenhuma classe.

<style type="text/tailwindcss">
@theme {
  --color-marca: #b4532a;
}
</style>

<div id="alvo" class="rounded-lg bg-amber-100 p-4 text-amber-900">Pão quentinho</div>
padding: 16px
background-color: oklch(0.962 0.059 95.617)
color: oklch(0.414 0.112 45.904)
border-radius: 8px

<style type="text/tailwindcss">
@theme {
  --color-marca: #b4532a;
  --color-amber-100: #ffe4c4;
}
</style>

<div id="alvo" class="rounded-lg bg-amber-100 p-4 text-amber-900">Pão quentinho</div>

A missão não pediu para mexer no HTML, e é essa a lição: as classes do cartão continuam iguais. Quem mudou foi a tabela. O painel mostra background-color: rgb(255, 228, 196) porque o Tailwind traduziu o seu hexadecimal para o formato que o navegador devolve — o mesmo bege, escrito de outro jeito.

Uma consequência prática: sobrescrever é ótimo para ajustar a paleta existente, e ruim para nomear a marca. Se você declarar --color-amber-700 com o terracota da padaria, daqui a seis meses ninguém vai saber se aquele âmbar escuro é âmbar ou é a marca. O caminho saudável é usar nomes próprios para as decisões da marca e deixar a paleta do Tailwind em paz — é o assunto de Cores Próprias.

6. O prefixo é a regra: quando nada acontece

Agora o erro que abriu a aula. O Tailwind lê o nome da variável para decidir em que prateleira ela entra. Se o nome não começa com um prefixo conhecido, ele faz a coisa mais razoável do ponto de vista dele: guarda a variável como está e não gera classe. O valor continua disponível em var(--cor-marca), o que aumenta a confusão — a cor existe, só não virou utilitária.

O selo está transparente porque o token foi declarado na prateleira errada. Corrija o nome no @theme para que bg-marca passe a existir.

<style type="text/tailwindcss">
@theme {
  --cor-marca: #b4532a;
}
</style>

<span id="alvo" class="rounded-full bg-marca px-3 py-1 text-white">Feito hoje</span>
color: rgb(255, 255, 255)
border-radius: 3.35544e+07px
padding-inline: 12px
padding-block: 4px

<style type="text/tailwindcss">
@theme {
  --color-marca: #b4532a;
}
</style>

<span id="alvo" class="rounded-full bg-marca px-3 py-1 text-white">Feito hoje</span>

O exercício de diagnóstico vale para todos os casos parecidos, e é curto: olhe o começo do nome. Se não estiver na tabela de namespaces, é ali o problema. Depois disso, olhe a classe no HTML — mesmo token certo, classe errada não funciona. As combinações que aparecem na prática:

O que você escreveuO que o Tailwind fezO que corrigir
--cor-marca: #b4532aguardou a variável, nenhuma classetrocar por --color-marca
--color-marca: #b4532a e bg-cor-marcagerou bg-marcausar bg-marca no HTML
--color-Marca: #b4532agerou a classe com maiúsculaminúsculas, sempre
--color-marca #b4532a;nada: falta o dois-pontosCSS exige nome: valor;

A última linha da tabela merece uma frase a mais, porque é um erro de conceito e não de digitação. O @theme é uma declaração de valores, não um lugar para CSS solto. Se você precisa de uma regra com seletor, escreva-a fora; se ela usa classes do Tailwind, use @apply. Misturar as duas coisas costuma dar o mesmo resultado de tudo o que falha em silêncio: nada.

Existe ainda o caso do valor com espaços. --font-titulo: Georgia, serif funciona porque a vírgula separa as famílias e o navegador entende. Mas um nome de fonte com espaço precisa de aspas dentro do valor, e as aspas do HTML e do CSS não são a mesma coisa — em uma tag de estilo dentro da página, escreva --font-titulo: "Trebuchet MS", sans-serif e confira o resultado no painel, não no código.

7. As variáveis publicadas servem para o seu CSS

Como as variáveis vão para :root, elas não são propriedade exclusiva das classes do Tailwind. Qualquer CSS da página pode usá-las com var(), e isso resolve um problema antigo: o CSS escrito à mão e as classes do Tailwind passam a ler a mesma tabela de valores.

A etiqueta de encomendas está com uma borda sem graça. Pinte o fundo dela com a variável que o @theme publicou: background-color: var(--color-marca).

<style type="text/tailwindcss">
@theme {
  --color-marca: #b4532a;
}

.etiqueta {
  border: 1px solid #e7e5e4;
  color: white;
}
</style>

<span id="alvo" class="etiqueta rounded-full px-3 py-1 text-xs">Encomendas</span>
color: rgb(255, 255, 255)
font-size: 12px
line-height: 16px
border: 1px solid rgb(231, 229, 228)
border-radius: 3.35544e+07px
padding-inline: 12px
padding-block: 4px

<style type="text/tailwindcss">
@theme {
  --color-marca: #b4532a;
}

.etiqueta {
  border: 1px solid #e7e5e4;
  background-color: var(--color-marca);
  color: white;
}
</style>

<span id="alvo" class="etiqueta rounded-full px-3 py-1 text-xs">Encomendas</span>

O ganho aparece no dia da troca de cor. A Ana muda --color-marca no bloco e a etiqueta muda junto com todos os botões e selos do site: um lugar, muitos efeitos. Sem o @theme, ela teria a variável numa ponta e as classes na outra, e as duas pontas dariam para divergir.

Essa ponte tem um nome no vocabulário do Tailwind: as variáveis do tema são tokens, e um token é a menor unidade de decisão visual. Um site com dez tokens é um site que você consegue mudar; um site com duzentos valores soltos é um site que você reescreve. Não é preciosismo: é a diferença entre uma tarde de trabalho e uma semana.

8. O que sai no arquivo final (e como apagar uma prateleira)

Uma surpresa agradável de quem abre o CSS gerado pela primeira vez: as variáveis que você declarou e não usou não aparecem no arquivo final. O Tailwind publica só o que a página precisa. Se --color-trigo está no bloco e nenhuma classe o usa, ele é descartado — o que mantém o arquivo pequeno e evita que um tema de teste vaze para a produção.

Isso tem um efeito colateral que confunde: você declara uma cor, abre o CSS gerado e não a encontra. A conferência honesta é procurar no arquivo publicado:

ana@notebook:~/padaria$ grep -c -- "--color-trigo" dist/site.css
0
ana@notebook:~/padaria$ grep -c -- "--color-marca" dist/site.css
3

Zero para o token que ninguém usa, três para o que aparece no tema e em duas classes. Não é bug. Existe uma palavra para forçar a saída de tudo: @theme static { … }. Use com parcimônia, porque o arquivo cresce sem necessidade. E existe a operação oposta, que é apagar uma família inteira:

@import "tailwindcss";

@theme {
  --color-*: initial;
  --color-marca: #b4532a;
  --color-trigo: #e7d8b8;
}

A linha --color-*: initial diz "esqueça todas as cores padrão". Depois dela, a única paleta que existe é a sua: bg-amber-100 deixa de gerar CSS, bg-red-500 também. Parece radical, e é — mas é a diferença entre um site com liberdade total e um site com curadoria. Em projeto de cliente, com identidade visual fechada, essa linha é uma aliada: ninguém consegue colar um bg-lime-300 no meio da vitrine.

O mesmo vale para outras prateleiras: --font-*: initial apaga as famílias padrão, --radius-*: initial apaga os arredondamentos. O asterisco é o coringa do namespace. E o atalho mais radical de todos, --*: initial, apaga o tema inteiro — só faça isso se você pretende declarar tudo de novo, porque aí até --spacing desaparece e p-4 para de funcionar.

Uma ressalva de convivência: se você apagar a prateleira de cores e um componente antigo usar bg-stone-100, ele fica sem cor. O CSS não se queixa, o componente é que some. Por isso a ordem saudável é primeiro mapear o que o site usa, depois fechar a paleta e só então revisar as páginas uma a uma.

9. Cenários do dia a dia

Cenário 1: o tema está certo e a página não muda

A Ana declarou --color-marca, salvou, e o cartão continuou branco. Depois de dez minutos, descobriu que o bloco estava no HTML, dentro de uma tag style comum, e não no CSS de entrada. O @theme tem de estar no CSS que o Tailwind compila — no arquivo de entrada do projeto, ou numa tag style type="text/tailwindcss" no modo sem build. Tag comum é lida pelo navegador, que descarta o @theme em silêncio.

Cenário 2: dois @theme no projeto e ninguém sabe qual venceu

Ela colou um bloco no topo do arquivo de entrada e outro no fim de um CSS de componente. Os dois funcionam: o Tailwind lê os blocos e junta os valores. Quando o mesmo nome aparece duas vezes, vale o último declarado na ordem do arquivo final — e é aí que nasce a confusão. A regra prática é ter um @theme só, no arquivo de entrada, e tratar qualquer segundo bloco como sinal de que a decisão precisa ser centralizada.

Cenário 3: o cliente mandou a paleta em hexadecimal e a equipe em oklch

O @theme aceita qualquer formato de cor que o CSS aceite: hexadecimal, rgb(), oklch(), color-mix(). Não há conversão obrigatória, e o Tailwind não reclama de mistura. O que não dá para fazer é usar a cor em um lugar como hexadecimal e em outro como token com nome diferente — aí a troca futura volta a ser uma caça. Escolha um formato, declare uma vez, use o nome em todo o resto.

3. Qual é a diferença entre acrescentar e sobrescrever?

Exercício: o nome completo do token

A Ana quer a classe bg-trigo-300 com o bege claro da farinha. Escreva o nome completo da variável que precisa entrar no @theme, com os dois hífens e o prefixo.

@theme { : #e7d8b8; }

Dica: o prefixo é o que garante a classe bg-, e o resto do nome vira o sufixo. Se você escrever --trigo-300, a variável existe e bg-trigo-300 não.

11. Resumo

O @theme é um bloco de CSS, no arquivo de entrada, com declarações de variáveis e nada mais. O Tailwind lê esse bloco antes de gerar o CSS, publica cada variável em :root e cria classes conforme o prefixo do nome: --color-* gera bg-* e text-*, --font-* gera font-*, --radius-* gera rounded-*, e assim por diante. Nome fora da tabela não gera classe — e não avisa.

Nome novo acrescenta; nome que já existe sobrescreve o padrão, sem mudar o nome da classe. Como as variáveis ficam em :root, o seu CSS escrito à mão pode usá-las com var(--color-marca), e as duas pontas passam a ler a mesma decisão. O arquivo final leva só as variáveis usadas, a menos que você peça @theme static, e a linha --color-*: initial apaga a paleta padrão para trabalhar com curadoria.

Para lembrar

  • @theme mora no CSS de entrada, depois do @import "tailwindcss".
  • Dentro dele, só variáveis: regra com seletor fica fora, com @apply quando precisar.
  • O prefixo é a prateleira, e a prateleira decide a classe: --color-x vira bg-x.
  • Prefixo em inglês: --cor- não gera nada, --color- gera.
  • Nome novo acrescenta; nome existente sobrescreve o valor padrão.
  • As variáveis vão para :root: use var(--color-marca) no seu CSS.
  • Só as variáveis usadas aparecem no arquivo final; @theme static força todas.
  • --color-*: initial apaga a paleta padrão e deixa só a sua.
  • Valor com espaço pede aspas dentro do valor.
  • Um @theme só no projeto evita dúvida sobre qual valor venceu.
