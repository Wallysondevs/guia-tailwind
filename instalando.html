Instalando o Tailwind

Até agora a Ana viu o Tailwind funcionando nas caixas do guia, onde ele já está instalado e compila sozinho. Mas o site dela não mora numa caixa: mora numa pasta em /home/ana/padaria, com três arquivos HTML. Nesta aula ela leva o Tailwind para lá. São duas estradas — uma sem instalar nada, outra com alguns comandos no terminal — e a Ana vai percorrer as duas para entender quando cada uma serve. No fim, ela faz as três provas que mostram, sem dúvida, que o CSS gerado está chegando na página.

Você vai aprender
  • O que significa "instalar" o Tailwind, na prática.
  • A estrada sem build, com uma linha de script no HTML.
  • A estrada com npm: Node, dois pacotes e um comando.
  • O papel do CSS de entrada e o do CSS gerado.
  • O que faz cada pedaço do comando -i, -o e --watch.
  • Como ligar a folha gerada na página com uma tag link.
  • Os quatro tropeços clássicos da primeira instalação.

1. A cena: do guia para o projeto dela

A Ana entendeu a ideia e já sabe escrever meia dúzia de utilitárias. O problema é que, no projeto dela, nada acontece: ela abre o index.html da padaria, escreve class="p-4 bg-amber-100", salva, recarrega — e o cartão continua sem respiro e sem cor. Nas caixas do guia funcionava. Por que ali não?

Porque o guia injeta o Tailwind na prévia. Na pasta dela, não há nada: nem o gerador, nem a folha de CSS que ele produz. "Instalar" é exatamente isso — colocar o gerador dentro do projeto e criar um arquivo de CSS que o navegador possa carregar. Não é um programa com janela, não fica na barra de tarefas e não precisa ser aberto toda vez. É uma ferramenta de linha de comando que você chama quando quer (ou que fica vigiando enquanto você trabalha).

O resto do caminho já é conhecido: as classes no HTML, o CSS gerado a partir delas, o navegador aplicando. A aula anterior mostrou o mecanismo; esta mostra o encanamento. Vale fazer uma vez com calma, porque a instalação é o único momento em que aparecem arquivos e comandos dos quais você vai depender todos os dias.

2. As duas estradas

Existem dois jeitos oficiais de usar a versão 4, e eles não competem: servem a momentos diferentes. A estrada curta é uma tag script no HTML, que traz um construtor de CSS para o navegador. A estrada longa é instalar com npm e rodar um comando que gera um arquivo de CSS de verdade.

EstradaO que você precisaO que aconteceQuando usar
sem builduma tag script no HTMLo navegador gera o CSS ao abrir a páginaestudar, testar uma ideia, protótipo descartável
com buildNode, npm e dois comandosum arquivo .css pronto, ligado na páginasite de verdade, projeto que vai ao ar

A diferença que importa é onde o CSS é gerado. Sem build, ele nasce no navegador de quem visita — e aí cada visitante paga esse custo, o que só faz sentido em estudo. Com build, ele nasce uma vez, na sua máquina, e o visitante recebe um arquivo comum, pequeno e rápido. O guia usa o build na parte de produção e tem aulas próprias para cada assunto: sem build, instalando com npm e build de produção. Aqui você vê o suficiente para escolher e para fazer a primeira instalação funcionar.

Há ainda a questão da manutenção. Na estrada com build, as versões ficam anotadas no package.json, e atualizar é um comando (npm update) que vale para o projeto inteiro. Na estrada sem build, a versão está presa na URL da tag script e sobe quando alguém edita o HTML — prático para um teste, arriscado para um site com várias páginas.

3. Antes de começar: Node, npm e terminal

O Tailwind é escrito em JavaScript e roda fora do navegador. Para executá-lo, você precisa do Node.js, que é o programa que roda JavaScript no computador, e do npm, que vem junto e serve para baixar pacotes — bibliotecas de outras pessoas. O terminal é a janela onde você digita comandos em vez de clicar. No Ubuntu, ele abre com Ctrl + Alt + T; no macOS, fica em Aplicativos → Utilidades.

Node.js
O programa que roda JavaScript fora do navegador. É ele que executa a ferramenta do Tailwind no seu computador.
npm
O gerenciador de pacotes que vem com o Node. Baixa bibliotecas, guarda na pasta node_modules e anota o que foi baixado.
pacote
Um conjunto de arquivos de outra pessoa, publicado para ser reaproveitado. O motor e a CLI do Tailwind são dois pacotes.
build
O passo que transforma arquivos-fonte em arquivos prontos para o navegador. Aqui, transforma o CSS de entrada no CSS gerado.
watch
O modo que fica rodando e refaz o build a cada salvamento. Sem ele, o build acontece uma vez e para.

Comece conferindo se os dois estão instalados e em que versão, e já entre na pasta do projeto. A versão 4 do Tailwind pede Node 20 ou mais novo:

$ node -v
v22.11.0
$ npm -v
10.9.0
$ cd /home/ana/padaria
$ ls
index.html  produtos.html  contato.html

Duas linhas de resposta, e pronto. Se aparecer "comando não encontrado", instale a versão LTS no site oficial do Node e abra o terminal de novo — o instalador só é reconhecido em janelas abertas depois dele.

O cd muda a pasta atual; o ls lista o que tem dentro. Daqui para a frente, todos os comandos são digitados com essa pasta como atual — se você fechar o terminal, o caminho se perde e é preciso entrar de novo. Isso explica a maioria dos "não achei o arquivo" da vida real.

4. A estrada sem build, em três passos

Para estudar, a estrada curta é imbatível. Passo um: crie um HTML comum. Passo dois: cole a tag script do construtor dentro do head. Passo três: escreva as classes e abra o arquivo no navegador. O construtor lê o conteúdo da página, gera o CSS das classes e injeta o resultado ali mesmo.

<!doctype html>
<html lang="pt-BR">
<head>
  <meta charset="utf-8">
  <title>Padaria da Ana</title>
  <script src="https://cdn.jsdelivr.net/npm/@tailwindcss/browser@4"></script>
</head>
<body class="p-6 bg-amber-50">
  <h1 class="text-2xl font-semibold text-amber-900">Padaria da Ana</h1>
  <p class="mt-2 text-amber-800">Pão quentinho às 6h.</p>
</body>
</html>

Funciona sem instalar nada, sem terminal, sem pasta nova. Mas há três limites que você precisa conhecer. O primeiro é a internet: a tag busca o construtor num servidor externo, então sem conexão nada é gerado. O segundo é o tempo: a geração acontece a cada abertura de página, no navegador do visitante, e isso é lento para um site com muitas páginas. O terceiro é que o CSS nasce depois do HTML, o que pode causar um piscar de conteúdo sem estilo. Por isso a própria documentação chama essa estrada de ferramenta de desenvolvimento: ótima para aprender, imprópria para publicar.

5. A estrada com build: instalar

Agora a estrada de verdade. A ideia é ter duas pastas: uma com os arquivos-fonte (o HTML e um CSS de entrada, que você escreve) e outra com o resultado (o CSS gerado, que o navegador carrega). A Ana vai usar src/ para as fontes e dist/ para a saída:

padaria/
  index.html
  src/input.css
  dist/estilo.css

Com a pasta do projeto aberta no terminal, são esses os comandos:

$ npm init -y
Wrote to /home/ana/padaria/package.json
$ npm install tailwindcss @tailwindcss/cli
added 12 packages in 3s
$ npx @tailwindcss/cli -i src/input.css -o dist/estilo.css --watch
Done in 84ms

Linha por linha. npm init -y cria o package.json, a carteira de identidade do projeto: nome, versão e a lista de pacotes que ele usa. O -y aceita as respostas padrão, para não fazer perguntas. npm install tailwindcss @tailwindcss/cli baixa duas peças: o motor (tailwindcss) e o comando de linha de comando (@tailwindcss/cli). Na versão 4 eles são pacotes separados — o motor é usado por outras ferramentas também, e a CLI é só uma delas.

A terceira linha é o comando que faz o trabalho: -i src/input.css diz qual arquivo ler, -o dist/estilo.css diz onde escrever o resultado, e --watch pede que ele fique rodando, olhando os arquivos e regerando a cada salvamento. Você vai ver uma linha de "Done in ...ms" e o cursor parado, sem devolver o prompt: é assim mesmo, o processo está vivo. Para parar, use Ctrl + C. Os detalhes de cada opção têm aula própria: a CLI do Tailwind e o modo watch, mais adiante no guia.

6. O CSS de entrada

Falta o arquivo que o comando lê. Ele fica em src/input.css e, na versão 4, começa com uma linha só:

@import "tailwindcss";

Essa linha diz "carregue o Tailwind inteiro aqui". O resto — paleta, escala de espaço, tamanhos de letra, reset — vem junto, sem configuração. É a maior mudança da versão 4 em relação à 3, que pedia um arquivo tailwind.config.js com listas de cores e caminhos. Se você viu tutoriais antigos mandando criar esse arquivo, saiba que ele ainda é aceito, mas não é mais necessário. As personalizações — a cor da padaria, uma fonte própria — entram nesse mesmo CSS, com o comando @theme, como a aula de CSS de entrada mostra.

Duas observações práticas. Primeira: os nomes das pastas e dos arquivos são escolha sua; o guia usa src/input.css e dist/estilo.css porque são claros, e você deve manter os mesmos em todos os comandos. Segunda: o arquivo de entrada não é o que o navegador carrega. Quem carrega é o gerado, em dist/. Confundir os dois é o erro número um de quem está começando — o navegador nunca abre o src/input.css.

7. Ligar na página e fazer as três provas

Último passo: apontar o HTML para o arquivo gerado. A tag é a mesma de qualquer folha de estilo:

<link rel="stylesheet" href="dist/estilo.css">

O caminho é relativo ao HTML, então dist/estilo.css só funciona se o HTML está na raiz da pasta do projeto, ao lado de dist/. Depois de salvar, recarregue a página: o cartão deve aparecer com respiro, cor e canto. Se aparecer, a instalação está de pé — e você nunca mais precisa pensar nela, só manter o comando rodando enquanto edita.

Vale reparar numa coisa curiosa: o arquivo gerado não é "o Tailwind". Se você abrir dist/estilo.css num editor, vai encontrar regras de CSS comuns, com variáveis e seletores de classe. É o mesmo tipo de arquivo que você escreveria à mão, e é ele que o navegador carrega em todas as páginas. O Tailwind não entra no site publicado: ele só participa do momento em que o arquivo é gerado.

Para não ficar na fé, faça estas três provas. Elas testam o caminho inteiro: se o painel mostra o valor, é porque a classe chegou ao gerador, o gerador escreveu a folha e a folha está ligada na página. Se o painel ficar vazio, o problema está em um desses três elos.

Prova 1: o respiro já aparece. Acrescente o fundo âmbar claro. Se as duas linhas aparecerem no painel, a folha gerada está chegando na página.

<div id="alvo" class="p-4">Pão de queijo — R$ 4,00</div>
padding: 16px

<div id="alvo" class="p-4 bg-amber-100">Pão de queijo — R$ 4,00</div>

Repare que a prova não olha o desenho bonito: olha duas linhas de CSS computado. É assim que se confere instalação — com um sinal objetivo, e não com "acho que está funcionando". A partir daqui, o trabalho é só escrever classes.

Prova 2: a escala também está lá. Deixe o cartão com 24 px de respiro — o degrau seis — e confira que o painel acompanha o valor.

<div id="alvo" class="p-4 bg-amber-100">Pão de queijo — R$ 4,00</div>
padding: 16px
background-color: oklch(0.962 0.059 95.617)

<div id="alvo" class="p-6 bg-amber-100">Pão de queijo — R$ 4,00</div>

Prova 2 confirma que o degrau novo foi gerado: o CSS computado muda de 16 para 24 px. Se a primeira prova passou e a segunda não, o problema não é de instalação — é de nome de classe, e a conferência é letra por letra.

Prova 3: a ficha precisa caber em celular e em tela grande. Limite a largura a 384 px com max-w-sm e deixe-a ocupar a largura disponível com w-full.

<div id="alvo" class="p-4 bg-amber-100">Pão de queijo — R$ 4,00</div>
padding: 16px
background-color: oklch(0.962 0.059 95.617)

<div id="alvo" class="p-4 bg-amber-100 w-full max-w-sm">Pão de queijo — R$ 4,00</div>

A terceira prova é a que costuma revelar instalação incompleta: largura é uma família que depende de variáveis do tema (--container-sm). Se o respiro funciona e a largura não, o CSS gerado está velho ou incompleto — quase sempre porque o comando não estava rodando quando você salvou.

8. Quando não funciona

Os tropeços da primeira instalação são poucos e sempre os mesmos. Vale reconhecer o sintoma antes de mexer em qualquer coisa, porque a tentativa de conserto às cegas costuma piorar:

SintomaCausa provávelConserto
"command not found: npm"Node não instalado, ou terminal aberto antes da instalaçãoinstalar a versão LTS e abrir um terminal novo
a página fica toda sem estiloo link aponta para um arquivo que não existeconferir o caminho e rodar o comando uma vez sem --watch
as classes não fazem nadao CSS gerado está velho, ou o nome está erradorodar de novo, recarregar com cache limpo, conferir letra por letra
"cannot find module"o comando foi digitado em outra pastacd para a pasta do projeto e repetir

Há um quinto caso, mais sutil, que não aparece como erro: você escreve a classe num arquivo que o gerador não lê. Ele percorre a pasta do projeto e ignora o que está no .gitignore; uma cópia do HTML na área de trabalho, ou um arquivo em node_modules, fica invisível. Se a classe está escrita e o CSS não tem a regra, desconfie do lugar do arquivo antes de desconfiar do nome.

9. Cenários do dia a dia

Cenário 1: "instalei e a página ficou pior do que antes"

Provavelmente o reset entrou em cena e o CSS antigo da Ana não está mais sendo carregado — ou está, mas brigando. O Tailwind inclui uma base que zera margens e normaliza títulos, então a página sem classes fica realmente sem graça. O caminho é ir aplicando as utilitárias bloco por bloco, começando pelo corpo e pelos títulos, e deixar o CSS antigo para o fim, quando ele já não for necessário.

Cenário 2: "no meu computador funciona; no servidor, não"

O arquivo dist/estilo.css é gerado, não escrito à mão. Se ele não for gerado durante a publicação, o servidor recebe um HTML apontando para um arquivo ausente. As saídas são duas: gerar o CSS no momento do envio (o build de produção) ou enviar o arquivo junto. Em time, a primeira é a regra; em site pequeno, a segunda resolve. O que não pode é depender de um arquivo que só existe na sua máquina.

Cenário 3: "quero começar um projeto novo do zero"

Crie a pasta, o index.html, a pasta src com o input.css de uma linha, e rode os três comandos. Antes de escrever qualquer classe, abra a página e confirme que ela carrega o CSS (mesmo que sem estilo visível). Depois faça a prova 1. Só então comece o desenho — assim, se algo der errado mais tarde, você sabe que a instalação não é a culpada.

11. Resumo

Instalar o Tailwind é colocar o gerador no projeto e produzir uma folha de CSS que o navegador carregue. A estrada curta faz isso com uma tag script e serve para estudar; a estrada longa usa Node e npm, um arquivo de entrada com @import "tailwindcss"; e um comando que lê esse arquivo e escreve o CSS final — com --watch, ele fica rodando e regera a cada salvamento.

O navegador sempre carrega o arquivo gerado, nunca o de entrada. Saber disso resolve metade dos problemas de primeira instalação: caminho errado no link, comando parado, arquivo velho, pasta errada no terminal. E as três provas — espaço, degrau e largura — dizem em dez segundos se o encanamento está de pé, sem depender de impressão visual.

Para lembrar

  • Instalar = gerador no projeto + folha de CSS ligada na página.
  • Estrada curta: tag script do construtor, boa para estudo, ruim para publicar.
  • Estrada longa: Node 20+, npm init -y e npm install tailwindcss @tailwindcss/cli.
  • O CSS de entrada tem uma linha na versão 4: @import "tailwindcss";.
  • -i é o arquivo lido; -o é o arquivo escrito.
  • --watch mantém o processo vivo; Ctrl + C encerra.
  • O link aponta para o CSS gerado, com caminho relativo ao HTML.
  • Nomes de pasta são escolha sua — desde que iguais em todos os comandos.
  • Classe em arquivo fora do projeto não é lida: nada é gerado.
  • Página sem estilo depois de instalar: confira o caminho do link primeiro.
