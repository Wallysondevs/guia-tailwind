Barra de Navegação

O site da Ana tem três páginas — o cardápio, a história da padaria e o formulário de encomenda — e até agora não há como ir de uma para outra. Ela quer uma faixa no topo, com o nome da padaria à esquerda e os três links à direita, que continue visível quando o visitante rola a página de preços. No celular, os três links não cabem. Nesta aula ela monta essa barra do zero: alinhamento, link da página atual, a barra que gruda no topo e o que fazer com o menu na tela pequena.

Você vai aprender
  • As três partes de qualquer barra: marca, navegação e ação.
  • Como alinhar marca e links com flex e justify-between.
  • O miolo com largura máxima, centralizado e com respiro.
  • Os links, o gap entre eles e o estado de página atual.
  • Como grudar a barra no topo com sticky top-0 e o z-50.
  • Fundo translúcido e backdrop-blur sem perder a leitura.
  • Esconder os links no celular com hidden md:flex.
  • Por que a barra precisa de header e nav, e não só de div.

1. A cena: o site com três páginas e nenhum caminho

A primeira versão da barra da Ana era uma linha de texto no alto da página, feita de links separados por barras verticais:

<div>
  <a href="index.html">Padaria</a> | <a href="#">Cardápio</a> | <a href="#">Encomenda</a>
</div>

Não é errado, e durante anos a web inteira foi assim. Mas três coisas incomodam. A primeira é que nada se alinha: a marca é um link como os outros, então não existe hierarquia — o nome da padaria tem o mesmo peso de "Encomenda". A segunda é que, quando o visitante rola a página de preços, a barra vai embora e ele fica sem caminho de volta. A terceira é que, no celular, a linha simplesmente quebra no meio de um link.

Uma barra de navegação resolve os três problemas de uma vez. Ela é dividida em partes que você reconhece em qualquer site: a marca, à esquerda; a navegação, com os links; e, quando existe, uma ação à direita — "Encomendar", "Entrar", um botão de destaque. Saber essas três partes antes de escrever a primeira classe evita a maior parte do trabalho.

2. header, nav e a marca

A barra é feita de três tags que dizem o que cada pedaço significa. O Tailwind não muda nada nelas; ele só veste:

header
A faixa do topo da página. É a tag que anuncia "aqui começa a página" para o leitor de tela e para os robôs de busca.
nav
O bloco de navegação. Marca um conjunto de links que levam a outras páginas — e não a qualquer link, como um link dentro de um texto.
marca
O nome da padaria, geralmente um link para a página inicial. Não existe tag de marca: é um a com texto e, às vezes, um quadradinho colorido antes.
aria-current
Atributo que marca qual link é a página em que o visitante está. O leitor de tela anuncia "página atual".
barra fixa
A barra que continua visível quando a página rola. Se faz com sticky top-0 — não com posição fixa.
<header>
  <a href="index.html">Padaria da Ana</a>
  <nav>
    <a href="#">Cardápio</a>
    <a href="#">A padaria</a>
    <a href="#">Encomenda</a>
  </nav>
</header>

Sem nenhuma classe, essa estrutura aparece empilhada: marca em cima, links embaixo, cada um numa linha, e todos sublinhados em azul. É o visual padrão do HTML. A partir daqui, é só composição.

3. Marca à esquerda, links à direita

O alinhamento da barra é um caso clássico de flex: dois filhos, um empurrado para cada ponta, os dois alinhados pelo meio. A diferença é que a barra quase sempre tem um miolo com largura máxima, e esse miolo é que recebe o flex — não o header. Assim a faixa colorida ocupa a tela inteira e o conteúdo fica centralizado, como em qualquer site grande.

A marca e os links estão empilhados. Deixe os dois na mesma linha, com a marca à esquerda, os links à direita, alinhados pelo meio e com largura máxima de 1024 px.

<header class="border-b border-stone-200 bg-white">
  <div id="alvo" class="px-4 py-3">
    <a class="font-semibold text-amber-800" href="index.html">Padaria da Ana</a>
    <nav class="flex gap-6 text-sm text-stone-600">
      <a href="#">Cardápio</a>
      <a href="#">Encomenda</a>
    </nav>
  </div>
</header>
padding-inline: 16px
padding-block: 12px

<header class="border-b border-stone-200 bg-white">
  <div id="alvo" class="mx-auto flex max-w-5xl items-center justify-between gap-4 px-4 py-3">
    <a class="font-semibold text-amber-800" href="index.html">Padaria da Ana</a>
    <nav class="flex gap-6 text-sm text-stone-600">
      <a href="#">Cardápio</a>
      <a href="#">Encomenda</a>
    </nav>
  </div>
</header>

Quatro classes fazem o alinhamento: flex põe os dois filhos lado a lado, items-center alinha pela linha do meio, justify-between empurra um para cada ponta e gap-4 garante que eles nunca se encostem. O gap parece redundante com justify-between e não é: numa tela estreita, os dois blocos se aproximam até encostar, e o gap é o limite mínimo.

As outras três classes cuidam do miolo. max-w-5xl limita a largura a 1024 px, para o conteúdo não se esticar numa tela grande. mx-auto centraliza o bloco de largura limitada — margem automática dos dois lados. E px-4 py-3 dá o respiro.

.mx-auto {
  margin-inline: auto;
}
.max-w-5xl {
  max-width: var(--container-5xl);
}
.justify-between {
  justify-content: space-between;
}

Repare que o mx-auto só funciona porque existe um max-width: um bloco que ocupa 100% da largura não tem folga para centralizar. É a dupla clássica de qualquer página centralizada, e vale para a barra, para o rodapé e para o conteúdo.

4. Os links e a página atual

Os links dentro do nav precisam de três decisões: espaçamento, cor e estado. O espaçamento vem do gap-6 no pai — 24 px entre um link e outro, sem margem em ninguém. A cor vem de text-sm text-stone-600: 14 px e um cinza que não briga com a marca. E o estado de mouse vem de hover:text-amber-700, para o link responder.

O terceiro estado é o mais importante e o mais esquecido: onde o visitante está agora. Se ele está no cardápio, o link "Cardápio" precisa parecer diferente — cor mais forte, peso maior, e uma linha embaixo, se o desenho pedir. É o que evita a sensação de estar perdido.

<nav class="flex gap-6 text-sm font-medium">
  <a class="text-amber-800 underline underline-offset-8" href="#" aria-current="page">Cardápio</a>
  <a class="text-stone-600 hover:text-amber-700" href="#">A padaria</a>
  <a class="text-stone-600 hover:text-amber-700" href="#">Encomenda</a>
</nav>

Três detalhes nesse pedaço. As classes de cor e estado ficam em cada link, não no nav, porque cada um tem um estado diferente. O underline-offset-8 afasta a linha do texto, e é o que faz o sublinhado de link ativo parecer proposital em vez de esquecido. E o aria-current="page" repete em texto o que a cor já diz — quem não vê a cor precisa saber também.

Se a sua barra tiver um botão à direita — "Encomendar", por exemplo —, ele entra como terceiro filho do miolo, e o justify-between passa a distribuir três blocos: marca na esquerda, links no meio, botão na direita. Funciona, mas fica frágil quando um dos links tem texto comprido. A alternativa mais estável é agrupar: um div class="flex items-center gap-6" com os links e o botão juntos, e o justify-between só separa marca e grupo. Agrupar primeiro, distribuir depois — a mesma ideia da aula de listas de itens.

5. A barra que fica no topo

Agora o pedido central da Ana: a barra precisa continuar ali quando a página rola. Existem duas propriedades CSS que fazem isso, e elas são bem diferentes. fixed tira o elemento do fluxo e o prende na janela — o que faz o conteúdo de baixo subir e ficar escondido atrás da barra, exigindo compensação. sticky é mais gentil: o elemento continua no lugar dele até a página rolar o suficiente, e então gruda no topo.

Ao rolar a página, a barra some e o visitante perde o caminho de volta. Grude a barra no topo com sticky top-0, ponha fundo branco com 90% de opacidade e desfoque o que passa atrás dela.

<header id="alvo" class="border-b border-stone-200 bg-white">
  <div class="mx-auto flex max-w-5xl items-center justify-between gap-4 px-4 py-3">
    <a class="font-semibold text-amber-800" href="index.html">Padaria da Ana</a>
    <nav class="flex gap-6 text-sm text-stone-600">
      <a href="#">Cardápio</a>
    </nav>
  </div>
</header>

Depois de rodar, o painel mostra uma linha para cada classe, e cada uma tem um trabalho. position: sticky liga o modo. top: 0px diz onde ele gruda — sem essa coordenada, o sticky não faz nada, porque não sabe em relação a que ponto parar. z-index: 50 garante que a barra fique na frente do conteúdo que passa por baixo. E as outras duas, o fundo translúcido e o backdrop-filter: blur(8px), são o truque visual que quase todo site moderno usa.

.sticky {
  position: sticky;
}
.top-0 {
  top: calc(var(--spacing) * 0);
}
.z-50 {
  z-index: 50;
}
.backdrop-blur {
  --tw-backdrop-blur: blur(8px);
  backdrop-filter: var(--tw-backdrop-blur,);
}

O bg-white/90 merece atenção porque é uma sintaxe que confunde. A barra é a cor branca com 90% de opacidade — ou seja, 10% de transparência. Quando o conteúdo de baixo passa, ele aparece levemente através da barra, e o backdrop-blur borra esse resto. O resultado é uma barra que parece sólida sem ser opaca. Sem o desfoque, texto passando atrás a 10% de opacidade vira sujeira; com ele, vira profundidade.

Se você puser bg-white puro, tudo funciona e nada quebra — só fica mais sem graça. E se puser opacidade baixa demais, como bg-white/50, o texto que rola atrás concorre com os links e a barra perde legibilidade. A faixa segura fica entre 80% e 95%.

6. No celular: esconder, não espremer

Três links de 14 px, com 24 px entre eles, mais a marca, somam uns 340 px. Numa tela de 375 px isso passa. Numa de 320 px, mais ainda. A tentação é diminuir a fonte ou o espaço — o que resolve por dois minutos e volta no próximo link que a Ana acrescentar. A solução de verdade é outra: no celular, os links somem e um botão aparece; a partir de uma largura, os links voltam e o botão some.

Essa troca é o coração do jeito responsivo do Tailwind. hidden esconde; md:flex devolve o display: flex a partir de 768 px. Como a regra do md: vem depois no CSS, ela vence no breakpoint.

Nesta prévia de 375 px, os links apertam a marca. Esconda a navegação no celular e mostre-a a partir de 768 px: troque flex por hidden md:flex.

<div class="flex items-center justify-between gap-4 px-4 py-3">
  <a class="font-semibold text-amber-800" href="index.html">Padaria da Ana</a>
  <nav id="alvo" class="flex gap-6 text-sm text-stone-600">
    <a href="#">Cardápio</a>
    <a href="#">A padaria</a>
    <a href="#">Encomenda</a>
  </nav>
</div>
display: flex
gap: 24px
color: oklch(0.444 0.011 73.639)
font-size: 14px

<div class="flex items-center justify-between gap-4 px-4 py-3">
  <a class="font-semibold text-amber-800" href="index.html">Padaria da Ana</a>
  <nav id="alvo" class="hidden gap-6 text-sm text-stone-600 md:flex">
    <a href="#">Cardápio</a>
    <a href="#">A padaria</a>
    <a href="#">Encomenda</a>
  </nav>
</div>

O painel mostra display: none, porque a prévia tem 375 px de largura e o md: só vale a partir de 768. O CSS gerado, esse sim, mostra as duas regras:

.hidden {
  display: none;
}
@media (width >= 48rem) {
  .md\:flex {
    display: flex;
  }
}

Leia a segunda regra como uma condição: "a partir de 48 rem de largura, quem tem md:flex vira flex". Quarenta e oito rem são 768 px, o ponto de virada padrão do Tailwind. E repare na ordem: hidden vem primeiro, a condição vem depois, então no desktop a condição vence. Se você inverter a ordem mental — pensar que a classe que você escreveu por último ganha —, vai errar; o que manda é a ordem no CSS gerado, e o Tailwind já organiza as variantes depois das classes comuns.

Falta o botão. No celular, esconder os links sem oferecer caminho é pior que espremê-los. O caminho é um botão quadrado com três riscos, que abre uma lista. Esse botão é md:hidden — o contrário dos links —, e o menu que ele abre é o assunto das aulas de modal e de menu suspenso. Por hoje, basta a marcação certa:

<button type="button" class="rounded-lg border border-stone-300 p-2 md:hidden"
  aria-label="Abrir menu" aria-expanded="false">
  <span class="block h-0.5 w-5 bg-stone-700"></span>
  <span class="mt-1 block h-0.5 w-5 bg-stone-700"></span>
  <span class="mt-1 block h-0.5 w-5 bg-stone-700"></span>
</button>

Os três span são os riscos: 20 px de largura, 2 px de altura, fundo escuro, um embaixo do outro com mt-1. O aria-label dá nome ao botão, porque ele não tem texto. E o aria-expanded="false" diz ao leitor de tela se o menu está aberto — o JavaScript troca para true quando abre. Quem monta a troca de conteúdo por clique é a aula de abas. Botão sem essas duas informações é um quadrado mudo.

7. Fundo, borda e altura: os detalhes que somam

Com a estrutura pronta, o que separa uma barra amadora de uma barra profissional são três detalhes pequenos. O primeiro é a borda embaixo: border-b border-stone-200. Ela resolve o caso em que a barra branca encosta numa página branca e some — sem ela, a barra só existe quando há conteúdo colorido atrás. O segundo é a altura. Uma barra confortável fica entre 56 e 72 px; com py-3 e texto de 14 px, você chega em 48 px, que é o mínimo aceitável. Se quiser mais, py-4.

O terceiro é o z-50, e ele merece uma explicação porque é a origem de metade dos bugs de layout do mundo. Quando dois elementos se sobrepõem, quem aparece na frente? A resposta padrão é "o que vem depois no HTML". O z-index muda essa ordem — mas só funciona em elementos posicionados, e é por isso que ele anda junto do sticky. Sem z-50, a barra fixa pode ser coberta por uma imagem que vem depois dela no código, e o visitante vê a foto por cima do menu.

8. O link que leva para o lugar certo

Uma barra de navegação só é boa se os links funcionam para todos. Três detalhes de HTML fazem a diferença e nenhum deles é classe. O primeiro: todo href precisa apontar para um arquivo que existe. Link para página inexistente é o erro mais comum de site em construção, e o visitante descobre pelo 404.

O segundo: o texto do link precisa dizer para onde vai. "Clique aqui" e "saiba mais" não dizem nada quando lidos fora de contexto — e quem usa leitor de tela costuma navegar por uma lista de links, justamente fora de contexto. "Cardápio" e "Encomenda" dizem.

O terceiro: a marca precisa ser um link para a página inicial, porque é isso que todo mundo espera. Um visitante perdido clica no nome da padaria. Se ele não for link, o visitante fica sem a saída mais óbvia que existe.

<a href="index.html" class="flex items-center gap-2 font-semibold text-amber-800">
  <span class="grid size-8 place-items-center rounded-lg bg-amber-100 text-sm">A</span>
  Padaria da Ana
</a>

Esse quadradinho de 32 px com a letra "A" é o embrião de um logotipo. Ele usa grid place-items-center para centralizar a letra, rounded-lg para o canto e bg-amber-100 text-amber-800 para a cor. Quando a Ana tiver um desenho de verdade, é só trocar o span por uma imagem de 32 px — a barra não muda em nada.

9. Cenários do dia a dia

Cenário 1: a barra que cobria o título

Com fixed, a barra saiu do fluxo e o título da página ficou escondido atrás dela. A Ana tentou mt-20 no conteúdo e resolveu — até a barra mudar de altura no celular e o número virar errado outra vez. A correção foi trocar por sticky top-0, que não tira o elemento do fluxo e por isso não exige compensação nenhuma. Regra prática: use sticky; só use fixed quando precisar de algo que fique preso mesmo fora do fluxo, como um botão flutuante de WhatsApp.

Cenário 2: o menu que sumiu no tablet

No celular, os links estavam escondidos e o botão aparecia. No tablet de 800 px, os links voltavam — mas o botão continuava lá, ocupando espaço e sem fazer nada. O motivo: o botão tinha md:hidden e os links md:flex, mas o tablet estava em 768 px exatos e alguma regra de zoom mudava a conta. A correção foi testar nos três tamanhos de verdade, com o navegador em modo responsivo, em vez de confiar no número redondo. Breakpoint não é opinião: é medida.

Cenário 3: a barra transparente demais

Empolgada com o efeito de vidro, a Ana usou bg-white/50 e backdrop-blur-lg. No topo da página ficou lindo, porque não havia nada atrás. Ao rolar o cardápio, os preços passaram por baixo da barra e os links ficaram ilegíveis. Ela subiu para bg-white/90 e manteve o desfoque: o efeito continua, o texto de trás vira mancha, os links voltam a se ler. Transparência em barra fixa é tempero, não prato.

Exercício: a barra que fica no topo

A barra precisa continuar visível quando o visitante rola o cardápio, sem sair do fluxo da página. Qual classe de posição faz isso?

<header class=" top-0 z-50 border-b border-stone-200 bg-white/90">...</header>

Dica: é uma palavra só, que em inglês quer dizer "grudento". Ela precisa de uma coordenada junto — top-0 —, senão não sabe onde parar.

11. Resumo

Barra de navegação é um header com um miolo dentro: mx-auto max-w-5xl px-4 py-3 para centralizar e dar respiro, e flex items-center justify-between gap-4 para empurrar a marca e o nav para as pontas. Os links ficam em text-sm text-stone-600 com hover:text-amber-700, e o da página atual ganha cor mais forte, sublinhado afastado e aria-current="page".

Para a barra ficar no topo, sticky top-0 z-50: sticky mantém o elemento no fluxo, top-0 diz onde ele para e z-50 garante que ele fique na frente. O fundo bg-white/90 backdrop-blur dá o efeito de vidro sem perder a leitura, e a borda border-b border-stone-200 separa a barra de uma página branca.

No celular, não esprema: esconda. hidden md:flex nos links, md:hidden no botão, e o menu de verdade fica para a aula de menu suspenso. E lembre que a barra é header com nav dentro, não div com div: a estrutura continua dizendo o que cada pedaço é.

Para lembrar

  • Três partes: marca, navegação e ação. Agrupe antes de distribuir.
  • Miolo: mx-auto max-w-5xl px-4 py-3.
  • Alinhamento: flex items-center justify-between gap-4.
  • mx-auto só centraliza porque existe max-w.
  • Link atual: cor forte, underline underline-offset-8 e aria-current="page".
  • Barra no topo: sticky top-0 z-50 — sticky, não fixed.
  • bg-white/90 backdrop-blur para o efeito de vidro; 80% a 95% de opacidade.
  • hidden md:flex nos links, md:hidden no botão do celular.
  • z-index só vale em elemento posicionado — por isso anda com sticky.
