Tema por Classe

A Ana já tinha espalhado dark: pelo site inteiro seguindo a aula anterior. O cartão escurecia, o botão mudava de cor, o texto clareava — e nada disso acontecia na tela dela, porque faltava combinar uma coisa antes: quem avisa o CSS que a página está no escuro. Nesta aula ela descobre que esse aviso é uma classe, que mora no elemento mais alto da página, e que basta um botão de duas linhas para acender e apagar o tema. De quebra, aprende a escurecer só um pedaço do site — o cupom — sem escurecer o resto.

Você vai aprender
  • Por que dark: sozinho não faz nada e o que ele está esperando.
  • O que a linha @custom-variant dark (&:where(.dark, .dark *)) quer dizer.
  • Onde colocar a classe dark: no <html>, quase sempre.
  • Um botão de trocar tema com o mínimo de JavaScript, e o que cada pedaço faz.
  • Como lembrar a escolha entre uma visita e outra, sem piscar branco ao carregar.
  • Como escurecer só uma seção, deixando o resto da página no claro.
  • O que quebra quando a classe está no lugar errado.

1. A cena: o escuro que não acende

Na aula anterior a Ana aprendeu a escrever pares: bg-white dark:bg-stone-900, text-stone-900 dark:text-stone-100. Copiou o par para o cartão, para o botão, para o selo, para o rodapé. Salvou, recarregou, e a página continuou branca. Aí ela fez o que todo mundo faz: tirou e pôs a classe, trocou a ordem, abriu o inspetor. Nada.

O motivo é simples e vale entender antes de decorar: o dark: não escurece nada por conta própria. Ele é uma condição — "aplique esta regra quando a página estiver no tema escuro". A página, por padrão, está no claro. Ninguém tinha dito o contrário, então a condição nunca foi verdadeira e as regras com dark: ficaram paradas, esperando.

Quem diz que a página está no escuro? No Tailwind v4, você escolhe — e a escolha mais comum é uma classe chamada dark colocada num elemento. Daí o nome desta aula: o tema é decidido por classe, não pelo sistema operacional. A vantagem é controle: o visitante aperta um botão, a classe entra, o site escurece. A desvantagem é que alguém precisa escrever esse botão.

2. O que a variante dark espera

Para o Tailwind tratar dark: como "quando houver uma classe dark acima de mim", ele precisa de uma linha no seu arquivo CSS de entrada. Ela se chama @custom-variant e é esta aqui:

@custom-variant dark (&:where(.dark, .dark *));

Lendo com calma: "crie uma variante chamada dark, cujo seletor é o próprio elemento (&) quando ele tiver a classe .dark, ou quando ele for descendente de um elemento com a classe .dark (.dark *)". Traduzindo para português: tudo que está dentro de um elemento marcado como escuro também é escuro, e o próprio elemento marcado conta. É a mesma ideia de herança das variáveis de tema, agora com uma classe como interruptor.

O :where() em volta não é enfeite. Ele serve para que essa condição não aumente a "força" da regra no CSS. Sem ele, dark:bg-stone-900 ficaria mais forte que qualquer classe normal e ganharia brigas que você não queria. Com ele, a classe escura tem o mesmo peso de uma classe comum — e o que decide é a ordem em que o Tailwind escreveu as regras no arquivo final.

É fácil ver isso no CSS gerado. A regra da classe escura carrega a condição inteira no seletor:

.dark\:bg-stone-900:where(.dark, .dark *) {
  background-color: var(--color-stone-900);
}

Aquele :where(.dark, .dark *) no fim é o "e somente se" da regra. Ela existe no arquivo desde o começo; o que muda é se o seletor casa com o elemento. Quando o <html> ganha a classe, todos os descendentes passam a casar e o fundo escuro entra em cena. Quando ela sai, os seletores deixam de casar e vale a regra clara — que está escrita antes.

Essa ordem você pode conferir quando quiser: as regras com dark: vêm depois das regras normais. Por isso o par funciona sem !important e sem truque nenhum. É um detalhe técnico que explica por que você não precisa se preocupar com a ordem em que escreve as classes no HTML.

variante
Um prefixo que muda a condição de uma classe: dark:, hover:, md:. Sem a condição satisfeita, a classe não vale.
@custom-variant
A linha do CSS de entrada que ensina ao Tailwind qual é a condição de uma variante — no caso, a existência da classe .dark.
:where()
Envelope que zera a especificidade do que está dentro. É o que permite a classe escura ganhar pela ordem, sem virar uma regra "mais forte" que as outras.
especificidade
A nota de força de um seletor no CSS. Empate vai para quem vem depois no arquivo; é assim que o par claro/escuro se resolve.
classList
O objeto do JavaScript que lista e altera as classes de um elemento: add, remove, toggle.
localStorage
Uma gaveta do navegador que guarda textos simples e sobrevive ao recarregar. Boa para lembrar a escolha de tema.

3. Onde colocar a classe dark

A escolha mais comum — e a que resolve quase tudo — é o elemento <html>, o primeiro de todos. Ele envolve o cabeçalho, o conteúdo, o rodapé, tudo. Se a classe está ali, o site inteiro é escuro; se não está, é claro. Você não escreve essa classe à mão: quem coloca é o JavaScript do botão, como veremos daqui a pouco.

<html lang="pt-BR" class="dark">
  <head>…</head>
  <body class="bg-white text-stone-900 dark:bg-stone-900 dark:text-stone-100">
    <p>Pão quentinho</p>
  </body>
</html>

Repare que o dark: aparece no <body>, não no <html>. O corpo é quem pinta o fundo da página; o <html> é só o aviso. Essa separação é útil: o aviso pode estar ligado enquanto um componente tem a própria decoração. E é por isso que, quando o tema "não pega", a primeira coisa a conferir é se a classe entrou no elemento certo.

Onde vai a classeAlcanceQuando serve
<html>a página inteira, inclusive a margem de forao botão de trocar tema do site
<body>o conteúdo visívelquando o <html> é de outro sistema e você não pode mexer

Também vale saber que você pode marcar um elemento menor. Se a classe dark está num <div>, só o que está dentro dele fica escuro — e isso é um recurso, não um acidente. É assim que se faz um cupom escuro no meio de uma página clara, ou um bloco de destaque com a cara do tema noturno. Guarde o truque; voltamos nele na seção 7.

O cartão já tem os pares dark: escritos, mas a página continua clara porque nenhum ancestral tem a classe dark. Coloque dark na classe da caixa de fora e rode: o cartão escurece na hora.

<div class="p-4 rounded-2xl bg-stone-50">
  <div id="alvo" class="p-4 rounded-xl bg-white text-stone-900 dark:bg-stone-800 dark:text-stone-100">
    Pão quentinho
  </div>
</div>
padding: 16px
background-color: rgb(255, 255, 255)
color: oklch(0.216 0.006 56.043)
border-radius: 12px

<div class="dark p-4 rounded-2xl bg-stone-50">
  <div id="alvo" class="p-4 rounded-xl bg-white text-stone-900 dark:bg-stone-800 dark:text-stone-100">
    Pão quentinho
  </div>
</div>

Se você rodar a solução e depois apagar a palavra dark, o cartão volta a ser branco na mesma hora. O dark: continua escrito no cartão, intacto: o que mudou foi a condição. Essa separação entre condição (a classe no alto) e consequência (as regras dark: espalhadas) é o coração desta aula. Com ela, o mesmo HTML serve para os dois temas e não existe página duplicada.

4. O botão que acende o escuro

Agora a parte que não é Tailwind. Um botão que troca de tema precisa mexer no HTML enquanto a pessoa usa a página — e HTML sozinho não faz isso. Quem faz é o JavaScript, a linguagem que o navegador entende além do HTML e do CSS. Daqui para frente, todo trecho com a etiqueta <script> é JavaScript, e eu vou avisar sempre que isso acontecer.

<button type="button" class="rounded-lg border border-stone-300 px-3 py-1 text-sm" data-trocar-tema>
  Trocar tema
</button>

<script>
  var botao = document.querySelector("[data-trocar-tema]");
  botao.addEventListener("click", function () {
    document.documentElement.classList.toggle("dark");
  });
</script>

São quatro linhas de JavaScript e vale entender cada uma, porque a lógica se repete em qualquer site. document é a página inteira; document.querySelector("[data-trocar-tema]") procura o elemento que tem aquele atributo e guarda na variável botao. O addEventListener("click", …) significa "quando alguém clicar, execute isto". document.documentElement é a tag <html> — exatamente o elemento onde combinamos colocar a classe. E classList.toggle("dark") é o interruptor: se a classe não está lá, põe; se está, tira.

O atributo data-trocar-tema é só um apelido que você inventa para achar o botão. Não é classe do Tailwind, não é atributo do HTML: é um nome livre, e o hábito de usar data- para isso evita confusão com as classes de estilo. Podia ser um id, mas o id só pode existir uma vez na página, e um botão de tema pode aparecer duas vezes (no cabeçalho e no rodapé).

PedaçoO que éO que faz ali
documenta página, para o JavaScriptponto de partida de qualquer busca
querySelector("[data-trocar-tema]")uma busca por atributoacha o botão e devolve o elemento
addEventListener("click", …)um "quando acontecer"guarda a função para o clique
document.documentElementa tag <html>o elemento onde a classe entra
classList.toggle("dark")o interruptorpõe ou tira a classe, e devolve o estado

O laço que fecha a ideia: o botão põe uma classe; o Tailwind já escreveu as regras que respondem a essa classe; o navegador recalcula a página. Nenhuma linha de Tailwind muda quando você clica. O que muda é o estado do HTML — e o CSS reage. É a mesma engrenagem de hover: e focus:, que você já viu em hover: um estado, um conjunto de regras esperando por ele.

5. Por que o par é claro e escuro, na mesma classe

Um detalhe que vale revisitar agora, porque é onde os iniciantes erram: o jeito certo é escrever a classe clara e a escura juntas, no mesmo elemento. Não se escreve dark:bg-stone-900 sozinho, contando com o fundo branco para o tema claro. Se o claro é o padrão, ele precisa estar explícito — porque o navegador não tem fundo branco garantido, e porque assim você lê o componente inteiro numa linha.

<div class="bg-white text-stone-900 border border-stone-200
            dark:bg-stone-900 dark:text-stone-100 dark:border-stone-700">
  Pão quentinho
</div>

Esse bloco mostra a convenção que o guia usa: cada linha do componente trata de uma coisa, e cada coisa tem sua versão escura ao lado. Fundo, tinta, borda. Quando você lê dark:border-stone-700 sabe exatamente qual borda está sendo trocada, porque a borda clara está na linha de cima. Se o par estivesse separado em dois arquivos ou em duas classes diferentes, você teria que caçar.

Esta prévia está no escuro. Complete o par do cartão: acrescente dark:bg-stone-900 e dark:text-stone-100 e rode para ver o cartão acompanhar a página.

<div id="alvo" class="p-6 rounded-xl bg-white text-stone-900">
  <p class="font-medium">Pão de queijo</p>
  <p class="text-sm text-stone-600">saído do forno às 6h</p>
</div>
padding: 24px
background-color: rgb(255, 255, 255)
color: oklch(0.216 0.006 56.043)
border-radius: 12px

<div id="alvo" class="p-6 rounded-xl bg-white text-stone-900 dark:bg-stone-900 dark:text-stone-100">
  <p class="font-medium">Pão de queijo</p>
  <p class="text-sm text-stone-600 dark:text-stone-400">saído do forno às 6h</p>
</div>

Antes de rodar, repare no que está faltando no HTML inicial: o cartão branco numa página escura fica como um holofote. É o sintoma clássico de quem começou o tema escuro pelo componente e esqueceu o fundo do cartão. Depois de rodar, repare também na segunda linha do cartão: no escuro, o text-stone-600 fica apagado demais, e por isso a solução troca por dark:text-stone-400. Par de fundo sem par de tinta é meio par.

6. Lembrar a escolha entre uma visita e outra

Do jeito que está, o tema vale até a pessoa recarregar a página. Recarregou, voltou ao claro. Se o visitante escolheu o escuro porque a luz do balcão é forte, ele vai ter que escolher de novo toda vez — e é aí que o localStorage entra. Ele é uma gavetinha do navegador onde você guarda textinhos que sobrevivem ao recarregar.

<script>
  var botao = document.querySelector("[data-trocar-tema]");
  botao.addEventListener("click", function () {
    var escuro = document.documentElement.classList.toggle("dark");
    localStorage.setItem("tema", escuro ? "escuro" : "claro");
  });
</script>

classList.toggle devolve true quando passou a ter a classe e false quando tirou. Guardamos isso em escuro e escrevemos na gaveta com localStorage.setItem("tema", …). O ? e o : no meio são o "se/então" do JavaScript: se for escuro, guarde "escuro"; senão, guarde "claro".

Falta ler a gaveta quando a página abre. E aqui há um detalhe de qualidade: essa leitura tem de acontecer no <head>, antes de o corpo ser desenhado. Se você ler depois, o navegador já pintou a página de branco e a troca aparece como um piscar — aquele flash branco chato que todo site com tema escuro já teve. O script que a página que você está lendo usa é exatamente este, e ele é curto:

<head>
  <script>
    (function () {
      try {
        var t = localStorage.getItem("tema");
        if (t === "escuro") document.documentElement.classList.add("dark");
      } catch (e) {}
    })();
  </script>
</head>

Três coisas para observar. O if só age quando a gaveta diz "escuro" — o padrão continua claro. O try … catch protege contra navegador que bloqueia armazenamento (acontece em abas anônimas e em algumas configurações de privacidade): se der erro, o script segue em silêncio em vez de quebrar a página. E o classList.add não é toggle: aqui queremos garantir a classe, não alterná-la.

Um aviso honesto: sem JavaScript o botão não funciona e o site fica no claro. Isso é aceitável — o conteúdo continua legível —, mas é bom saber. Quem precisa que o escuro funcione sem JavaScript usa a preferência do sistema, que é o assunto da próxima aula. As duas técnicas convivem, e muita gente usa a preferência do sistema como padrão e a escolha manual por cima.

7. Escurecer só um pedaço: o cupom

Agora o truque que a herança da classe permite. A Ana queria um cupom de desconto com cara de tema escuro no meio da vitrine clara — um bloco que chamasse atenção. Não precisa de nada novo: basta pôr dark na classe do cupom. Ele passa a ser "a página escura" para efeito dos dark: que estão dentro dele.

O cupom já tem os pares dark: escritos, mas está claro como o resto. Ponha dark na classe do cupom — e só nele — para escurecer apenas esse bloco, deixando a linha de baixo no claro.

<div class="p-4 bg-white">
  <div id="alvo" class="p-3 rounded-lg bg-white text-stone-900 dark:bg-stone-800 dark:text-stone-100">
    Cupom: 10% no café
  </div>
  <p class="fora bg-white text-stone-700">A padaria abre às 6h</p>
</div>
padding: 12px
background-color: rgb(255, 255, 255)
color: oklch(0.216 0.006 56.043)
border-radius: 8px

<div class="p-4 bg-white">
  <div id="alvo" class="dark p-3 rounded-lg bg-white text-stone-900 dark:bg-stone-800 dark:text-stone-100">
    Cupom: 10% no café
  </div>
  <p class="fora bg-white text-stone-700">A padaria abre às 6h</p>
</div>

O mesmo vale ao contrário, e é uma das coisas mais úteis de saber: para manter um bloco claro dentro de uma página escura, você não precisa de classe nenhuma — precisa de valores fixos no bloco. Se a página está escura e o cartão tem bg-white text-stone-900 sem par, ele fica claro. O par com dark: é só para quem deve acompanhar o tema. Componente que deve ser sempre claro (um selo de "novo", uma etiqueta de preço) se protege ficando sem par.

8. Cenários do dia a dia

Cenário 1: o site escurece, mas as bordas da página continuam brancas

A Ana pôs a classe dark num <div> de conteúdo, dentro do <body>. Os textos e cartões escureceram, e a margem de fora continuou branca, porque o <body> ficou de fora do bloco escuro. A correção é subir a classe para o <html> e deixar o fundo do <body> com o par bg-white dark:bg-stone-900. Regra de bolso: o tema começa onde começa a pintura.

Cenário 2: o flash branco ao abrir a página

Ela guardou a escolha no localStorage e leu a gaveta no fim do <body>. Funcionava, mas a cada página nova o site abria branco e escurecia meio segundo depois. Movendo a leitura para o <head>, antes de qualquer pintura, o problema desapareceu. É a diferença entre arrumar a casa depois da visita entrar e arrumar antes de abrir a porta.

Cenário 3: dois botões, uma escolha

O site ganhou um botão de tema no cabeçalho e outro no rodapé. Cada um tinha o próprio document.querySelector, e os dois mexiam na mesma classe — funcionava, mas o localStorage era gravado duas vezes com nomes diferentes em cada script, e a bagunça apareceu quando ela quis um terceiro botão. A correção foi uma função só, chamada pelos dois botões, e um único nome de chave ("tema") em todo o site. Um estado, um lugar.

10. Fixando com o olho: o que olhar quando não funciona

Antes do resumo, uma lista de conferência que economiza tempo. Ela é curta porque os erros são poucos e sempre os mesmos. Primeiro: a classe dark existe em algum ancestral do elemento? Abra o inspetor e olhe a árvore de cima para baixo — a classe pode estar num irmão, que não ajuda. Segundo: a linha @custom-variant está no arquivo CSS de entrada? Sem ela, o dark: responde à preferência do sistema, não à classe. Terceiro: o CSS foi recompilado depois da última alteração? No modo de desenvolvimento com npm, um build parado deixa regras velhas.

Quarto, e o mais sutil: o elemento tem as duas versões? Um componente com dark:bg-stone-900 mas sem bg-white parece funcionar no escuro e mostra o fundo padrão no claro — que pode ser transparente, e aí o cartão fica com a cor do pai. O painel das caixas mostra isso na hora: se o background-color não aparece, nenhuma classe de fundo está valendo ali. Quinto: o texto tem a cor do par escuro? Fundo escuro com tinta escura é o erro seguinte ao primeiro acerto.

E uma conferência que não é de código: o tema escuro não é o tema claro invertido. Sombras fortes no claro viram borrões no escuro, branco puro machuca a vista, e a hierarquia de texto precisa de outros degraus. A aula de componentes no escuro cuida disso com calma. Aqui, o que importa é que a mecânica já está no lugar: uma classe no alto, pares espalhados, um botão de quatro linhas.

11. Resumo

O dark: é uma condição, não uma ordem. Quem torna a condição verdadeira é a classe dark, colocada num elemento ancestrais — quase sempre o <html> —, e é o JavaScript do botão que a coloca e tira. Para o Tailwind obedecer a essa classe em vez da preferência do sistema, o seu CSS de entrada precisa da linha @custom-variant dark (&:where(.dark, .dark *)). O :where() mantém a briga de especificidade justa, e a ordem das regras no arquivo final é o que faz o par funcionar sem !important.

O resto é disciplina: escrever sempre o par (claro e escuro no mesmo elemento), guardar a escolha no localStorage e ler essa escolha no <head> para não piscar branco, e usar a herança a seu favor quando quiser só um bloco escuro. Um estado, um lugar, um botão.

Para lembrar

  • dark: sozinho não faz nada: falta a classe dark num ancestral.
  • @custom-variant dark (&:where(.dark, .dark *)) liga o dark: à classe.
  • A classe vai no <html> no caso comum; num <div> ela vale só para dentro dele.
  • classList.toggle("dark") é o interruptor; add só liga.
  • document.documentElement é a tag <html> para o JavaScript.
  • localStorage.setItem("tema", …) guarda; getItem lê.
  • Leia a escolha no <head>, antes da pintura, para evitar o flash branco.
  • Escreva sempre o par: bg-white dark:bg-stone-900.
  • Componente que deve ser sempre claro fica sem par — e é assim que ele se protege.
  • Sem JavaScript o botão não troca nada; a preferência do sistema é o plano B da próxima aula.
