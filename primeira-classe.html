A Primeira Classe

A Ana tem um cartão na tela e um problema bobo: o texto encosta na borda. Ela já sabe que existe um jeito de dar respiro, mas o CSS que ela viu por aí parece uma lista de regras com chaves e pontos e vírgulas, e ela não quer decorar nada disso agora. Nesta aula ela escreve a primeira classe do Tailwind — p-4 — e descobre o que acontece por baixo: o navegador lê essa palavra, o Tailwind gera o CSS, e o espaço aparece. Sem instalar nada, sem arquivo de configuração, sem quebrar a cabeça.

Você vai aprender
  • O que é uma classe no HTML e onde ela mora (no atributo class).
  • O que p-4 significa e por que ele vira 16 px.
  • Como ler o painel que mostra o CSS computado, sem decorar CSS.
  • A escala de espaço do Tailwind: 1, 2, 3, 4, 6, 8.
  • Como juntar duas ou três classes no mesmo elemento.
  • A diferença entre class e style="", e quando cada um serve.
  • O que fazer quando a classe não faz nada: erro de digitação e classe que não existe.

1. A cena: o pão encostado na borda

A Ana está montando a página de uma padaria. Ela escreveu o HTML mais simples do mundo: uma caixa e um texto dentro. Ficou assim:

<div class="cartao">Pão quentinho</div>

O navegador mostra a caixa colada no canto, e o texto colado na borda da caixa. Parece que falta ar. É sempre assim no começo: o navegador tem um jeito padrão de desenhar as coisas, e esse jeito não é bonito — é só o mais neutro possível, para não atrapalhar. Quem decide o desenho é você.

Antes de qualquer coisa, vale entender o que aquela palavra class faz ali. Ela não é do Tailwind, é do HTML. Ela existe desde os anos 1990 e serve para dar um nome a um pedaço de conteúdo. Com um nome, você consegue dizer "tudo que se chama cartao recebe tal aparência". O Tailwind não inventou esse mecanismo — ele só entregou um catálogo enorme de nomes prontos.

E é isso que muda o jogo para quem está começando: você não precisa inventar nome nenhum. Precisa escolher, no catálogo, a palavra que descreve o que quer. Quer espaço dentro? p, de padding. Quer fundo colorido? bg, de background. Quer texto maior? text-lg. As palavras são curtas, mas não são código secreto: são abreviações em inglês, e a gente vai traduzindo uma por uma.

2. O que é uma classe no HTML

Toda tag pode carregar um atributo chamado class. O valor é uma lista de nomes separados por espaço:

<div class="p-4 bg-amber-100">Pão quentinho</div>

Aqui são dois nomes: p-4 e bg-amber-100. Cada um será explicado em algum momento; por ora, guarde a mecânica: um elemento pode ter várias classes, e cada classe soma uma característica. É como uma etiqueta de características colada na caixa. Uma etiqueta diz "tem 16 px de respiro por dentro", a outra diz "tem fundo amarelo claro".

Isso é diferente de outras linguagens que você talvez já tenha esbarrado. Não há cascata de herança para você controlar, não há arquivo separado para sincronizar: a etiqueta está ali, no mesmo lugar em que o conteúdo está. Quem lê o HTML entende a aparência sem abrir outro arquivo. Essa é a maior vantagem e também a maior reclamação — quando há muitas classes, a linha fica longa. A gente volta a esse assunto mais adiante; por enquanto, uma ou duas classes por elemento.

tag
A peça do HTML: <div>, <p>, <button>. É o tipo da caixa.
atributo
Uma informação dentro da tag, no formato nome="valor". class é um atributo; id também.
classe
Um nome que o CSS usa para achar o elemento. No Tailwind, cada classe é uma utilidade pronta — uma única característica visual.
utilitária
O nome que se dá a esse tipo de classe: ela faz uma coisa só, e faz bem. O oposto de uma classe "cartao" que junta dez coisas diferentes.

Uma última palavra sobre o id, que aparece nas caixas desta aula. O id é um nome único — só um elemento na página pode ter aquele nome. O Tailwind não usa id para nada; nós usamos só para dizer ao painel qual elemento ele deve descrever. Guarde: id="alvo" é a lupa do painel, não uma classe.

3. A primeira classe: p-4

Vamos ao respiro. A letra p vem de padding, o espaço entre o conteúdo e a borda de dentro da caixa. O número 4 é a posição na escala do Tailwind. Juntos, p-4 quer dizer: 16 pixels de respiro em todos os lados.

O cartão está com p-1, que dá 4 px. Troque a classe para o respiro de 16 px e clique em Rodar.

<div id="alvo" class="p-1">Pão quentinho</div>
padding: 4px

<div id="alvo" class="p-4">Pão quentinho</div>

Repare no que o painel mostra depois de rodar: uma linha só, padding: 4px antes, padding: 16px depois. Não é o Tailwind falando bonito — é o navegador informando o valor que ele realmente aplicou. Toda a conferência do guia é feita assim, lendo o valor final, e não a beleza do código.

Por que 4 vira 16 e não 4 pixels? Porque a escala do Tailwind não é em pixels crus: é um multiplicador. Cada passo vale 0,25 rem, e 1 rem é o tamanho de fonte padrão do navegador, que é 16 px. Então 4 × 0,25 rem = 1 rem = 16 px. O CSS gerado mostra isso na cara:

.p-4 {
  padding: calc(var(--spacing) * 4);
}

--spacing é uma variável que vale 0,25 rem. Ou seja: o Tailwind escreve a conta, e o navegador resolve. Se amanhã o tamanho de fonte base mudar, a proporção se mantém — é por isso que a escala é em rem e não em pixels fixos.

4. Lendo o que o navegador fez

Quem começa tende a olhar o código e adivinhar o resultado. O hábito que vale ouro é o contrário: mudar, rodar, ler o que o navegador respondeu. O painel das caixas faz isso por você, mas no seu projeto você faz à mão. O caminho é curto:

Firefoxbotão direito → Inspecionaraba Computed, caixa do elemento
Safarimenu Desenvolvedor → Mostrar Web Inspectoraba Computed

A aba Computed mostra o valor final de cada propriedade, já com as contas resolvidas: ali p-4 aparece como padding: 16px. É a fonte da verdade. As abas Styles mostram as regras na ordem em que o navegador as aplicou, o que ajuda quando algo não está pegando.

Existe um detalhe que confunde e vale desmistificar: o painel mostra só as propriedades que a classe mudou. Um div sem classe já é display: block, já tem margin: 0. Mostrar essas linhas seria ruído. Quando o Tailwind não muda nada, o painel fica vazio — e isso é informação: aquela classe não teve efeito.

5. A escala do espaço

A escala é curta e vale memorizar só o começo. Os passos que aparecem o tempo todo:

ClasseValorOnde costuma servir
p-14 pxrespiro mínimo, etiqueta pequena
p-28 pxbotão pequeno, etiqueta
p-312 pxcampo de formulário compacto
p-416 pxo padrão de cartão e botão
p-624 pxcartão grande, seção interna
p-832 pxárea de destaque, capa

Não existe p-5? Existe — 20 px. E p-7? Também, 28 px. A escala é contínua de 0 a 96, e depois vai de 4 em 4 em valores maiores. O que acontece é que ninguém usa tudo: os projetos sérios usam meia dúzia de degraus, sempre os mesmos, e é essa repetição que faz o desenho parecer coerente. Se você usar 13, 17 e 21 px inventados, o resultado parece torto mesmo que cada peça esteja "certa".

Há uma razão prática para a escala ser assim, e ela vale para todo o guia: quando duas pessoas escrevem a mesma tela em dias diferentes, elas chegam nos mesmos degraus e o resultado parece desenhado por uma pessoa só. Espaçamento é ritmo, e ritmo só existe quando se repete. Se você quiser um número fora da escala — 18 px, digamos —, o Tailwind aceita: p-[18px] com colchetes. Use com parcimônia, e sempre com um motivo que você consiga explicar em uma frase.

A escala também tem atalhos por lado. px-4 é só na horizontal (esquerda e direita), py-2 só na vertical, pt-8 só no topo, pe-4 só no fim da linha (direita em português). Esses atalhos são o assunto de uma aula inteira, porque é ali que nasce a maioria dos layouts apertados.

6. Duas classes: cor e texto

Respiro resolvido, o cartão continua sem graça. Vamos pintar. A classe de fundo é bg- mais o nome da cor e o tom. bg-amber-100 é o âmbar bem clarinho; text-amber-900 é o mesmo âmbar, no tom escuro, para o texto. Essa lógica de nome — cor, número de 50 a 950 — vale para as dezenove famílias de cor do Tailwind.

O fundo já está âmbar claro. Falta o texto escuro para dar contraste: acrescente text-amber-900 ao cartão.

<div id="alvo" class="bg-amber-100 p-4">Pão quentinho</div>
padding: 16px
background-color: oklch(0.962 0.059 95.617)

<div id="alvo" class="bg-amber-100 p-4 text-amber-900">Pão quentinho</div>

Quando rodar a solução, o painel vai mostrar três linhas: o respiro, o fundo em oklch(...) e a cor do texto em outro oklch(...). Esse oklch é um jeito moderno de escrever cor, com três números: claridade, saturação e ângulo do tom. Você não precisa calcular nada — o Tailwind já traz a paleta pronta. Só não se assuste ao ver o valor: ele é o mesmo amarelo que você escolheu, escrito de outro jeito.

O CSS que o Tailwind gera para essas duas classes é curto e legível: ele só aponta para as variáveis da paleta. Não há hexadecimal na sua página, e é por isso que trocar o tom depois é só trocar o número:

.bg-amber-100 {
  background-color: var(--color-amber-100);
}
.text-amber-900 {
  color: var(--color-amber-900);
}

Repare também que as classes se somam sem brigar: p-4 cuida do espaço, bg-amber-100 do fundo, text-amber-900 da cor da letra. Cada uma mexe numa coisa. É por isso que a ordem em que você as escreve não importa — class="p-4 bg-amber-100" e class="bg-amber-100 p-4" desenham igual. A exceção são classes que disputam a mesma propriedade (dois p- no mesmo elemento); aí vale a que o Tailwind colocou por último no CSS, e não a que você escreveu por último. A gente evita essa briga não repetindo a propriedade.

7. Classe ou style=""?

Talvez você já tenha visto style="padding: 16px" em algum lugar. Funciona. Então por que aprender classes? A diferença não é de gosto, é de consequência:

<div style="padding:16px;background:#fef3c7">Pão</div>
<div class="p-4 bg-amber-100">Pão</div>

Os dois desenham parecido. Mas o primeiro não aceita variação responsiva, não aceita estado de foco, não combina com o tema escuro e não pode ser ajustado de um lugar só. O segundo aceita prefixos: md:p-8 muda o respiro em telas grandes, hover:bg-amber-200 muda no mouse, dark:bg-amber-950 muda no escuro. Esses prefixos são a razão de existir do Tailwind, e eles só funcionam com classes.

O style="" não é proibido: ele é a válvula de escape para valores que não estão na escala, como uma altura calculada em tempo de execução. Só não pode virar hábito, porque aí você perde justamente o que veio buscar.

8. Quando a classe não faz nada

Uma hora vai acontecer: você escreve a classe, salva, recarrega e nada muda. Na maioria das vezes é uma das três coisas abaixo.

  • Erro de digitação. p-4 existe; p4 não; padding-4 não; P-4 não (o Tailwind diferencia maiúsculas). O pior é que nada acontece e nenhum aviso aparece. Confira a classe letra por letra.
  • A classe não está no HTML. O Tailwind só gera o CSS das classes que encontra escritas no arquivo. Se a classe é montada por código, com pedaços juntos, ele não vê — e o CSS não existe. Escreva a classe inteira, sempre.
  • O arquivo não foi recompilado. No modo de desenvolvimento com npm, o CSS é gerado num arquivo separado: se o processo que gera não está rodando, o CSS fica velho. É o assunto do nível 3, mas fica a dica: se só a página nova não muda, olhe o processo de build.

Deixe o botão com 16 px de respiro interno e cantos de 12 px — duas classes: p-4 e rounded-xl.

<div id="alvo" class="p-4 bg-amber-100">Comprar pão</div>
padding: 16px
background-color: oklch(0.962 0.059 95.617)

<div id="alvo" class="p-4 rounded-xl bg-amber-100">Comprar pão</div>

Se digitar rounded-xl com dois "l" ou com underline no lugar do hífen, o painel continua mostrando só o padding. Isso já é o diagnóstico: a classe de arredondamento não gerou nada. Na dúvida, compare o seu HTML com a solução, caractere por caractere — é o que a gente faz com mais frequência do que gostaria de admitir.

9. Cenários do dia a dia

Cenário 1: o cartão parece certo no computador e apertado no celular

A Ana usou p-6 no cartão, 24 px de respiro. No monitor, elegante. No celular, o cartão ocupa a largura toda e 24 px de cada lado comem metade do espaço útil do texto. A solução não é escolher um número médio que fica ruim nos dois: é usar o prefixo de breakpoint e deixar o respiro crescer com a tela — p-4 md:p-6. Você vai ver isso com calma na aula de responsivo; a semente é esta: espaçamento é uma decisão por tamanho de tela.

Cenário 2: dois espaçamentos brigando e o menor perdendo

Ela colou um componente pronto com p-4 e, na mesma linha, acrescentou p-6 para "aumentar um pouco". Resultado: o cartão ficou com 24 px, mas ninguém sabia por quê, e dias depois, ao trocar a ordem das classes, o espaçamento mudou sozinho. A regra prática é simples: uma propriedade, uma classe. Se precisa variar por tela, use o prefixo (p-4 md:p-6), não a repetição. Quando a repetição for inevitável, saiba que vence a última regra que o Tailwind gerou, e não a última que você escreveu.

Cenário 3: "não aparece nada no painel"

O painel vazio assusta. Na maioria das vezes ele está dizendo a verdade: a classe não está gerando CSS nenhum — chute no nome, erro de digitação, ou um elemento que não é o id="alvo". A segunda causa é olhar o elemento errado: o painel descreve o alvo, então se você mexeu no filho, ele não muda. E há o caso legítimo: a classe existe, mas o valor que ela aplica é exatamente o que o elemento já tinha. Aí não há diferença para mostrar, e o silêncio é a resposta certa.

Exercício: o cartão da padaria

No seu arquivo, deixe o cartão com 24 px de respiro interno, fundo âmbar claro e texto âmbar escuro. Depois responda: qual é a classe do respiro?

<div class=" bg-amber-100 text-amber-900">Pão quentinho</div>

Dica: a escala é de 4 em 4 até 16; 24 px é o sexto degrau. Se você escrever p-4, o cartão fica com 16 px — funciona, mas não é o pedido.

11. Resumo

Uma classe é um nome que você coloca no atributo class de uma tag, e o Tailwind transforma esse nome em CSS. p-4 dá 16 px de respiro interno porque a escala é um multiplicador de 0,25 rem; o CSS gerado é literalmente padding: calc(var(--spacing) * 4). Um elemento aceita várias classes, cada uma cuidando de uma propriedade, e a ordem em que você as escreve no HTML não altera o resultado.

O hábito que sustenta todo o resto é conferir o CSS computado: o painel das caixas ou a aba Computed do navegador. É ali que você descobre que a classe não existe, que o nome está errado ou que o elemento observado é outro. E o style="" fica reservado para o valor fora da escala — a classe é o caminho normal, porque aceita breakpoint, estado e tema.

Para lembrar

  • Classe mora no atributo class, em nomes separados por espaço.
  • p é padding, o espaço por dentro; m é margin, o espaço por fora.
  • p-4 = 16 px; a conta é 4 × 0,25 rem, e 1 rem = 16 px.
  • Escala curta: 1=4, 2=8, 3=12, 4=16, 6=24, 8=32 px.
  • bg- pinta o fundo, text- pinta a letra; o número vai de 50 a 950.
  • Cada classe mexe em uma propriedade; a ordem no HTML não importa.
  • Duas classes da mesma propriedade: vence a última que o Tailwind gerou.
  • Classe inexistente ou digitada errado não avisa nada — confira letra por letra.
  • O painel mostra só o que a classe mudou, e descreve o elemento com id="alvo".
  • style="" é válvula de escape, não o caminho do dia a dia.
