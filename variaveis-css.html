Variáveis CSS

A Ana abriu uma barraca na feira do bairro, com o mesmo pão, o mesmo café e o mesmo site. Só uma coisa muda: a barraca é verde, e o site é âmbar. Ela não quer manter dois sites, nem um segundo arquivo de CSS, nem recompilar nada quando trocar de lugar — quer o mesmo HTML pintado de outra cor. A resposta está numa camada que o Tailwind já entrega pronta e que quase ninguém abre: o bloco de variáveis que vai para o CSS final. Nesta aula a Ana descobre o que o compilador publica, como sobrescrever um valor sem tocar nas classes, por que às vezes a troca não pega, e como declarar uma variável com tipo para ela nunca chegar vazia.

Você vai aprender

  • A diferença entre declarar uma variável no @theme e declará-la em :root.
  • Como sobrescrever uma cor do tema em uma parte do site, sem recompilar.
  • Por que a troca às vezes não pega — e o que @theme inline resolve.
  • Como a variável --spacing muda o respiro de um bloco inteiro.
  • O que @property acrescenta: tipo, valor inicial e herança.
  • Como usar uma variável em classe de tamanho, cor e respiro.
  • Como ler e escrever uma variável pelo JavaScript.

1. A cena: o mesmo site, outra cor

O site da Ana tem três páginas e uma cor só: o âmbar da padaria. Na feira, a barraca é verde, e ela não abre mão disso. As opções que passaram pela cabeça dela foram todas ruins. Copiar o site e trocar as cores, mantendo dois projetos: em um mês, um dos dois fica velho. Criar uma classe nova (bg-verde) e repetir tudo: o HTML dobra de tamanho. Recompilar o CSS com outra cor antes de abrir a barraca: funciona, mas depende de ela lembrar do passo e de ter um terminal à mão às seis da manhã.

Existe um caminho mais simples, e ele parte de uma constatação: as classes do Tailwind não guardam cores, guardam nomes de variáveis. Quando o navegador desenha um bg-amber-50, ele não consulta o Tailwind; consulta uma variável chamada --color-amber-50 que está declarada na página. Se essa variável puder ser trocada em um pedaço do documento, a mesma classe pinta uma coisa na padaria e outra na feira. Nenhum build, nenhum HTML duplicado.

Só que essa conversa tem uma pegadinha no meio, e ela é o motivo desta aula existir: existem duas camadas de variáveis no Tailwind v4, uma que gera classes e outra que só guarda valores, e o jeito de escrever muda o resultado. Quem confunde as duas passa a tarde trocando um valor que não chega na tela.

2. O que o Tailwind deixa no CSS final

Vamos começar pelo que existe de verdade, sem promessa. Se você compilar um projeto pequeno — um cartão com bg-marca e p-4 — e abrir o arquivo gerado, a primeira coisa que aparece, depois do comentário da licença, é a ordem das camadas. A segunda é esta:

@layer theme {
  :root, :host {
    --font-sans: -apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, sans-serif;
    --spacing: 0.25rem;
    --color-marca: #b4532a;
  }
}

Leia de novo, devagar, porque é aqui que o assunto começa. O Tailwind não escreveu #b4532a dentro de cada regra que usa a cor da marca. Ele escreveu a cor uma vez, como variável, num bloco que vale para o documento inteiro. As regras das classes apontam para esse nome. E o valor continua sendo uma variável de CSS comum no navegador: dá para ler, dá para trocar em tempo de execução, dá para perguntar o valor pelo console.

O seletor duplo :root, :host merece uma explicação curta. :root é o elemento raiz do documento, o <html>; declarar ali é o jeito de dizer “vale para a página toda”, porque tudo que está dentro herda. :host é o mesmo papel quando o CSS roda dentro de um componente isolado, como um web component — o Tailwind cobre os dois casos na mesma regra para não duplicar o bloco. Para você, hoje, os dois nomes significam “a raiz”.

Um detalhe importante e fácil de perder: só entra nesse bloco o que o seu site usa ou declarou. A paleta inteira do Tailwind não vai para o arquivo. Num projeto com três cores, o @layer theme tem três cores. É por isso que o CSS gerado costuma ser pequeno, e é por isso que procurar uma variável que você nunca usou no arquivo gerado não dá em nada.

:root
O elemento raiz da página, o <html>. Variável declarada aqui vale para o documento inteiro, por herança.
:host
O equivalente a :root quando o CSS roda dentro de um web component. O Tailwind declara as duas coisas na mesma regra.
@layer theme
A camada do CSS final onde o Tailwind publica as variáveis do tema. É a “prateleira pública” do projeto.
@theme inline
A variante do @theme em que a classe gerada aponta para a variável de origem, em vez de apontar para o nome do tema. É o que faz a troca em tempo de execução pegar.
@property
A regra que dá tipo, valor inicial e regra de herança a uma variável. Sem ela, a variável não tem tipo nem valor de fábrica.

3. Duas prateleiras: @theme e :root

Todo mundo tropeça no mesmo lugar: declarar a variável no lugar errado. Há duas prateleiras, e elas servem a coisas diferentes.

A primeira é o @theme. Tudo que entra ali vira uma variável no CSS final e uma família de classes. --color-marca no @theme cria bg-marca, text-marca e border-marca. É a prateleira do desenho: o lugar onde você diz “esta cor existe neste projeto”.

A segunda é o :root comum, fora do @theme. Ali a variável só guarda um valor. Nenhuma classe nasce dela. Ela serve para o que não é do Tailwind: um valor que o seu próprio CSS usa, um número que o JavaScript vai ler, um dado que veio de outro sistema. Se você declarar --color-marca em :root e escrever bg-marca no HTML, nada acontece — a classe não existe, porque só o @theme fabrica classe.

Onde você declaraO que ganhaQuando é a escolha certa
@theme { --color-x: … }a variável no CSS final e as classes bg-x, text-x, border-xcor, fonte, sombra ou respiro que o desenho usa
:root { --x: … }só o valor, sem classevalor para o seu CSS ou para o JavaScript
@theme inline { --color-x: var(--y) }as classes apontando para --yquando a cor muda em tempo de execução
@property --x { … }tipo, valor inicial e herançavariável própria, que precisa se comportar como valor de verdade

Guarde a assimetria, porque ela explica quase todo “não funcionou” deste assunto: @theme faz as duas coisas (variável e classe), :root faz uma só (variável). Quando a classe existe e não pinta, o problema é o valor; quando a cor está declarada e a classe não faz nada, o problema é a prateleira.

4. O caso que engana: variável que aponta para variável

Agora o miolo da aula. A Ana quer a cor da loja numa variável só, porque a feira usa outra. Então ela faz o que parece natural: declara --cor-loja na raiz e manda o tema apontar para ela.

:root {
  --cor-loja: #b4532a;
}

@theme {
  --color-marca: var(--cor-loja);
}

Funciona: o site fica âmbar. Aí chega o dia da feira e ela escreve, no bloco da barraca, style="--cor-loja: #15803d". O texto fica verde, os títulos ficam verdes, e o botão continua marrom. Por quê?

Porque --color-marca foi resolvida na raiz. Variável que aponta para variável é resolvida no elemento onde ela foi declarada: a raiz perguntou “quanto é --cor-loja aqui?” e recebeu o marrom. O que desce pela árvore é o resultado, não a receita. Quando a barraca troca --cor-loja lá embaixo, já é tarde: ninguém mais está lendo esse nome.

A solução tem nome e é uma palavra: inline. Com @theme inline, o Tailwind escreve a classe apontando direto para a variável de origem — e aí a pergunta é feita no elemento que pinta, onde o verde já está valendo. Na caixa, o botão tem a cor da loja trocada no próprio elemento. Sua missão é fazer essa troca chegar ao fundo.

Acrescente inline depois de @theme e rode: o fundo do bloco deve passar de marrom para o verde declarado no style dele.

<style type="text/tailwindcss">
:root {
  --cor-loja: #b4532a;
}

@theme {
  --color-marca: var(--cor-loja);
}
</style>

<div id="alvo" class="bg-marca p-4 text-white" style="--cor-loja: #15803d">
  Barraca da Ana
</div>
padding: 16px
background-color: rgb(180, 83, 42)
color: rgb(255, 255, 255)

<style type="text/tailwindcss">
:root {
  --cor-loja: #b4532a;
}

@theme inline {
  --color-marca: var(--cor-loja);
}
</style>

<div id="alvo" class="bg-marca p-4 text-white" style="--cor-loja: #15803d">
  Barraca da Ana
</div>

Repare no que o painel mostra antes e depois. Antes, o fundo vem em rgb(180, 83, 42) — o marrom da raiz —, apesar do verde ali do lado. Depois, vem rgb(21, 128, 61), o verde da barraca. A diferença entre os dois casos é uma palavra no CSS, e o CSS gerado conta a história em duas linhas:

/* sem inline: a classe aponta para o nome do tema */
.bg-marca { background-color: var(--color-marca); }

/* com inline: a classe aponta para a variável de origem */
.bg-marca { background-color: var(--cor-loja); }

Isso responde também uma dúvida de quem vem de projetos antigos: por que a documentação insiste em inline nos casos de tema por variável. Não é preferência de estilo; é a diferença entre congelar o valor na raiz e mantê-lo vivo até o elemento que pinta. Use inline quando o valor precisar mudar por escopo — tema por seção, por cliente, por horário. Use o @theme comum quando o valor for uma constante do projeto, que só muda quando você edita o CSS.

5. Mexendo na régua: a variável --spacing

Cor é o exemplo mais vistoso, mas o mesmo mecanismo vale para as outras escalas do tema, e a régua de espaço é a mais útil de todas. Você já sabe que p-4 não vale “16 px”: vale quatro vezes a variável --spacing. Isso significa que dá para mudar a régua em um pedaço da página, sem tocar em nenhuma classe.

Na caixa abaixo, o bloco é uma faixa promocional. A Ana quer que, só ali dentro, o espaçamento seja mais generoso. Em vez de reescrever todas as classes de p-4 para p-8, ela declara --spacing: 0.5rem no elemento.

Declare --spacing: 0.5rem no atributo style do bloco e rode. O p-4 continua escrito igual, mas o respiro deve dobrar, de 16 px para 32 px.

<div id="alvo" class="bg-amber-50 p-4 text-amber-900">
  <p class="font-semibold">Promoção da feira</p>
  <p class="text-sm">Pão de queijo a R$ 5 até as 10h.</p>
</div>
padding: 16px
background-color: oklch(0.987 0.022 95.277)
color: oklch(0.414 0.112 45.904)

<div id="alvo" class="bg-amber-50 p-4 text-amber-900" style="--spacing: 0.5rem">
  <p class="font-semibold">Promoção da feira</p>
  <p class="text-sm">Pão de queijo a R$ 5 até as 10h.</p>
</div>

O painel sai de padding: 16px e chega em padding: 32px, e a classe não mudou de nome. É a prova mais limpa de que a classe é só um apelido: por baixo, ela é uma conta que consulta uma variável na hora de aplicar.

Esse poder pede uma advertência. Trocar --spacing na raiz muda o site inteiro de uma vez, e aí os tamanhos que você escolheu com cuidado — o respiro do cartão, o vão entre as colunas, a altura dos botões — perdem a referência que você tinha na cabeça. Um projeto que muda a régua global precisa rever todos os espaçamentos, e essa revisão é maior do que parece. A troca por bloco, como no exercício, é mais segura: fica óbvio no HTML de quem é aquele espaçamento, e o efeito não vaza para o resto.

6. @property: variável com tipo e valor de fábrica

Uma variável de CSS comum tem um comportamento que assusta: se ninguém declarou o nome, o var() não tem o que entregar e a propriedade é descartada em silêncio. O valor não vira zero, não vira preto, não vira nada — a declaração inteira some. Para o respiro, isso dá 0 px; para a cor, dá o valor herdado. O console fica limpo e o desenho fica torto.

O CSS moderno resolve isso com @property: você descreve a variável antes de usá-la, dizendo qual é o tipo, se ela herda e qual é o valor inicial. Com isso, o navegador sabe o que fazer quando o nome aparece vazio, e passa a aceitar a variável em animações e transições, porque agora ela é um valor de verdade e não um texto solto.

@property --respiro {
  syntax: "<length>";
  inherits: false;
  initial-value: 24px;
}

Três linhas e uma decisão cada. syntax é o tipo: <length> aceita comprimentos como 24px ou 1.5rem; um valor fora do tipo é recusado e o inicial entra no lugar. inherits: false diz que a variável não desce para os filhos — útil quando cada bloco deve ter o seu valor, sem pegar emprestado o do pai. E initial-value é o valor de fábrica: o que vale quando ninguém declarou nada.

Na caixa abaixo, a classe usa p-(--respiro), que vira padding: var(--respiro). O bloco @property já está lá, com valor inicial 0px, e é por isso que o cartão está sem respiro nenhum. Sua missão é dar um valor de fábrica de 24 px.

Ninguém declara --respiro em lugar nenhum. Mude o initial-value de 0px para 24px e rode: o cartão deve ganhar 24 px de respiro interno.

<style type="text/tailwindcss">
@property --respiro {
  syntax: "<length>";
  inherits: false;
  initial-value: 0px;
}
</style>

<div id="alvo" class="p-(--respiro) bg-amber-50 text-amber-900">
  Pão quentinho, R$ 7
</div>
background-color: oklch(0.987 0.022 95.277)
color: oklch(0.414 0.112 45.904)

<style type="text/tailwindcss">
@property --respiro {
  syntax: "<length>";
  inherits: false;
  initial-value: 24px;
}
</style>

<div id="alvo" class="p-(--respiro) bg-amber-50 text-amber-900">
  Pão quentinho, R$ 7
</div>

Duas notas que só aparecem quando se testa de verdade. A primeira: escreva o valor inicial em px, não em rem. O navegador exige que o valor inicial não dependa de contexto, e rem depende do tamanho de fonte da raiz; na prática, initial-value: 1.5rem é recusado e o valor de fábrica não entra. Se você precisa de um valor relativo, calcule em pixel ou declare a variável explicitamente no elemento. A segunda: com @property, o painel passa a mostrar o respiro; sem ela, o mesmo HTML fica com 0 px e o painel não tem o que mostrar.

7. Variável dentro da classe: os parênteses

Até aqui, a variável veio pelo tema. E quando ela não tem classe nenhuma? O Tailwind atende com os parênteses: p-(--respiro), bg-(--cor-do-dia), w-(--largura). A regra é geral: qualquer valor entre parênteses é um var() para o Tailwind. A forma longa, p-[var(--respiro)], também funciona e faz exatamente a mesma coisa — os parênteses são o atalho.

Existe um caso em que os parênteses sozinhos não bastam: quando a mesma classe aceita tipos diferentes. text-(--tamanho) tanto pode ser cor quanto tamanho de fonte, e o Tailwind não tem como adivinhar. A solução é dizer o tipo na frente, dentro dos parênteses, no formato text-(length:--tamanho). É a única situação em que você escreve essa palavra extra.

Você escreveO Tailwind geraQuando serve
bg-(--cor-loja)background-color: var(--cor-loja)cor que vem de fora do tema
p-(--respiro)padding: var(--respiro)respiro definido por bloco
w-(--largura)width: var(--largura)largura calculada em outro lugar
text-(length:--tamanho)font-size: var(--tamanho)tamanho de fonte, quando a classe é ambígua
bg-(--cor-loja, #b4532a)background-color: var(--cor-loja, #b4532a)com reserva, se o nome faltar

Repare na última linha: o valor de reserva continua funcionando aqui, e é a defesa mais barata contra o silêncio de uma variável que não chegou. Você escreve o reserva uma vez e nunca mais precisa conferir se aquele bloco recebeu o tema.

8. Variável e JavaScript: a mesma ponte

Variável de CSS não é um recurso só de estilo: é o único lugar onde o desenho e o código compartilham um valor sem combinar strings. Três operações resolvem quase tudo, e valem a pena ficar na memória.

Para ler o valor que está valendo em um elemento, use getComputedStyle e getPropertyValue. Para trocar, use setProperty — que é o que faz um botão de “trocar tema” funcionar. Para ler da raiz, pergunte ao document.documentElement:

const raiz = document.documentElement;
const cor = getComputedStyle(raiz).getPropertyValue("--color-marca").trim();
raiz.style.setProperty("--cor-loja", "#15803d");

A primeira linha guarda o <html>. A segunda pergunta ao navegador quanto vale --color-marca naquele momento — repare no .trim(), porque o valor volta com espaços sobrando. A terceira troca a variável, e tudo que aponta para ela se repinta no mesmo quadro, sem recarregar e sem recompilar.

Onde isso é útil de verdade? Quando o valor precisa sair do CSS: desenhar um gráfico de vendas num canvas, montar um SVG cujas barras têm a cor da marca, gerar um PDF no navegador, ou sincronizar a cor de um mapa. Em todos esses casos, o JavaScript precisa do valor em texto, e a variável é a fonte da verdade. A alternativa seria repetir o hexadecimal em dois lugares, e aí um dia os dois discordam.

9. Cenários do dia a dia

Cenário 1: a filial que queria verde e ficou marrom

A Ana declarou --cor-loja no bloco da filial, e metade da página mudou, metade não. As partes que mudaram usavam bg-(--cor-loja), que lê a variável no lugar do uso. As que não mudaram usavam bg-marca, que aponta para --color-marca resolvida na raiz. Duas soluções, escolha uma: trocar as classes para a forma com parênteses, ou declarar o par no @theme inline. A primeira deixa explícito de onde vem a cor; a segunda mantém os nomes bonitos. O que não dá é misturar as duas e esperar coerência.

Cenário 2: a variável que sumiu no caminho

Ela escreveu p-(--respiro) e o cartão ficou sem respiro. Nenhum erro no console. Havia três suspeitos: a variável nunca foi declarada (o var() sem reserva é descartado); o nome estava escrito diferente no CSS e no HTML (variável diferencia maiúsculas e hífen); ou a declaração estava num irmão, e não num ancestral — variável desce pela árvore, não atravessa. O teste rápido é escrever var(--respiro, red) no lugar: se o vermelho aparece, o nome não chegou.

Cenário 3: o tema que muda com o horário

Na feira, a Ana queria o site claro de manhã e escuro à noite, sem botão. Bastou uma linha de JavaScript trocando uma variável na raiz, e o resto do site acompanhou porque tudo apontava para ela. O trabalho de verdade não foi o JavaScript: foi garantir que nenhuma cor estivesse escrita em hexadecimal direto na classe, porque essa não acompanha nada. Variável é uma promessa que só vale se ninguém furar o caminho por fora.

Exercício: o verde da barraca

A cor da loja está em --cor-loja e o tema aponta para ela. Complete o bloco para que as classes do tema leiam o valor no elemento que pinta, e não na raiz:

@theme { --color-marca: var(--cor-loja); }

Dica: é uma palavra só, escrita entre @theme e a chave de abertura. Sem ela, o navegador resolve --cor-loja na raiz e o valor desce já decidido.

11. Resumo

O Tailwind publica o tema como variáveis de CSS de verdade: um bloco @layer theme com :root, :host, contendo só o que o projeto usa. As classes apontam para esses nomes, e é isso que permite trocar um valor em tempo de execução, sem recompilar e sem duplicar HTML. Declarar no @theme cria variável e classe; declarar em :root cria só a variável.

A pegadinha é a variável que aponta para variável: sem inline, o valor é resolvido na raiz e a troca feita num bloco mais abaixo não chega. Com @theme inline, a classe aponta para a variável de origem e a troca pega. Para o seu próprio CSS, o @property dá tipo, herança e um valor inicial que o navegador usa quando ninguém declarou nada — e o valor inicial, esse, precisa ser absoluto, em pixel.

Para lembrar

  • O CSS final tem um @layer theme com :root, :host e as variáveis usadas.
  • @theme cria variável e classes; :root só cria a variável.
  • Classe do Tailwind é apelido: por baixo ela chama var(--nome).
  • Variável que aponta para variável é resolvida onde foi declarada.
  • @theme inline faz a classe apontar para a variável de origem.
  • --spacing no elemento muda o respiro de todas as classes p- ali dentro.
  • p-(--x) é padding: var(--x); p-[var(--x)] é o mesmo.
  • text-(length:--x) desempata quando a classe aceita tipos diferentes.
  • @property dá tipo, herança e initial-value — sempre em pixel.
  • getPropertyValue lê e setProperty grava; nada precisa recompilar.
