Esconder e Mostrar

No celular, o telefone da padaria não cabe ao lado do nome e empurra tudo para fora da tela. No monitor, o botão “Ligar agora” não faz sentido nenhum. A Ana já sabe mudar tamanho e cor com o breakpoint certo, mas agora precisa de outra coisa: tirar um elemento do desenho numa tela e trazê-lo de volta na outra. É a dupla hidden e block, que parece simples e esconde (nunca melhor dito) três armadilhas: o elemento que desaparece mas continua no caminho, o que some para quem enxerga e continua para quem ouve, e o que você esconde sem deixar alternativa.

Você vai aprender
  • O que hidden faz de verdade, e por que ele precisa de um par para voltar.
  • Como aparecer só no desktop com hidden md:block.
  • Como desaparecer só no celular com md:hidden.
  • A diferença entre hidden, invisible, opacity-0 e sr-only.
  • Por que md:visible não existe para isso e o que usar no lugar.
  • Como esconder sem deixar quem usa leitor de tela (ou teclado) no prejuízo.

1. A cena: o telefone que não cabe e o botão que não serve

No monitor do balcão, o cabeçalho da padaria tem três coisas numa linha: o nome, o telefone e o horário. No celular, as três não cabem. A Ana tentou diminuir a letra, depois tentou quebrar a linha, depois pensou em tirar o telefone do site — e aí percebeu que a cliente no celular é justamente quem quer ligar. O telefone precisa estar lá, só não precisa estar no cabeçalho apertado.

A decisão ficou assim: no celular, o cabeçalho mostra só o nome e o horário; o telefone aparece no rodapé, em forma de botão. No monitor, o telefone volta para o cabeçalho e o botão “Ligar agora” desaparece, porque no computador quem liga usa o próprio telefone. Duas informações, dois lugares diferentes, e a mesma pergunta para o CSS: como dizer “este elemento existe, mas não aparece aqui”?

A resposta curta é hidden. A resposta completa é hidden combinado com uma classe que devolve o elemento ao desenho num breakpoint. E a resposta cuidadosa — a que separa quem sabe Tailwind de quem só decorou — é escolher, entre as quatro formas de esconder, a que combina com o motivo pelo qual você está escondendo. É o que esta aula faz, uma de cada vez.

2. hidden: tirar do desenho

A classe hidden aplica display: none. Não é “fique transparente”, nem “fique atrás”: o elemento sai do fluxo do documento, como se não existisse. O espaço que ele ocupava é recuperado pelos vizinhos, o navegador não o desenha, ele não recebe clique, não recebe foco pelo Tab e não é anunciado por leitores de tela. É o esconde mais radical que existe, e é o certo quando a informação realmente não deve existir naquele contexto.

O nome é uma palavra em inglês que já era usada no HTML: existe um atributo global hidden que faz a mesma coisa. No Tailwind, ele virou uma classe, o que permite combiná-lo com prefixos — e é aí que está a vantagem. O atributo não sabe de breakpoint; a classe sabe.

<p hidden>Telefone: (11) 4002-8922</p>
<p class="hidden">Telefone: (11) 4002-8922</p>

As duas linhas acima escondem o parágrafo, e as duas param de esconder se você apagar o que esconde. A diferença aparece na segunda: como é uma classe, ela aceita md:hidden, hover:hidden, group-hover:hidden. É o mesmo raciocínio de sempre — a classe é uma etiqueta que pode ganhar condição, o atributo não.

hidden
Classe que aplica display: none: tira o elemento do desenho, do clique e do leitor de tela.
display
A propriedade que decide como a caixa se comporta no fluxo: block, flex, grid, none.
invisible
Aplica visibility: hidden: ocupa espaço, mas não é desenhado nem clicável.
sr-only
Esconde visualmente, mas mantém o texto disponível para leitores de tela.
árvore de acessibilidade
A versão da página que o leitor de tela “vê”. Esconder no CSS pode remover o elemento dela.

Um detalhe que confunde: hidden não é “o contrário de mostrar”. O contrário de display: none é qualquer outro valor de display, e existem vários. Se o elemento escondido era um parágrafo, o valor natural é block; se era um link dentro de um texto, inline-block; se era um contêiner flex, flex; se era uma grade, grid. É por isso que a volta nunca é “desesconder”: é escolher um display.

3. Aparecer só no desktop: hidden md:block

Juntando o que você já sabe de breakpoint com o que acabou de ver: escreva hidden na base e devolva o elemento com md:block. A leitura é “escondido em qualquer largura; a partir de 768 px, bloco”. No celular, nada aparece e o espaço é liberado; no monitor, o parágrafo volta ao lugar de sempre.

Na caixa abaixo, o telefone está escondido e a missão é trazê-lo de volta a partir de 768 px. O painel observa o parágrafo do telefone e mostra display: none — a prova de que ele saiu do desenho. Depois de rodar a solução, o valor depende da janela: block se ela tiver 768 px ou mais, e none se estiver abaixo.

O telefone está escondido. Faça ele aparecer a partir de 768 px, mantendo-o escondido no celular: acrescente md:block ao parágrafo do telefone.

  <p id="alvo" class="hidden text-sm text-stone-600">(11) 4002-8922</p>
  <p class="text-sm text-stone-600">Aberto das 6h às 19h.</p>
</div>

  <p class="text-sm text-stone-600">Aberto das 6h às 19h.</p>

Repare que o md:block não é “o contrário de hidden”: ele é um valor de display, escolhido porque o elemento é um parágrafo. Se fosse um link dentro de uma frase, o par seria hidden md:inline; se fosse um contêiner de ícones, hidden md:flex. Escolher o display errado não esconde nada, mas deixa o layout torto: um md:block num item que devia ser flex perde o alinhamento interno, e o sintoma aparece longe do lugar onde você mexeu.

Outra coisa que vale saber: a ordem das classes no HTML não muda o resultado. hidden md:block e md:block hidden desenham igual, porque o CSS gerado coloca a base antes e o degrau depois. Isso já apareceu nas aulas de breakpoint e de mobile first, e continua valendo aqui — mas, por legibilidade, escreva sempre a base primeiro: quem lê o HTML entende “escondido, e depois bloco”.

4. O CSS que o Tailwind gera

O par hidden md:block vira duas regras, uma fora e uma dentro da media query:

.hidden {
  display: none;
}
@media (width >= 48rem) {
  .md\:block {
    display: block;
  }
}

Nada de especial acontece aqui: são dois valores da mesma propriedade, e o segundo está dentro de uma condição de largura. O que muda o jogo é a cascata — quando a janela passa de 768 px, as duas regras casam, e a de baixo vence. É o mesmo mecanismo da escada de respiro da aula de mobile first, aplicado a uma propriedade que liga e desliga o elemento inteiro.

Vale notar o que não existe: não há uma regra “desfazendo” o display: none. O md:block simplesmente escreve outro valor para a mesma propriedade, e o navegador usa o que venceu. Quem pensa em “esconder e depois mostrar” costuma procurar uma classe chamada show ou visible. Não existe show no Tailwind, e visible existe mas faz outra coisa (volta o visibility, não o display) — é a armadilha da próxima seção.

Essa confusão tem nome e sobrenome: md:visible não traz o elemento de volta. Se você escrever hidden md:visible, ele continua escondido em todas as larguras, porque visible mexe em visibility e quem está mandando no desenho é o display: none. O par certo é sempre um valor de display: block, inline, inline-block, flex, grid, inline-flex ou table.

5. Desaparecer só no celular: md:hidden

O contrário também é comum e é mais simples: o elemento aparece normalmente e você o esconde a partir de certo ponto. No caso da Ana, o botão “Ligar agora” serve no celular e atrapalha no monitor. A classe é md:hidden, sem nenhuma base especial — o estado natural do botão já é visível.

Na caixa abaixo, o botão está visível. A missão é escondê-lo a partir de 768 px. O painel de partida mostra o botão em estado normal: fundo âmbar, texto branco, cantos de 6 px, respiro e tamanho de fonte. Depois de rodar a solução, o valor de display passa a depender da janela — e no celular o botão continua aparecendo.

O botão “Ligar agora” só faz sentido no celular. Esconda-o a partir de 768 px: acrescente md:hidden ao botão.

  <button id="alvo" class="rounded-md bg-amber-600 px-3 py-2 text-sm text-white">Ligar agora</button>
</div>

  <button id="alvo" class="rounded-md bg-amber-600 px-3 py-2 text-sm text-white md:hidden">Ligar agora</button>
</div>

A escolha entre hidden md:block e md:hidden não é de gosto, é de leitura do código. Se o elemento deve existir na maioria dos casos e sumir em alguns, use md:hidden: a base fica limpa e o caso especial aparece explícito. Se ele deve sumir na maioria e aparecer em alguns, use hidden md:block. Em ambos, quem olha o HTML entende a intenção sem abrir o CSS — e isso é metade do valor do Tailwind.

Há um custo escondido no md:hidden: o elemento continua sendo baixado, renderizado e depois escondido. Para um botão, irrelevante. Para uma imagem grande ou um bloco de terceiros, é desperdício de dados de quem está no celular — que muitas vezes é justamente quem tem a conexão pior. Nesse caso, o caminho é outro: carregar a imagem certa para cada tela, com <picture> ou srcset. O CSS não resolve o que nem chegou a ser escolhido.

6. Quatro jeitos de esconder (e eles não são iguais)

Aqui está a parte que separa quem sabe de quem acha que sabe. hidden, invisible, opacity-0 e sr-only parecem a mesma coisa na tela, e são mundos diferentes embaixo. Cada um responde de um jeito a quatro perguntas: ocupa espaço? aparece? é clicável? o leitor de tela lê?

Comece pelo hidden, que é o mais usado e o mais honesto: o elemento não existe naquele contexto. Depois, o invisible, que é o esconde “segurando o lugar”: o texto fica reservado no layout, mas ninguém vê nem clica. Ele serve para truques de alinhamento — trocar um rótulo por outro sem que o botão mude de tamanho — e quase nunca para conteúdo.

O opacity-0 é o mais perigoso justamente por ser o mais bonito: o elemento fica transparente, mas continua ocupando espaço, recebendo cliques e sendo lido em voz alta. Um botão com opacity-0 é um botão invisível que funciona — o que pode ser ótimo (para animar a entrada com transition) ou um desastre (para um botão que devia estar fora do caminho). Na aula de group-hover, o botão escondido usava exatamente isso, e a ressalva era a mesma: quem navega por teclado encontra o botão antes de vê-lo.

E o sr-only é o esconde do bem: ele reduz o elemento a um quadradinho de 1 px, recortado e fora da tela, mas deixa o texto disponível para leitores de tela. É a ferramenta certa para rótulos que só fazem sentido fora do visual — o “Buscar” de um campo com ícone de lupa, o “Abrir menu” de um botão com três traços. Quem enxerga não precisa ler; quem ouve, precisa.

7. sr-only: esconder para quem vê, mostrar para quem ouve

O campo de busca da padaria tem um ícone de lupa e nenhum texto visível — no espaço de um botão não cabe “buscar”. Só que um leitor de tela anunciaria apenas “campo de edição”, sem dizer para quê. A solução é um <label> de verdade, escondido visualmente com sr-only: ele não aparece na tela, mas continua ligado ao campo pelo atributo for.

Na caixa abaixo, o rótulo está visível e empurra o campo para a direita. A missão é aplicar sr-only ao <label>. Depois de rodar a solução, o painel mostra o resultado em detalhe: posição absoluta, 1 px de largura, 1 px de altura, margem de −1 px, recorte e texto sem quebra de linha. É assim que se esconde sem esconder de verdade.

Deixe o rótulo “Buscar pão” só para leitores de tela, sem sumir da árvore de acessibilidade: acrescente sr-only ao <label>.

<div class="rounded-xl bg-amber-50 p-4">

  <input id="busca" type="search" placeholder="Pão francês, broa…" class="mt-1 w-full rounded-md border border-amber-300 bg-white p-2">
</div>
color: oklch(0.374 0.01 67.558)
font-size: 14px
font-weight: 500

<div class="rounded-xl bg-amber-50 p-4">
  <label id="alvo" for="busca" class="sr-only">Buscar pão</label>
  <input id="busca" type="search" placeholder="Pão francês, broa…" class="mt-1 w-full rounded-md border border-amber-300 bg-white p-2">
</div>

O CSS gerado deixa claro que não há mágica: são nove declarações que, juntas, tiram o elemento da tela sem tirá-lo do documento.

.sr-only {
  position: absolute;
  width: 1px;
  height: 1px;
  padding: 0;
  margin: -1px;
  overflow: hidden;
  clip-path: inset(50%);
  white-space: nowrap;
  border-width: 0;
}

Repare que a solução removeu as classes de texto do rótulo. Não é obrigatório, mas é recomendado: tamanho de fonte e cor não têm efeito visível num elemento recortado, e manter as classes dá a impressão de que algo ali ainda é desenhado. O sr-only já cuida de tudo. Se depois você precisar trazer o rótulo de volta em telas grandes, existe o par sr-only lg:not-sr-only — útil em tabelas e em formulários longos.

8. Esconder com cuidado

A primeira regra é simples e cobre metade dos problemas: o que você esconde no celular desaparece para quem está no celular. O preço, o telefone, o endereço e o botão de comprar não podem viver só no desktop. Se a informação é importante, ela muda de lugar, não de existência — como o telefone da Ana, que saiu do cabeçalho e apareceu no rodapé em forma de botão.

A segunda regra é sobre o teclado. hidden remove o elemento do foco, o que é correto. Mas opacity-0 e invisible fora de fluxo deixam armadilhas: o usuário aperta Tab, o foco some da tela, e ele não entende para onde foi. Se você usa esses dois para animar, garanta que o elemento também seja escondido do foco quando não deve ser usado — ou aceite que ele seja focável e torne-o visível no foco, com focus:opacity-100.

A terceira regra é sobre animação. Por padrão, display não faz transição suave: quando o valor muda de none para block, o elemento aparece de uma vez. Se você quer um fade, combine opacity-0 com invisible e anime a opacidade; se quer só aparecer e desaparecer sem frescura, hidden é mais simples e mais leve. Escolher a ferramenta certa evita gambiarras de transition com display que nunca funcionam.

Uma nota sobre busca: conteúdo com display: none costuma não ser indexado do mesmo jeito que o conteúdo visível. Isso não é punição — é a consequência lógica de esconder. Só vira problema quando você esconde informação importante para o visitante de celular: além de prejudicar a pessoa, você reduz o que o buscador tem para mostrar. De novo: esconda o que não deve existir naquele contexto, não o que você não quis organizar.

9. Cenários do dia a dia

Cenário 1: o menu com dois desenhos

O menu da padaria tem seis links no desktop e um botão de três traços no celular. São dois elementos no HTML, cada um com a sua condição: os links com hidden md:flex e o botão com md:hidden. No celular, os links somem e o botão aparece; no desktop, o contrário. O detalhe que ela quase esqueceu: o botão precisa de um aria-label dizendo o que faz, senão o leitor de tela anuncia só “botão”. Visibilidade resolvida no CSS, significado resolvido no HTML.

Cenário 2: o aviso que só valia no celular

Na tabela de preços, ela pôs um aviso “arraste para o lado para ver tudo” acima da tabela. No desktop, o aviso era ruído, porque a tabela cabia inteira. A solução foi md:hidden no aviso — e não hidden md:block na tabela, que era o conteúdo principal. A lição: esconda o acessório, nunca o conteúdo. Se você se pegar escondendo dados no celular, provavelmente o problema é o desenho, não o dado.

Cenário 3: o formulário que ficou impossível no teclado

Num formulário de encomenda, ela animou os campos com opacity-0 e transition para aparecerem um a um. No teclado, o foco entrava em campos invisíveis e a pessoa “sumia” da tela a cada Tab. A correção foi voltar ao hidden para os campos que não deviam existir naquele passo, e reservar a opacidade para o enfeite do botão. Menos bonito na animação, muito melhor de usar.

Exercício: o horário no cabeçalho

O horário de funcionamento deve aparecer só no desktop, a partir de 768 px. O parágrafo já começa escondido. Complete com a classe que o traz de volta:

<p class="hidden text-sm">Aberto das 6h às 19h</p>

Dica: é o prefixo do ponto de 768 px mais um valor de display. Se você escrever md:visible, o parágrafo continua escondido — visible mexe em visibilidade, não em display.

11. Resumo

hidden aplica display: none: o elemento sai do desenho, do clique, do foco e do leitor de tela, e o espaço é liberado. Para voltar, você não “desesconde”: dá outro valor de display num breakpoint — hidden md:block para aparecer no desktop, md:hidden para sumir nele. O CSS gerado são duas regras com display diferentes, e a cascata decide qual vale em cada largura.

Nem todo esconder é igual: invisible guarda o espaço, opacity-0 deixa clicável e audível, e sr-only esconde só de quem enxerga. Escolher a ferramenta certa é o que separa um layout bonito de uma página que funciona para todas as pessoas — e esconder conteúdo essencial no celular nunca é uma boa troca.

Para lembrar

  • hidden = display: none: some do layout, do clique, do foco e do leitor de tela.
  • Para voltar, use um valor de display: md:block, md:flex, md:inline.
  • md:visible não traz nada de volta: visible mexe em visibility.
  • hidden md:block = só no desktop; md:hidden = só no celular.
  • A ordem das classes no HTML não muda o resultado: a base vem antes no CSS.
  • invisible ocupa espaço; hidden não.
  • opacity-0 continua clicável, focável e audível.
  • sr-only esconde visualmente e mantém o texto para leitores de tela.
  • display não faz transição por padrão: para suavizar, anime opacity.
  • Esconda o acessório, não o conteúdo: esconder dado no celular é dívida, não solução.
