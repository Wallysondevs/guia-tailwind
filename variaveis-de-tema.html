Variáveis de Tema

A Ana decidiu trocar o âmbar do site da padaria por um marrom mais sério, de farinha integral. Abriu o arquivo, contou quarenta e dois lugares com amber escrito e desistiu. Quarenta e dois lugares é muita coisa para mudar de novo no mês que vem. Nesta aula ela descobre que as cores do Tailwind não estão escritas nas classes: elas moram em variáveis, e uma variável é um valor com nome — um nome que você muda em um lugar só e todos os lugares acompanham. É a peça que sustenta o tema claro, o escuro e qualquer cor da marca.

Você vai aprender
  • O que é uma variável no CSS e por que ela começou com dois hífens.
  • Como ler o CSS gerado e ver que bg-amber-100 é só um atalho para uma variável.
  • O que o @theme guarda e por que ele fica num arquivo CSS, não no HTML.
  • A convenção --color-*: é ela que transforma um nome em classe.
  • As outras famílias do tema: --spacing, --radius-*, --text-*.
  • Como usar uma variável sua dentro de uma classe: bg-(--minha-cor).
  • O que acontece quando a variável não existe e para que serve o valor de reserva.

1. A cena: a cor que aparece em quarenta lugares

A Ana vende pão de queijo, bolo de fubá e café coado. O site tem três páginas: a vitrine, a página dos horários e uma de encomendas. Ela escolheu o âmbar do Tailwind porque achou bonito e porque combinava com o trigo. Funcionou por seis meses. Agora ela quer um marrom mais escuro, e aí vem o problema: cada cartão, cada selo e cada botão está pintado separado, com a classe escrita por inteiro.

<div class="bg-amber-100 text-amber-900">Pão quentinho</div>
<span class="bg-amber-200 text-amber-900">Novo</span>
<button class="bg-amber-700 text-white">Encomendar</button>

Três lugares, três tons diferentes da mesma família, e nenhum deles sabe que faz parte de uma decisão só. Se a Ana quiser o marrom, ela precisa mexer em quarenta e dois lugares e acertar os tons na mão, um por um. É o tipo de tarefa em que a gente erra na linha 38 e só descobre duas semanas depois, quando alguém manda mensagem perguntando por que aquele botão está amarelo claro.

A saída não é o Tailwind ter um botão mágico de "trocar tudo". É mais bonito que isso: por baixo das classes existe uma camada de valores com nome, e as classes só apontam para ela. Quem mexe nessa camada troca a cor do site inteiro de uma vez. Essa camada tem nome — variáveis de tema — e é o assunto desta aula. Depois dela, a Ana não vai mais copiar uma cor; vai apontar para um nome.

2. O que é uma variável (e por que ela começa com dois hífens)

Variável é a ideia mais simples do mundo: um nome onde você guarda um valor. No CSS isso existe desde 2015 e se chama propriedade personalizada, na documentação oficial. Na prática todo mundo chama de variável. O jeito de declarar é este: dois hífens, o nome, dois-pontos e o valor.

:root {
  --color-trigo: #b45309;
}

Aquela primeira linha, :root, quer dizer "a raiz do documento", que na prática é a página inteira: tudo que estiver abaixo herda o que foi declarado ali. E depois, quando quiser usar o valor, você chama pelo nome dentro de var() — var(--color-trigo). O var() é o carteiro: vai até o nome, pega o conteúdo e entrega no lugar do pedido.

.selo {
  background-color: var(--color-trigo);
}

Por que os dois hífens? Porque o CSS já tinha um monte de propriedades com nome curto (color, font, gap) e precisava de um espaço onde ninguém mais fosse mexer. Dois hífens no começo é o sinal de "este nome é seu, invente o que quiser". E como o nome é livre, o Tailwind pôde batizar as cores dele sem risco de conflito: --color-amber-100 é a declaração de variável, e uma coisa completamente diferente de color.

variável (propriedade personalizada)
Um valor guardado com um nome, declarado com dois hífens: --color-trigo: #b45309;. Ela não pinta nada sozinha; só guarda.
var()
A função que busca o valor de uma variável e o entrega no lugar onde foi chamada: background-color: var(--color-trigo).
@theme
O bloco do arquivo CSS onde o Tailwind lê as variáveis do tema e, de quebra, gera uma classe para cada uma delas.
declaração
Uma linha de CSS no formato propriedade: valor;. Declarar a variável é escrever a linha; usar a variável é chamar o var().
escopo
Onde a variável vale. Declarada em :root, vale na página toda; declarada num elemento, vale nele e nos filhos dele.
valor de reserva
O segundo pedaço do var(), depois da vírgula: var(--cor-x, #000). É o que o navegador usa se o nome não existir.

Guarde a distinção que confunde todo mundo no começo: declarar a variável não muda nada na tela. Ela é só uma anotação. Enquanto ninguém chamar var(--color-trigo) em alguma propriedade, o marrom está guardado e invisível. Se você já viu uma variável "não funcionando", provavelmente faltou chamá-la — ou o nome estava escrito diferente no lugar do uso.

3. O CSS que o Tailwind gera já fala em variáveis

Agora o pulo do gato. Toda aula deste guia mostrou o CSS gerado com valores em var(), e talvez você tenha passado os olhos sem reparar. Repare agora:

.bg-amber-100 {
  background-color: var(--color-amber-100);
}
.text-amber-900 {
  color: var(--color-amber-900);
}

Não há hexadecimal ali. Não há oklch. O Tailwind não escreveu a cor: escreveu o nome da variável onde a cor mora. Isso quer dizer que a cor de todos os fundos âmbar do seu site é decidida no lugar onde --color-amber-100 foi declarada — uma linha, num arquivo, longe do HTML. É exatamente o que a Ana queria e não sabia pedir.

O cartão já tem texto âmbar escuro e respiro. Falta o fundo: acrescente bg-amber-100 e rode. Depois olhe o painel de CSS gerado embaixo e repare no que o Tailwind escreveu no lugar da cor.

<div id="alvo" class="p-4 text-amber-900">Pão quentinho</div>
.p-4 {
  padding: calc(var(--spacing) * 4);
}
.text-amber-900 {
  color: var(--color-amber-900);
}

<div id="alvo" class="p-4 text-amber-900 bg-amber-100">Pão quentinho</div>

O painel mostrou a regra inteira: .bg-amber-100 { background-color: var(--color-amber-100); }. Cinco palavras e um nome de variável. Se amanhã a Ana achar esse âmbar claro demais, ela muda o valor de --color-amber-100 — e esse é o único lugar do projeto em que ele existe. Todos os cartões, selos e caixas que pedem bg-amber-100 acompanham, porque todos pedem a mesma coisa.

Isso também explica um comportamento que parece mágica. Se você declarar a variável dentro de um elemento, só o que está abaixo dele muda. A vara de condão funciona por herança: cada pedaço da página pergunta "quanto é --color-amber-100 aqui?" e obedece ao valor mais próximo encontrado. É assim que existem tema claro e tema escuro na mesma folha de estilos, sem duplicar nada — mas essa história fica para a aula de tema por classe.

4. De onde vêm esses nomes: o @theme

Se as variáveis moram em algum lugar, onde exatamente? No Tailwind v4 elas moram num bloco chamado @theme, dentro do seu arquivo CSS de entrada. É um bloco curto e a coisa mais parecida com uma "configuração" no v4:

@import "tailwindcss";

@theme {
  --color-trigo: #b45309;
  --radius-caixa: 0.75rem;
}

Duas linhas declaradas, duas coisas criadas. A primeira dá ao Tailwind uma cor chamada trigo, que passa a existir em classes como bg-trigo, text-trigo e border-trigo. A segunda cria um arredondamento chamado caixa, que vira rounded-caixa. O @theme é ao mesmo tempo o lugar onde você guarda os valores e a lista de nomes que o Tailwind aceita escrever nas classes. Um lugar só, duas funções.

Repare também no que não mudou: o --color-trigo continua sendo uma variável de CSS comum, com dois hífens e tudo. A diferença é que o Tailwind leu o bloco e, para cada --color-* que encontrou, montou as classes de cor correspondentes. Você não escreve essas classes à mão em lugar nenhum; elas nascem do nome. É por isso que errar o nome no @theme e usar outro no HTML é o tropeço mais comum deste assunto: o nome é a única ponte entre os dois lados.

E onde fica esse arquivo? No seu projeto, quando você instala o Tailwind com npm, é o arquivo CSS que você manda compilar — no nível 3 do guia isso ganha uma aula inteira. Nas caixas desta aula o compilador monta esse arquivo para você, e é por isso que as caixas trabalham com as variáveis que já existem (a paleta padrão) ou com variáveis declaradas no próprio HTML, no atributo style. A mecânica é a mesma; só muda o endereço da declaração.

5. A convenção --color-* é o que cria as classes

Aqui está o detalhe mais útil da aula: o Tailwind não adivinha o que a variável significa. Ele lê o começo do nome. --color-* gera classes de cor. --radius-* gera arredondamentos. --text-* gera tamanhos de texto. O prefixo é a etiqueta da gaveta, e cada gaveta produz um tipo de classe.

Variável no @themeClasse que nasceO que ela pinta
--color-trigobg-trigo, text-trigo, border-trigocor de fundo, de letra e de borda
--radius-caixarounded-caixaarredondamento dos cantos
--text-titulotext-titulotamanho de fonte
--font-marcafont-marcafamília de fonte
--spacingp-4, m-2, gap-6a régua de espaço que todo mundo usa

As famílias da paleta padrão seguem a mesma convenção, e é por isso que bg-amber-100 tem exatamente esse nome: existe uma variável --color-amber-100 na gaveta. A escala inteira está lá, de --color-amber-50 a --color-amber-950, com todos os números no meio. Você nunca precisa decorar a lista: escreve a classe, roda, e o CSS gerado mostra o nome da variável que ele foi buscar.

Cuidado com uma pegadinha: variável declarada em :root não gera classe nenhuma. Ela é só um valor guardado, para você usar dentro de um var() no seu próprio CSS. Quem fabrica classe é o @theme. A Ana passou uma tarde nessa confusão: declarou --color-trigo em :root, escreveu bg-trigo no HTML e nada aconteceu. A variável existia, o valor existia, mas a classe não — porque ninguém tinha pedido ao Tailwind para olhar aquele nome.

6. A variável --spacing e as outras escalas do tema

Cor é só a família mais famosa. A régua de espaço também é uma variável, e é uma das mais elegantes: p-4 não vale "16 px", vale "quatro vezes a variável --spacing". O CSS gerado escreve a conta na sua frente:

.p-4 {
  padding: calc(var(--spacing) * 4);
}
.max-w-md {
  max-width: var(--container-md);
}
.rounded-xl {
  border-radius: var(--radius-xl);
}

Isso significa que a escala não é uma tabela de números colados: é uma multiplicação por um valor que mora no tema. Mude --spacing e todo espaçamento do site cresce ou encolhe na mesma proporção — os 4 px do p-1, os 16 px do p-4, os 24 px do p-6. É útil para uma marca com respiro mais generoso e é ótimo para entender o desenho do sistema. Só não faça isso por esporte: metade do guia supõe a régua padrão, e a sua página vai ficar diferente dos exemplos sem que ninguém entenda por quê.

As outras famílias funcionam igual. --radius-xl guarda o arredondamento de rounded-xl; --text-lg guarda o tamanho de text-lg, com a altura de linha derivada (--text-lg--line-height, outro nome que você pode sobrescrever se quiser); --container-md guarda o teto de largura de max-w-md. Sempre o mesmo desenho: um nome no tema, uma classe no HTML, um var() no meio.

Dê ao cartão cantos de 12 px e texto maior: acrescente rounded-xl e text-lg. No painel de CSS gerado, veja que nenhuma das duas classes traz o número — as duas chamam variáveis do tema.

<div id="alvo" class="bg-amber-100 p-4">Pão quentinho</div>
.bg-amber-100 {
  background-color: var(--color-amber-100);
}
.p-4 {
  padding: calc(var(--spacing) * 4);
}

<div id="alvo" class="bg-amber-100 p-4 rounded-xl text-lg">Pão quentinho</div>

Reparou que o text-lg gerou duas linhas, font-size e line-height? A altura de linha também sai de uma variável do tema (--text-lg--line-height), porque tamanho e entrelinha são uma decisão só. O Tailwind não deixa você escolher um tamanho enorme com a entrelinha antiga por acidente — ele já entrega o par pronto. E, se quiser mudar, é ali no tema, com o nome certo.

7. Usar uma variável que ainda não tem classe

E quando você quer usar uma variável que não tem classe? Acontece quando a cor vem de outro lugar: do CSS de um sistema antigo, de uma marca que só existe naquele arquivo, de um valor que muda com JavaScript. O Tailwind atende com os parênteses: bg-(--cor-do-dia) quer dizer "pinte o fundo com o que estiver em --cor-do-dia". É a forma curta de bg-[var(--cor-do-dia)], que também funciona e faz a mesma coisa.

O marrom do trigo está declarado no atributo style do cartão, mas nenhuma classe o usa. Aponte o fundo para essa variável com bg-(--color-trigo).

<div id="alvo" class="p-4 text-stone-900" style="--color-trigo: #b45309">Pão do dia</div>
.p-4 {
  padding: calc(var(--spacing) * 4);
}
.text-stone-900 {
  color: var(--color-stone-900);
}

<div id="alvo" class="p-4 text-stone-900 bg-(--color-trigo)" style="--color-trigo: #b45309">Pão do dia</div>

Duas coisas para levar desse exercício. A primeira: a cor não está no HTML, está na variável, e a classe só aponta. Se você trocar o #b45309 por outro valor no style, o fundo muda na hora, sem tocar em classe nenhuma. A segunda: o mesmo nome que você inventa no @theme pode ser usado direto com parênteses. No projeto de verdade, bg-(--color-trigo) e bg-trigo chegam no mesmo lugar — a diferença é que a segunda forma exige a declaração no @theme.

Você escreveO Tailwind geraQuando usar
bg-amber-100background-color: var(--color-amber-100)cor da paleta, sem pensar
bg-trigobackground-color: var(--color-trigo)cor declarada no @theme
bg-(--minha-cor)background-color: var(--minha-cor)variável que veio de fora do tema
bg-[var(--minha-cor)]igual ao de cimamesma coisa, escrito por extenso
bg-[#b45309]background-color: #b45309quando o valor é único e acabou ali

A última linha é a tentação do iniciante e merece uma palavra. O valor entre colchetes funciona e é honesto: o Tailwind escreve o hexadecimal na regra, sem variável no meio. O preço é que aquele valor não tem nome, então ninguém consegue trocá-lo depois de um lugar só, e ele não acompanha o tema escuro sem trabalho extra. Use colchete para o caso avulso, e variável para o que se repete.

8. Quando a variável não existe

Existe um jeito de falhar que não dá erro nenhum e por isso assusta: chamar uma variável que não existe. O navegador não reclama, o console fica limpo e a propriedade simplesmente não é aplicada — como se você não tivesse escrito nada. É o mesmo silêncio das classes digitadas errado, que já apareceu na primeira aula.

A defesa é o valor de reserva, o segundo pedaço do var():

.selo {
  background-color: var(--color-selo, var(--color-amber-100));
}
.selo-forte {
  color: var(--color-tinta, #1c1917);
}

Lendo em voz alta: "pinte com --color-selo; se esse nome não estiver declarado em lugar nenhum acima, use --color-amber-100". O reserva pode ser outra variável ou um valor cru, e pode até ter vírgulas dentro — o navegador usa tudo o que vier depois da primeira vírgula. Isso deixa o componente seguro para viver em páginas onde o tema ainda não chegou, e é o truque que bibliotecas usam para não depender de uma configuração específica.

Tem um detalhe de escopo que vale conhecer desde já, porque ele explica metade dos mistérios do tema escuro. A variável é resolvida no elemento onde a propriedade é aplicada, olhando para cima na árvore. Se o seu bg-(--color-fundo) está num cartão, o valor que vale é o que estiver declarado no cartão, senão no pai dele, senão na raiz. Então a mesma classe pode pintar branco numa seção e preto em outra — sem que a classe mude. Guarde essa ideia: ela é o motor do tema claro/escuro das próximas aulas.

9. Cenários do dia a dia

Cenário 1: a cor da marca muda a cada estação

A Ana troca a cor de destaque do site duas vezes por ano — terracota no inverno, verde no verão. Com a cor escrita em cada classe, cada troca é uma tarde de trabalho e três erros. Com uma variável no @theme (--color-marca) e as classes apontando para ela (bg-marca, text-marca, border-marca), a troca é uma linha. O ganho não é digitar menos: é não precisar procurar. O nome do papel virou o lugar da decisão, e a decisão passou a existir num único endereço.

Cenário 2: a variável existe, mas o valor não chega

Ela declarou --color-destaque dentro de um <div> e usou a cor num botão que estava acima dele, fora da árvore. Não funcionou, e com razão: variável vale para o elemento e para os filhos dele, nunca para os tios. A correção é declarar mais alto — na raiz, num container que envolva os dois — ou repetir a declaração onde for preciso. Vale a mesma regra do tema: quem manda é o ancestral mais próximo que declarou o nome.

Cenário 3: dois nomes para a mesma cor

Depois de um tempo o projeto dela tinha --color-trigo, --color-marca e --color-destaque com o mesmo hexadecimal, usados em lugares diferentes. Trocar a cor virou uma caça ao tesouro: mudar um dos três deixava o site bicolor. A faxina é escolher um nome por papel e apagar os outros, ou — melhor ainda — declarar um como apelido do outro: --color-destaque: var(--color-trigo). Uma decisão, um nome de verdade, apelidos apontando para ele.

11. Resumo

Uma variável de CSS é um valor com nome, declarado com dois hífens e chamado com var(). O Tailwind v4 monta o tema inteiro assim: cada cor da paleta é uma variável, cada degrau de espaço é --spacing multiplicado, cada arredondamento é uma variável. As classes não carregam valores; elas apontam para nomes. Por isso trocar o valor de uma variável muda todos os lugares de uma vez — o que a Ana precisava e não sabia como pedir.

Quem declara é o bloco @theme, no seu arquivo CSS, e é o prefixo do nome que decide a classe que nasce: --color-* para cor, --radius-* para canto, --text-* para tamanho de letra. Declarar em :root guarda o valor mas não gera classe nenhuma. Para usar uma variável de fora do tema, os parênteses resolvem: bg-(--minha-cor). E para dormir tranquila, o valor de reserva do var() cobre o nome que não existe, que é o erro que o navegador nunca denuncia.

Para lembrar

  • Variável = valor com nome. Declara com --nome: valor;, usa com var(--nome).
  • O CSS gerado de uma classe de cor é background-color: var(--color-…): nenhum hexadecimal.
  • @theme guarda as variáveis do tema e cria as classes correspondentes.
  • O prefixo manda: --color-* cor, --radius-* canto, --text-* fonte.
  • --spacing é a régua: p-4 é calc(var(--spacing) * 4).
  • :root só guarda valor; classe nova exige @theme.
  • bg-(--minha-cor) é a forma curta de bg-[var(--minha-cor)].
  • bg-[#b45309] funciona, mas o valor fica sem nome e ninguém o troca depois.
  • Variável vale no elemento e nos filhos; quem manda é o ancestral mais próximo.
  • var(--x, reserva) evita o silêncio de uma variável que não existe.
