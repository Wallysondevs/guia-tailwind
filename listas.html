Listas de Itens

A Ana agora tem uma tela de bastidor: as encomendas do dia, uma embaixo da outra, com nome do cliente, o pão pedido e o horário de retirada. Ela escreveu tudo numa ul e o resultado foi um paredão de texto — cinco linhas grudadas, sem espaço, sem hierarquia, e o horário misturado com o nome. Nesta aula ela transforma essa lista numa peça de interface: cada li vira uma linha organizada, com o nome à esquerda, o horário à direita, um respiro entre os itens e um corte elegante quando o nome do pão é comprido demais.

Você vai aprender
  • Quando usar ul, ol e li, e por que não div.
  • Por que a lista nasce sem marcador no Tailwind.
  • O espaço entre os itens com flex flex-col gap-3.
  • O item como linha: flex items-center justify-between.
  • Nome, descrição e preço, cada um com seu tamanho e sua cor.
  • O quadradinho do ícone, que não pode amassar.
  • Separar itens com divide-y e dar resposta ao mouse.
  • Nome comprido: truncate e o min-w-0 que faz ele funcionar.

1. A cena: o paredão de encomendas

O HTML que a Ana escreveu era este, repetido cinco vezes:

<ul>
  <li>Marina · pão de queijo · 7h</li>
  <li>João · francês · 8h</li>
</ul>

Funciona, no sentido de que a informação está lá. Mas o olho não encontra nada: os itens se encostam, todos os dados têm o mesmo peso, e o horário — que é a informação mais urgente de todas, porque define a ordem de produção — fica escondido no meio da frase. A Ana tentou separar com vírgulas, depois com traços, depois com maiúsculas. Nenhuma dessas soluções resolve, porque o problema não é de pontuação: é de estrutura.

A lista precisa de três decisões visuais que a Ana ainda não tomou. A primeira é o espaço entre um item e outro. A segunda é o que fica à esquerda e o que fica à direita em cada item. A terceira é o que acontece quando um texto é maior que o espaço — e ele vai ser, porque sempre existe um pão com nome comprido.

2. ul, ol e li: a lista que o navegador entende

Antes das classes, vale escolher a tag certa. Existem três listas no HTML e cada uma diz uma coisa diferente para o navegador e para o leitor de tela:

ul
Lista sem ordem. A sequência não significa nada: o cardápio de hoje, os ingredientes, as encomendas. Os leitores de tela anunciam quantos itens existem.
ol
Lista ordenada. A sequência importa: passos de uma receita, ordem de produção. Por padrão vem numerada.
li
Um item da lista. Só existe dentro de ul ou ol, e é o elemento que você vai estilizar como linha.
dl
Lista de pares nome e valor, feita de dt e dd. Serve para ficha técnica: "Peso: 60 g", "Validade: 2 dias".
marcador
A bolinha ou o número que o navegador desenha ao lado do item. O Tailwind tira esse marcador por padrão, e existe uma aula só para devolvê-lo quando faz sentido.

Se você fizer a lista com div, o desenho fica igual e a informação se perde: o leitor de tela não anuncia "lista com 5 itens", o navegador não oferece atalho de navegação entre itens, e o buscador não entende que aquilo é uma lista de produtos. Use div para layout; use li para item. É uma escolha de uma palavra no HTML que muda o significado inteiro.

Uma surpresa para quem vem do HTML puro: no Tailwind, a lista nasce sem marcador. O CSS de base do Tailwind aplica list-style: none em ul e ol, porque na maioria dos sites a lista é usada como componente — menu, cardápio, passos — e a bolinha atrapalha. Para uma lista de ingredientes com bolinha, você devolve o marcador com list-disc; esse é o assunto de outra aula, e por aqui seguimos sem marcador mesmo.

3. O espaço entre os itens

Sem espaço, cinco itens parecem um parágrafo de cinco linhas. O primeiro ajuste é afastar um item do outro, e existem duas formas de fazer isso: margin em cada item ou espaço no pai. A segunda é melhor, porque a regra fica num lugar só — e há duas classes de pai que resolvem: space-y-3, que você já viu, e flex flex-col gap-3, que é a que vamos usar aqui.

A lista está com p-2, que só afasta os itens da borda e não cria espaço entre eles. Transforme-a numa coluna com 12 px de espaço entre os itens: flex flex-col gap-3 no ul.

<ul id="alvo" class="p-2">
  <li>Marina · pão de queijo · 7h</li>
  <li>João · francês · 8h</li>
  <li>Rita · broa · 9h</li>
</ul>
padding: 8px

<ul id="alvo" class="flex flex-col gap-3">
  <li>Marina · pão de queijo · 7h</li>
  <li>João · francês · 8h</li>
  <li>Rita · broa · 9h</li>
</ul>

Antes de rodar, o painel mostra uma linha só: padding: 8px. Esse é o resultado da primeira tentativa da Ana — ela deu respiro à lista inteira, e os itens continuaram colados uns nos outros. Depois da solução, o painel mostra três linhas: display: flex, gap: 12px e flex-direction: column. Leia na ordem inversa para entender: a lista virou uma coluna porque a direção do flex é column; os filhos ficam um embaixo do outro; e o gap coloca 12 px entre eles, sem margem em ninguém.

.flex {
  display: flex;
}
.flex-col {
  flex-direction: column;
}
.gap-3 {
  gap: calc(var(--spacing) * 3);
}

Por que gap e não margem? Porque margem não sabe onde o vizinho está: você põe mb-3 em todos e o último item ganha uma margem que sobra embaixo, empurrando o que vem depois. O gap só existe entre os itens, nunca antes do primeiro nem depois do último. É a diferença entre "espaço entre" e "espaço embaixo".

Com flex-col, a lista deixa de ser uma lista para o motor de layout e passa a ser uma coluna — mas continua sendo uma ul para o leitor de tela. Isso é uma das coisas boas do Tailwind: as classes mudam o desenho, não a semântica.

4. O item como linha

Agora cada item precisa de organização interna. Na cabeça da Ana, cada linha tem três informações: o nome do cliente, o que ele pediu e o horário. O horário é a informação que ela olha primeiro, então precisa estar alinhado à direita, sempre no mesmo lugar, para o olho descer a coluna sem esforço.

O jeito de conseguir isso é o flex no próprio li, com justify-between empurrando o primeiro bloco para a esquerda e o último para a direita. items-center alinha os dois pelo meio vertical, o que importa quando um bloco tem duas linhas de texto e o outro só uma.

Dentro de cada item, o nome e o horário estão em linhas separadas. Deixe os dois na mesma linha, com o nome à esquerda e o horário à direita, alinhados pelo meio.

<ul class="flex flex-col gap-3">
  <li id="alvo" class="rounded-lg border border-stone-200 p-3">
    <div>
      <p class="font-medium text-stone-900">Marina</p>
      <p class="text-xs text-stone-500">12 pães de queijo</p>
    </div>
    <span class="text-sm text-amber-800">7h</span>
  </li>
</ul>
padding: 12px
border-radius: 8px
border-width: 1px
border-color: oklch(0.923 0.003 48.717)

<ul class="flex flex-col gap-3">
  <li id="alvo" class="flex items-center justify-between gap-3 rounded-lg border border-stone-200 p-3">
    <div>
      <p class="font-medium text-stone-900">Marina</p>
      <p class="text-xs text-stone-500">12 pães de queijo</p>
    </div>
    <span class="text-sm text-amber-800">7h</span>
  </li>
</ul>

Repare no div que envolve as duas linhas de texto: sem ele, os três pedaços — nome, quantidade e horário — seriam três filhos do flex e ficariam lado a lado, cada um do tamanho do seu texto. Com o div, o flex tem dois filhos: o bloco de texto e o horário. O justify-between então empurra um para cada ponta.

Essa ideia de agrupar antes de distribuir é o coração do flex, e vale para qualquer componente: antes de escolher classes, decida em quantos blocos o conteúdo se divide. Um erro comum de quem está começando é tentar alinhar seis elementos soltos com justify-between e terminar com espaços tortos.

5. Nome, descrição e preço no lugar certo

Dentro do bloco de texto, a hierarquia se faz com tamanho e cor, e o Tailwind oferece exatamente três degraus que resolvem quase tudo:

PapelClassesEfeito
título do itemfont-medium text-stone-900peso médio e o tom mais escuro: é o nome
detalhetext-xs text-stone-50012 px e claro: quantidade, tipo de pão
valortext-sm font-medium text-amber-800 tabular-numspreço ou horário, alinhado e com cor de destaque
linha inteiraflex items-center justify-between gap-3 p-3organiza e dá respiro interno
listaflex flex-col gap-3coluna com espaço entre itens

Note que o item aqui usa rounded-lg border p-3 e não linhas separando. As duas opções são válidas, e a diferença é de intenção: cartão por item diz "cada um é um objeto independente"; lista com separadores diz "todos fazem parte do mesmo bloco". Para encomendas que a Ana vai riscar uma a uma, o cartão ajuda; para o cardápio, a lista com separadores é mais leve.

E quando o item é clicável — a lista de produtos que leva para a página de cada pão —, ele não pode ser um li com eventos de clique: precisa ser um a de verdade dentro do li, ocupando a linha toda. Acessibilidade e Google agradecem, e o foco por teclado funciona de graça.

6. O quadradinho do ícone

Numa lista de produtos, o ícone ou a foto pequena à esquerda ajuda muito: o olho reconhece antes de ler. O padrão é um quadrado de 40 px com fundo suave e uma letra ou um símbolo dentro:

<li class="flex items-center gap-3 rounded-lg border border-stone-200 p-3">
  <span class="grid size-10 shrink-0 place-items-center rounded-full bg-amber-100 text-sm font-medium text-amber-800">F</span>
  <div class="min-w-0">
    <p class="font-medium text-stone-900">Francês</p>
    <p class="text-xs text-stone-500">60 g · assado às 5h</p>
  </div>
  <span class="ml-auto text-sm font-medium text-amber-800 tabular-nums">R$ 0,90</span>
</li>

Quatro classes merecem explicação. size-10 define largura e altura iguais, 40 px. grid place-items-center centraliza o conteúdo nos dois eixos — é o jeito mais curto de centralizar uma letra numa caixa. rounded-full deixa o quadrado redondo. shrink-0 é o seguro contra o flex: sem ele, quando o texto ao lado é longo, o flex encolhe o ícone até virar uma bolinha oval. Com ele, o ícone mantém 40 px e o texto é que se ajusta.

O ml-auto no preço é um atalho elegante: dentro de um flex, margem automática à esquerda empurra o elemento para a ponta direita, sem precisar de justify-between no pai. Funciona bem quando você tem três filhos e quer só o último na ponta. Quando você quer dois blocos distintos, justify-between continua sendo mais claro.

7. Separar sem moldura e responder ao mouse

Lista de cardápio costuma ficar melhor sem moldura em cada item: um fio fino entre eles, e nada em volta. A classe é divide-y no pai, e ela desenha a linha entre os filhos, nunca antes do primeiro nem depois do último. Você já viu divide-y na aula de divisores; aqui basta lembrar que a cor vem junto, divide-stone-200.

<ul class="divide-y divide-stone-200">
  <li class="flex items-center justify-between gap-3 py-3">
    <span class="font-medium text-stone-900">Francês</span>
    <span class="text-sm tabular-nums text-stone-600">R$ 0,90</span>
  </li>
</ul>

Se os itens forem clicáveis, o py-3 precisa virar px-3 py-3 e o item ganha rounded-lg hover:bg-stone-50. O padding horizontal existe para o fundo do hover ter o que pintar: sem ele, o cinza fica grudado no texto e parece um erro de renderização. E o rounded-lg no item evita o canto quadrado no meio de uma interface arredondada.

Juntando as opções, cada jeito de agrupar os itens comunica uma coisa diferente. Vale escolher com intenção, porque a lista é a peça que o cliente vê primeiro numa tela de bastidor:

JeitoOnde vão as classesQuando usar
coluna com respiroflex flex-col gap-3 no ulitens soltos, sem moldura; ocupa menos
cartão por itemrounded-lg border p-3 em cada liitens independentes, que a pessoa risca um a um
linhas separadasdivide-y divide-stone-200 no ulbloco único, como cardápio e lista de preços
linha que respondeborder-b mais hover:bg-stone-50 no liitens clicáveis dentro de um mesmo bloco

Um cuidado com divide-y e hover juntos: a linha do divisor não muda de cor no hover, e o item parece "flutuar" sobre uma linha fixa. É aceitável e é o que a maioria dos sites faz. Só não tente pintar o divisor no hover com uma classe no li — o divisor pertence ao pai, não ao filho, e a classe não pega. Se isso incomodar, troque o divisor por border-b border-stone-200 em cada li, que aí sim responde ao hover.

8. Nome comprido: truncate e min-w-0

Chegamos ao problema que mais aparece no mundo real. O pão se chama "Pão de queijo com queijo minas, orégano e uma pimenta que a Rita trouxe". Num item com horário à direita, esse nome empurra o horário para fora da tela ou quebra em cinco linhas. A solução é cortar com reticências, e a classe para isso é truncate.

Só que truncate sozinho não funciona dentro de um flex — e essa é a pegadinha da aula. O motivo é que um filho de flex tem largura mínima automática, e essa largura mínima é o tamanho do conteúdo. O navegador se recusa a encolher o texto abaixo do nome inteiro, então não sobra nada para cortar. A solução é dizer explicitamente "você pode encolher até zero" com min-w-0.

O nome comprido está empurrando o preço para fora do cartão. Corte o nome com reticências, lembrando que, dentro do flex, o truncate só funciona junto com min-w-0.

<div class="flex max-w-sm items-center justify-between gap-3 rounded-lg border border-stone-200 p-3">
  <p id="alvo" class="font-medium text-stone-900">Pão de queijo com queijo minas, orégano e pimenta</p>
  <span class="shrink-0 text-sm font-medium text-amber-800 tabular-nums">R$ 12,00</span>
</div>
color: oklch(0.216 0.006 56.043)
font-weight: 500

<div class="flex max-w-sm items-center justify-between gap-3 rounded-lg border border-stone-200 p-3">
  <p id="alvo" class="min-w-0 truncate font-medium text-stone-900">Pão de queijo com queijo minas, orégano e pimenta</p>
  <span class="shrink-0 text-sm font-medium text-amber-800 tabular-nums">R$ 12,00</span>
</div>

O painel mostra as três propriedades que o truncate liga de uma vez, mais o min-width: 0px do min-w-0:

.truncate {
  overflow: hidden;
  text-overflow: ellipsis;
  white-space: nowrap;
}
.min-w-0 {
  min-width: 0px;
}

Cada linha tem seu papel. white-space: nowrap proíbe a quebra em várias linhas. overflow: hidden esconde o que passa da caixa. text-overflow: ellipsis desenha as reticências no ponto do corte — mas só funciona se as duas primeiras estiverem lá. Por isso truncate é uma classe só para três propriedades que sempre andam juntas.

Se em vez de cortar você preferir mostrar o texto em duas linhas e depois cortar, existe line-clamp-2, que faz isso com reticências no fim da segunda linha. É ótimo para descrição de produto e péssimo para nome, porque nome cortado em duas linhas deixa a lista com alturas diferentes. Nome sempre numa linha; descrição pode ter duas.

9. Cenários do dia a dia

Cenário 1: a lista que virou tabela sem querer

A Ana queria nome, quantidade e horário na mesma linha e começou a dar larguras fixas em cada pedaço, tipo w-40, w-16, w-12. Funcionou no monitor dela e quebrou no celular, porque a soma passava da tela. A correção foi trocar as larguras fixas por flex flex-col gap-3 no item, na tela pequena, e sm:flex-row sm:items-center sm:justify-between a partir de 640 px. O mesmo HTML, duas disposições: em pé no celular, em linha no desktop.

Cenário 2: o horário que desapareceu do lado direito

Num dos itens, o horário simplesmente não aparecia. Não era CSS: o nome do pão era tão comprido que o bloco de texto ocupava tudo e o horário era espremido até a largura zero — porque o bloco de texto não tinha min-w-0 e o horário não tinha shrink-0. Com as duas classes no lugar, o texto encolhe e corta, e o horário mantém o tamanho. A dupla min-w-0 no texto e shrink-0 no valor é a receita de toda lista com valor à direita.

Cenário 3: vinte itens, nenhum marcador de posição

Quando a lista passou de vinte encomendas, a Ana percebeu que não sabia onde estava ao rolar. Ela resolveu com duas coisas simples: divide-y no pai para cada item ter começo e fim visíveis, e um cabeçalho fixo com a data acima da lista. Zíper não é enfeite: numa lista longa, ele é o que permite ao olho voltar para o lugar certo depois de olhar para o lado.

Exercício: o nome comprido do cardápio

O nome do pão é maior que o espaço e está empurrando o preço. Qual classe corta o texto com reticências em vez de deixar quebrar?

<p class="min-w-0 font-medium text-stone-900">Pão de queijo com queijo minas</p>

Dica: é uma classe de uma palavra só, que liga três propriedades: esconder o excesso, não quebrar linha e desenhar reticências. O min-w-0 ao lado é o que permite a ela funcionar dentro do flex.

11. Resumo

Lista de itens começa com a tag certa: ul para ordem livre, ol para sequência, dl para pares de nome e valor. No Tailwind, a lista nasce sem marcador, e isso é intencional: a maioria das listas na tela é componente, não texto corrido. O espaço entre itens fica no pai, com flex flex-col gap-3, e cada item vira uma linha com flex items-center justify-between gap-3.

A hierarquia dentro do item se faz com três degraus de texto: nome em font-medium text-stone-900, detalhe em text-xs text-stone-500 e valor em text-sm tabular-nums. O ícone é size-10 shrink-0 rounded-full com grid place-items-center por dentro. Para separar itens, divide-y no pai ou border-b em cada um, dependendo de você querer que a linha responda ao hover.

E o par que salva qualquer lista real: min-w-0 truncate no texto que pode encolher, shrink-0 no valor que não pode. Sem esse par, o nome comprido espreme o preço até desaparecer — e você passa uma tarde achando que o problema é o preço.

Para lembrar

  • ul é para ordem livre, ol para ordem que importa, dl para fichas.
  • O Tailwind tira o marcador por padrão; list-disc devolve quando fizer sentido, como mostra a aula de listas e marcadores.
  • Espaço entre itens: flex flex-col gap-3 no ul.
  • Item em linha: flex items-center justify-between gap-3.
  • Nome escuro e médio; detalhe pequeno e claro; valor com tabular-nums.
  • Ícone: size-10 shrink-0 rounded-full grid place-items-center.
  • divide-y divide-stone-200 separa sem moldura e ignora o primeiro e o último.
  • hover:bg-stone-50 só faz sentido com px-3 e rounded-lg.
  • truncate exige min-w-0 dentro do flex; o valor ao lado pede shrink-0.
