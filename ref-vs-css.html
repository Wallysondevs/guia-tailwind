Tailwind x CSS

A Ana aprendeu Tailwind, mas continua lendo CSS: tutoriais, respostas de fórum, o código de um tema pronto que ela baixou para a padaria. Ela quer saber o que está fazendo quando escreve p-4 — e o que exatamente aquilo vira no navegador. Também quer saber quando vale a pena escrever CSS do jeito antigo, e se as duas coisas podem conviver no mesmo arquivo sem uma sabotar a outra. Esta página é a mesa de tradução: classe de um lado, CSS do outro, com os valores reais que o motor do guia produz.

1. A mesma caixa, dois jeitos de escrever

Todo CSS tem três peças: um seletor que encontra elementos, uma declaração que diz o que mudar e um valor. .cartao { padding: 16px; } tem o seletor .cartao, a propriedade padding e o valor 16px. O Tailwind não muda essa gramática: ele entrega seletores prontos. Cada classe utilitária é um seletor de uma regra só, com uma declaração ou duas, e um nome que descreve o efeito.

A diferença de verdade está em quem escolhe o nome. No CSS clássico, você inventa .cartao, .cartao-destaque, .cartao-grande e depois precisa manter esse vocabulário em dois arquivos, o HTML e o CSS, sincronizados. No Tailwind, o vocabulário já existe e mora no próprio HTML: class="rounded-xl bg-white p-4" diz tudo sobre aquela caixa, e não há outro arquivo para abrir. Quem lê a marcação entende a aparência; quem muda a aparência muda ali.

O preço é o tamanho da linha. Uma caixa com sete características vira sete palavras, e isso incomoda na primeira semana. A compensação vem depois, quando você percebe que nunca precisa procurar onde uma classe é definida — ela não é definida em lugar nenhum, é gerada. Nomes inventados são ótimos quando você tem um componente reutilizado em cinquenta lugares; classes utilitárias são melhores quando cada tela é ligeiramente diferente, que é o caso de quase todo site pequeno.

utilitária
Classe que faz uma coisa só: p-4 só dá respiro, bg-white só pinta o fundo.
declaração
Um par propriedade e valor, terminado em ponto e vírgula: padding: 16px;.
seletor
O que encontra o elemento: .p-4, #alvo, li:first-child.
cascata
A ordem de prioridade entre regras que disputam a mesma propriedade. Quem vence é decidido por origem, camada, especificidade e ordem.
variável de tema
Um valor nomeado com dois traços, como --spacing, que as classes usam no lugar de um número solto.

Duas observações antes de ler: o Tailwind escreve calc(var(--spacing) * n) em vez de 16px, e usa variáveis para cor, raio, sombra e fonte. E space-y-2 usa :not(:last-child) justamente para não sobrar margem embaixo do último item, um problema clássico de quem fazia isso à mão.

3. As variáveis por baixo

O Tailwind v4 não gera hexadecimal atrás de hexadecimal: ele gera variáveis CSS e aponta para elas. Isso muda três coisas na sua vida. Primeiro, a página inteira fica coerente com uma troca só. Segundo, você pode usar as mesmas variáveis no seu CSS, com var(--color-amber-500). Terceiro, o build só publica as variáveis que alguém usou — se nenhuma classe pede --color-rose-300, ela não aparece no arquivo final. A tabela traz valores reais do motor.

Repare no seletor: :root, :host. O :root é o elemento raiz da página, o que faz a variável valer em todo lugar. O :host é para quando esse CSS roda dentro de um Web Component, com sombra própria. E note que as variáveis moram dentro de @layer theme — a primeira camada declarada no arquivo, o que significa que qualquer camada posterior pode sobrescrevê-las sem briga de especificidade.

4. Camadas e especificidade: por que uma classe ganha de um seletor comprido

Aqui está a parte que ninguém conta e que resolve a maior parte dos "meu CSS não pega". O Tailwind v4 declara quatro camadas na primeira linha do arquivo gerado, nesta ordem: @layer theme, base, components, utilities;. Camadas do CSS são um mecanismo oficial: entre regras de camadas diferentes, vence a camada declarada por último, independentemente da especificidade. Como utilities é a última, uma classe utilitária vence .cartao p escrito em components, mesmo que o seletor comprido pareça mais forte.

@layer theme, base, components, utilities;
@layer utilities {
  .p-4 {
    padding: calc(var(--spacing) * 4);
  }
}

Isso tem uma consequência que pega muita gente na migração: CSS escrito à mão sem @layer vence qualquer camada. Se você tem um .cartao { padding: 8px } solto no fim de um arquivo antigo, ele passa por cima de p-4, e a conclusão apressada é "o Tailwind não funciona". A regra é: ou você coloca o CSS antigo dentro de @layer base (para as utilitárias vencerem), ou assume que ele é a última palavra e para de tentar sobrescrever com classe.

Para os casos em que a classe precisa vencer de qualquer jeito, o v4 tem o ! no fim da classe: bg-amber-100! gera background-color: … !important. No v3 o ! ia na frente (!bg-amber-100), e essa é uma das trocas que mais confundem quem tem código antigo. Já o atributo style="" continua invencível: nenhuma classe, nem com !, passa por cima de estilo inline — só outro !important no próprio style.

5. Valores avulsos: quando o catálogo não tem o número

A escala do Tailwind cobre 95% do que você precisa, mas não tudo. Para o resto existem os colchetes, que aceitam CSS cru. Dentro deles, espaço vira sublinhado, porque espaço separa classes no HTML. A tabela mostra o que o motor escreve para cada forma.

ClasseCSS geradoQuando usar
p-[13px]padding: 13pxmedida exata de um desenho aprovado
text-[11px]font-size: 11pxletra miúda de nota fiscal

bg-[#fdf6e3]background-color: #fdf6e3cor da marca que não está na paleta
grid-cols-[1fr_2fr]grid-template-columns: 1fr 2frcolunas com proporções diferentes

shadow-[0_1px_2px_rgb(0_0_0/0.2)]--tw-shadow: 0 1px 2px rgb(0 0 0/0.2)sombra específica de um componente
bg-(--minha-cor)background-color: var(--minha-cor)cor que vem de variável do seu tema

Duas armadilhas dos colchetes. A primeira é o espaço: p-[10px 20px] no atributo class são duas classes, e nenhuma existe — o certo é p-[10px_20px]. A segunda é que colchetes aceitam qualquer coisa, inclusive erros: p-[16] sem unidade gera CSS inválido, o navegador descarta a declaração e a caixa fica sem respiro. O compilador não avisa, porque para ele a sintaxe está certa.

A variante com & merece um parágrafo próprio, porque é o que substitui o CSS filho do jeito antigo. [&>li]:mt-2 quer dizer "aplique mt-2 aos li filhos diretos deste elemento". O & representa o elemento que tem a classe. Você pode usar isso para qualquer seletor: [&:hover]:underline, [&::placeholder]:italic, [&:nth-child(3)]:bg-amber-50. É a válvula de escape completa, e mora no mesmo lugar das outras classes.

Este cartão usa style="padding:16px", escrito à mão. Troque o estilo inline pela classe equivalente, sem mudar o resultado na tela.

<div id="alvo" class="rounded-lg bg-amber-50" style="padding:16px">
  <p>Pão quentinho</p>
</div>
background-color: oklch(0.987 0.022 95.277)
border-radius: 8px

<div id="alvo" class="rounded-lg bg-amber-50 p-4">
  <p>Pão quentinho</p>
</div>

O painel mostra padding: 16px nas duas versões — o resultado na tela é idêntico, e é justamente essa a lição: a diferença não está no pixel, está no que você ganha depois. Com p-4, dá para escrever md:p-8 e dark:p-4; com style="", não. O estilo inline é ponto final, não ponto de partida.

6. O que o Tailwind não resolve

Existe uma lenda de que Tailwind "substitui CSS". Não substitui: ele substitui a maior parte do CSS de aparência. Continuam sendo CSS, e continuam no seu arquivo, os casos abaixo. Saber quais são evita a frustração de procurar uma classe que não existe.

Animação com vários quadros. As quatro prontas são giro, pulso, ping e quique. Uma animação de cinco etapas com cores diferentes precisa de @keyframes escrito por você — no @theme, como mostrado em Animações.

Seletores que dependem de estrutura incomum. O Tailwind cobre pai (group), irmão anterior (peer), filhos com [&>li] e até :has(). Mas um seletor como "o terceiro item de uma lista aninhada dentro de uma tabela" não tem classe; escreve-se à mão, com @layer components.

Estilos globais. Cor de fundo do site, fonte base, seleção de texto, barra de rolagem, scroll-behavior. Isso vai em @layer base, com seletor de elemento (body, html), e não em classe no HTML. A aula Estilos de Base mostra onde colocar cada um.

Componentes repetidos em muitos lugares. Um botão que aparece em vinte páginas merece uma classe só. O caminho no v4 é @layer components com @apply para reaproveitar as utilitárias. Em arquivo CSS separado — módulo, componente de framework —, o v4 exige @reference "caminho/entrada.css" no topo, para o compilador saber onde estão as definições do tema.

Valores que vêm de fora. Uma cor escolhida pelo cliente, salva no banco e injetada na página. Não dá para gerar classe em tempo de execução: use style="--cor: #a33" no elemento e bg-(--cor) na classe, ou aceite o style="" completo para aquele pedaço.

Interação com JavaScript. Arrastar, medir, animar em função da posição do dedo. O Tailwind dá a aparência do estado; quem troca o estado é o seu código, com classList ou com atributos que as variantes leem (data-*, aria-*).

7. Misturando os dois sem brigar

A convivência é possível e comum. A regra que organiza tudo é a das camadas: coloque cada coisa na camada certa e o resto se resolve sozinho. @layer base para o que é padrão de página, @layer components para o que tem nome e se repete, e utilitárias soltas no HTML para o que é específico daquela tela. O CSS sem camada fica reservado para correções conscientes e comentadas.

Um exemplo de componente com @apply, do jeito que o v4 aceita no mesmo arquivo que importa o Tailwind:

@import "tailwindcss";

@layer components {
  .botao-padaria {
    @apply inline-flex items-center gap-2 rounded-lg bg-amber-600 px-4 py-2 text-white;
  }
  .botao-padaria:hover {
    @apply bg-amber-700;
  }
}

Atenção a um detalhe do @apply: ele copia as declarações, não as variantes. Escrever @apply hover:bg-amber-700 funciona em versões recentes, mas o resultado é uma regra com :hover dentro do seletor — e aí a classe perde a vantagem de ser uma utilitária isolada. O exemplo acima deixa o hover numa regra separada, o que é mais fácil de ler e de depurar. E lembre: o @apply não enxerga classes que você inventou; ele só conhece utilitárias e o que estiver no tema.

Para valores do tema dentro do seu CSS, existem duas funções. var(--color-amber-500) lê a variável em tempo de navegador — simples e direto. theme(--color-amber-500) resolve o valor no momento de compilar, o que só é necessário quando o destino não aceita variáveis, como dentro de uma consulta de mídia. Na prática, use var() e guarde theme() para os casos especiais.

O título do cartão está com text-base e parece apagado. Suba para text-lg: a missão confere o tamanho e a entrelinha que vêm juntos.

<h3 id="alvo" class="font-semibold text-stone-800">Pão do dia</h3>
color: oklch(0.268 0.007 34.298)
font-weight: 600

<h3 id="alvo" class="text-lg font-semibold text-stone-800">Pão do dia</h3>

O interessante desta missão é o que ela revela sobre a escala tipográfica: text-lg não mexe só no tamanho, mexe também na entrelinha, porque as duas andam juntas. Se você trocar por text-[18px], ganha os 18 px mas perde a entrelinha de 28 px — e a linha fica apertada. É a diferença entre usar o sistema e usar um número.

8. Traduzindo uma regra escrita à mão

Vale treinar a tradução no sentido inverso, porque é o que você vai fazer ao migrar um site pronto. Pegue a regra abaixo, típica de tutorial:

.cartao {
  background: #fff;
  border: 1px solid #e7e5e4;
  border-radius: 12px;
  padding: 16px;
  box-shadow: 0 1px 2px rgb(0 0 0 / 0.05);
}
.cartao h3 {
  font-size: 18px;
  line-height: 28px;
  font-weight: 600;
  color: #292524;
}
.cartao p {
  margin-top: 8px;
  font-size: 14px;
  color: #78716c;
}

A tradução honesta não é uma classe só; é o conjunto aplicado onde cada coisa mora. A tabela abaixo faz o serviço linha por linha, com o valor que o v4 realmente usa.

Com a tabela na mão, a caixa recebe rounded-xl border border-stone-200 bg-white p-4 shadow-xs. O título recebe text-lg font-semibold text-stone-800 — e aqui está a graça: text-lg já traz os 18 px com 28 px de entrelinha, exatamente o que a regra escrita à mão fazia em duas linhas. O parágrafo recebe mt-2 text-sm text-stone-600.

Repare no que desapareceu: o seletor descendente .cartao h3. No Tailwind, o estilo mora no próprio h3, e não importa quem é o pai. Isso parece mais verboso e é, mas elimina uma classe inteira de bugs — o estilo que "vaza" para um título que não devia recebê-lo, porque estava dentro do cartão sem querer. Em compensação, se amanhã você quiser mudar todos os títulos de cartão, precisa editar cada arquivo onde há um. É o trade-off de sempre, e não tem resposta única.

Três conferências fecham a tradução. A cor da borda: no CSS antigo ela vinha junto com border; no Tailwind, border sozinho não define cor, e a borda herda a cor do texto. A sombra: a escala mudou de nome no v4 — o shadow-sm do v3 virou shadow-xs, e o shadow sem sufixo do v3 virou shadow-sm. Quem copiou a classe antiga vê uma sombra mais forte do que esperava. O raio: 12 px é rounded-xl na escala, e rounded-[12px] faria o mesmo com um número explícito.

Por fim, um teste de sanidade que vale para qualquer migração: rode a página e compare o painel de CSS computado do elemento antigo com o do novo. As propriedades que a classe mudou devem ser as mesmas, com os mesmos valores. Se algo divergir, a diferença está numa variável — e a seção 3 desta página é o mapa para descobrir qual.

9. Resumo

Classe utilitária é um seletor de uma declaração, com nome pronto. p-4 gera padding: calc(var(--spacing) * 4); text-lg gera tamanho e entrelinha juntos; shadow-md guarda o desenho em --tw-shadow e compõe com anel e contorno interno. Os valores moram em variáveis de tema, e o build publica só as que alguém usa — a lista completa das cores está em Paleta de Cores.

  • Camadas na ordem theme, base, components, utilities: utilitária vence componente, mesmo com seletor mais fraco.
  • CSS escrito à mão sem @layer vence todas as camadas — é a causa número um de "não pegou".
  • ! vai no fim da classe no v4; style="" vence classe e !.
  • Colchetes aceitam CSS cru, com sublinhado no lugar do espaço: p-[13px], bg-[#fdf6e3], [&>li]:mt-2.
  • Fora do catálogo ficam keyframes longos, estilos globais, seletores estruturais raros e valores que vêm do banco — todos resolvidos com CSS, @layer e @apply.
  • @apply copia declarações; em arquivo separado, o v4 pede @reference.
